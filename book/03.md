# 第3章　最初の最適化モデルを作る

**初花**: 実家の庭の梅がたくさん採れたから、マルシェで梅ジャムと梅シロップを売ろうと思うんだ。どっちをどれだけ作ればいいか、PuLPで決められる？

**マリゴールド**: ちょうどいい題材だね。第1章では出来上がったコードを読んだだけだったけど、この章では **自分の手で一行ずつ** モデルを組み立てよう。

**初花**: 一行ずつ……。どこから書けばいいの？

**マリゴールド**: 順番は決まっていて、**変数 → 目的関数 → 制約条件 → 解く → 説明する** の五つ。この章の節も、その順番で並べてあるよ。

---

まず、題材を表にまとめます（数値は本書用の架空の設定です）。

| | うめジャム（1kgあたり） | うめシロップ（1Lあたり） | 使える上限 |
|---|----------------------|------------------------|-----------|
| 梅の使用量 | 0.6 kg | 0.5 kg | **33 kg** |
| 作業時間 | 0.5 時間 | 0.2 時間 | **21 時間** |
| 利益 | 800 円 | 500 円 | — |

作った分は全部売れるものとします。ジャムはkg、シロップはLで量るので、量は小数でもかまいません。

---

## 3.1　意思決定変数を定義する

**初花**: 決めたいのは「ジャムを何kg作るか」と「シロップを何L作るか」の二つだね。

**マリゴールド**: そう、それが **意思決定変数**。PuLPでは、問題を作ってから、その問題に変数を追加していく。

```python
import pulp

prob = pulp.LpProblem("ume_kobo", pulp.LpMaximize)

jam = prob.add_variable("jam", lowBound=0)      # うめジャムを作る量（kg）
syrup = prob.add_variable("syrup", lowBound=0)  # うめシロップを作る量（L）
```

| 引数 | 意味 | この例 |
|------|------|-------|
| 1つ目（`"jam"`） | 変数の名前。ログやLPファイルに出る | 英数字で付ける |
| `lowBound` | 下限 | 0（マイナスの量は作れない） |
| `upBound` | 上限 | 省略（上限なし） |
| `cat` | 変数の型 | 省略（`"Continuous"`、小数OK） |

**初花**: `lowBound=0` って、わざわざ書かないといけないの？ 作る量がマイナスなんて、ありえないのに。

**マリゴールド**: PuLPは「ありえない」を知らないんだ。省略すると下限なしになって、ソルバーは平気で「ジャムを −10kg 作る」答えを探しに行く。**常識は全部、自分で書く** のが最適化のルールだよ。

⚠️ `prob.add_variable(...)` の戻り値を、`jam` のようなPythonの変数に入れておきます。このあと目的関数や制約条件を書くときに使います。

---

## 3.2　最大化・最小化の目的関数を作る

**初花**: 次は「何をよくしたいか」。今回は利益をいちばん大きくしたい。

**マリゴールド**: 利益の合計は「800 × ジャムの量 ＋ 500 × シロップの量」。PuLPでも、ほぼそのまま書けるよ。

```python
prob += 800 * jam + 500 * syrup, "total_profit"
```

`prob +=` の右側に **式** を書くと、それが目的関数になります。カンマの後ろの `"total_profit"` は目的関数の名前です（省略可）。

最大化か最小化かは、問題を作るときの2つ目の引数で決めます。

| 書き方 | 意味 | 例 |
|--------|------|----|
| `pulp.LpProblem("名前", pulp.LpMaximize)` | 目的関数を **最大化** | 利益、売上、満足度 |
| `pulp.LpProblem("名前", pulp.LpMinimize)` | 目的関数を **最小化** | 費用、時間、距離 |

**初花**: 最小化の例も見てみたい。たとえば、注文が来て「ジャム20kg以上、シロップ20L以上」を作るとき、作業時間をいちばん短くしたい、とか。

**マリゴールド**: いい例だね。下限を `lowBound` で表して、目的関数を作業時間にすればいい。

`ch03_min.py`:

```python
import pulp

prob = pulp.LpProblem("ume_min_hours", pulp.LpMinimize)

jam = prob.add_variable("jam", lowBound=20)      # 注文：ジャム20kg以上
syrup = prob.add_variable("syrup", lowBound=20)  # 注文：シロップ20L以上

prob += 0.5 * jam + 0.2 * syrup, "work_hours"
prob += 0.6 * jam + 0.5 * syrup <= 33, "ume_kg"

stats = prob.solve(pulp.HiGHS(msg=False))
print("状態:", stats.status_str)
print("作業時間:", pulp.value(prob.objective), "時間")
print("ジャム:", jam.value(), "kg / シロップ:", syrup.value(), "L")
```

実行結果:

```text
状態: Optimal
作業時間: 14.0 時間
ジャム: 20.0 kg / シロップ: 20.0 L
```

**初花**: 注文ぴったりの量だけ作るのが、いちばん早い。そりゃそうか。

**マリゴールド**: 最小化では「余計なことをしない」答えになりやすいんだ。目的関数を変えると、同じ材料でも答えが大きく変わる——この章の本題の最大化に戻ろう。

---

## 3.3　制約条件を追加する

**初花**: 守るルールは、梅が33kgまでと、作業が21時間まで、の二つだね。

**マリゴールド**: 制約条件も `prob +=` で追加する。目的関数との違いは、**`<=` や `>=` が入っているかどうか** だよ。

```python
prob += 0.6 * jam + 0.5 * syrup <= 33, "ume_kg"
prob += 0.5 * jam + 0.2 * syrup <= 21, "work_hours"
```

| `prob +=` の右側 | PuLPの解釈 |
|-----------------|-----------|
| `800 * jam + 500 * syrup`（比較なし） | 目的関数 |
| `0.6 * jam + 0.5 * syrup <= 33` | 制約条件（以下） |
| `jam >= 20` | 制約条件（以上） |
| `jam + syrup == 50` | 制約条件（ちょうど等しい） |

制約条件の名前（`"ume_kg"` など）は省略できますが、本書では必ず付けます。結果を確かめるときや、エラーの原因を探すときに、どの制約の話かが一目で分かるからです。

**初花**: 表の行が、そのまま1行ずつのコードになってる。

**マリゴールド**: 表をきちんと作れば、コードは写すだけになる。逆に、コードで迷ったら表に戻ろう。

⚠️ 目的関数の `prob +=` は1回だけにします。比較のない式をもう一度 `prob +=` すると、目的関数が上書きされます。

## 3.4　モデルをソルバーで解く

ここまでをつなげると、モデルの完成です。

`ch03_ume.py`:

```python
import pulp

# 1. 問題を作る（利益を最大化）
prob = pulp.LpProblem("ume_kobo", pulp.LpMaximize)

# 2. 意思決定変数
jam = prob.add_variable("jam", lowBound=0)      # うめジャムを作る量（kg）
syrup = prob.add_variable("syrup", lowBound=0)  # うめシロップを作る量（L）

# 3. 目的関数：利益の合計
prob += 800 * jam + 500 * syrup, "total_profit"

# 4. 制約条件
prob += 0.6 * jam + 0.5 * syrup <= 33, "ume_kg"
prob += 0.5 * jam + 0.2 * syrup <= 21, "work_hours"

# 5. 解く
stats = prob.solve(pulp.HiGHS(msg=False))

print("状態:", stats.status_str)
print("利益:", pulp.value(prob.objective), "円")
print("ジャム:", jam.value(), "kg")
print("シロップ:", syrup.value(), "L")
```

実行結果:

```text
状態: Optimal
利益: 39000.0 円
ジャム: 30.0 kg
シロップ: 30.000000000000004 L
```

**初花**: ジャム30kg、シロップ30Lで、利益39,000円。……でもシロップの `30.000000000000004` って何？ 端っこに4がいる。

**マリゴールド**: コンピュータが小数を計算するときに出る、ごく小さな誤差だよ。ソルバーの計算は小数で行うから、こういう端数はよく出る。意味は「30」だと読んで大丈夫。

| 値を取り出す書き方 | 返すもの |
|------------------|---------|
| `stats.status_str` | 解けたかどうか（`Optimal` など） |
| `pulp.value(prob.objective)` | 目的関数の値（利益の合計） |
| `jam.value()` | 変数の値 |
| `pulp.value(式)` | 任意の式に、解の値を入れて計算した結果 |

⚠️ `stats.status_str` が `Optimal` でないときは、変数の値を信じないでください。解けなかった理由の調べ方は第7章で扱います。

## 3.5　解の意味を日本語で説明する

**初花**: 答えは出たけど、家族に「なんでこの量なの？」って聞かれたら、うまく説明できる自信がない。

**マリゴールド**: 説明には、**数字の答え** と **何が足りなくなったか** の二つがあればいい。まずは他の作り方と比べてみよう。

| 作り方 | ジャム | シロップ | 利益 | 先に足りなくなるもの |
|--------|-------|---------|------|---------------------|
| ジャムだけ | 42 kg | 0 L | 33,600 円 | 作業時間（21時間） |
| シロップだけ | 0 kg | 66 L | 33,000 円 | 梅（33kg） |
| **最適解** | **30 kg** | **30 L** | **39,000 円** | **梅も作業時間も両方** |

**初花**: ジャムは利益が高いけど手間がかかる。シロップは手間は少ないけど梅をたくさん使う。だから両方を混ぜると、梅も時間も無駄なく使い切れるんだ。

**マリゴールド**: それがこの答えの日本語訳だね。最適解では梅33kgも作業21時間もぴったり使い切っている。こういう「ぴったり使い切った制約」を、**効いている制約**（有効な制約）と呼ぶよ。

制約ごとに「どれだけ使ったか」を確かめるには、式をPythonの変数に入れておき、解いた後で `pulp.value()` に渡します。

```python
ume_used = 0.6 * jam + 0.5 * syrup
hours_used = 0.5 * jam + 0.2 * syrup

prob += ume_used <= 33, "ume_kg"
prob += hours_used <= 21, "work_hours"

# 解いた後で
pulp.value(ume_used)    # 33.0
pulp.value(hours_used)  # 21.0
```

**初花**: もし梅がもっとあったら、利益も増える？

**マリゴールド**: 梅も時間も効いているから、どちらかを増やせば利益は増える。どれだけ増えるかを調べる方法は、第18章の感度分析で扱うよ。

## ハンズオン 3-C — 解の意味を日本語で表示する

3.5 の考え方で、結果を日本語の文章として表示します。小数の誤差は、表示するときに `:.1f`（小数1桁）で丸めます。

`ch03_report.py`:

```python
import pulp

prob = pulp.LpProblem("ume_kobo", pulp.LpMaximize)

jam = prob.add_variable("jam", lowBound=0)
syrup = prob.add_variable("syrup", lowBound=0)

profit = 800 * jam + 500 * syrup
ume_used = 0.6 * jam + 0.5 * syrup
hours_used = 0.5 * jam + 0.2 * syrup

prob += profit, "total_profit"
prob += ume_used <= 33, "ume_kg"
prob += hours_used <= 21, "work_hours"

stats = prob.solve(pulp.HiGHS(msg=False))

print(f"状態: {stats.status_str}")
print(f"ジャムを {jam.value():.1f} kg、シロップを {syrup.value():.1f} L 作ると、")
print(f"利益は {pulp.value(profit):,.0f} 円で最大になります。")
print(f"梅は {pulp.value(ume_used):.1f} / 33 kg、作業時間は {pulp.value(hours_used):.1f} / 21 時間 使います。")
```

実行結果:

```text
状態: Optimal
ジャムを 30.0 kg、シロップを 30.0 L 作ると、
利益は 39,000 円で最大になります。
梅は 33.0 / 33 kg、作業時間は 21.0 / 21 時間 使います。
```

**初花**: これなら家族にそのまま見せられる！ `30.000000000000004` も消えた。

**マリゴールド**: 丸めるのは **表示するときだけ** にしよう。計算に使う値まで丸めると、検証のときに誤差の扱いがややこしくなる。表示用と計算用を分けておく考え方は、第6章でも使うよ。

| 書式 | 例 | 表示 |
|------|----|------|
| `:.1f` | `f"{30.000000000000004:.1f}"` | `30.0` |
| `:,.0f` | `f"{39000.0:,.0f}"` | `39,000` |

## 初花のメモ帳

- モデルは「変数 → 目的関数 → 制約条件 → 解く → 説明する」の順に書く
- `lowBound=0` のような常識も、全部自分で書かないとソルバーは知らない
- 説明には、数字の答えと「何を使い切ったか（効いている制約）」の二つを添える

## マリゴールドの one more thing

**2変数なら、答えは「角」にある。**

変数が2つの線形計画問題は、方眼紙に図を描いて解くこともできます。梅の制約と作業時間の制約をそれぞれ直線で描くと、両方を満たす領域は多角形になり、最適解は必ずその多角形の **角（頂点）** のどれかに現れます。3.5 の表の「ジャムだけ」「シロップだけ」「最適解」は、まさにその角でした。変数が増えると図は描けなくなりますが、ソルバーは同じ考え方で角から角へと答えを探しています。この見方は、第6章で「最適解が複数ある場合」を考えるときに役立ちます。
