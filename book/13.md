# 第13章　予算内で最良の組み合わせを選ぶ

**初花**: うめ食品の社長さんから、来年度の予算の使い道を相談されたんだって、マリゴールドに。

**マリゴールド**: そうなんだ。広告、設備、人材、システム……やりたいことは12個あるけど、予算は1,000万円しかない。どれを選べば効果が一番大きくなるか、という相談だよ。

**初花**: それって、第1章の屋台の問題に似てるね。予算内で、一番いい組み合わせを選ぶ。

**マリゴールド**: そう。ただ今回は、どの施策も **やるか・やらないか** の二択。この形は **ナップサック問題** と呼ばれていて、整数計画法の代表的な問題なんだ。

---

## 13.1　ナップサック問題

**マリゴールド**: 名前の由来は、登山のときにナップサックに何を詰めるか、という話だよ。

```text
ナップサックに入る重さには限りがある（予算）
  ↓
品物にはそれぞれ重さ（費用）と価値（効果）がある
  ↓
重さの上限を超えないように、価値の合計が最大になる品物の組み合わせを選ぶ
```

| ナップサック問題の言葉 | この章の例 |
|---------------------|-----------|
| 品物 | 施策の候補 |
| 重さ | 費用 |
| 価値 | 期待される効果 |
| ナップサックの容量 | 予算 1,000万円 |
| 入れる・入れない | やる・やらない（バイナリ変数） |

**初花**: 変数はバイナリ、目的は効果の最大化、制約は予算。前の章までで全部習ったものだね。

**マリゴールド**: 形は単純なんだけど、実務ではここに「この種類は1件まで」「これは必ずやる」のような条件が次々に加わる。それを一つずつ書けるようになるのが、この章の目標だよ。

|------|------|----------:|----------:|----------:|
| Web広告 | 販促 | 120 | 180 | 1.50 |
| 地方テレビCM | 販促 | 400 | 520 | 1.30 |
| 店頭試食会 | 販促 | 80 | 110 | 1.38 |
| ラベル刷新 | 販促 | 60 | 70 | 1.17 |
| 衛生設備の更新 | 設備 | 250 | 150 | 0.60 |
| 大型釜の導入 | 設備 | 300 | 420 | 1.40 |
| 太陽光パネル | 設備 | 350 | 300 | 0.86 |
| 品質研修 | 人材 | 90 | 140 | 1.56 |
| 品質管理者の採用 | 人材 | 200 | 230 | 1.15 |

**マリゴールド**: その作戦も比べてみよう。ハンズオン 13-A のプログラムで、効率順に選んだ結果と、PuLPで予算だけを条件にした結果を並べるよ。

```text

|------|-----:|-----:|----:|-----------|
```

**初花**: 効率順だと70万円も余って、効果は1,300万円。PuLPは予算をぴったり使い切って、1,380万円。第1章の屋台と同じことが起きてる。

**マリゴールド**: 効率順に詰める方法は、大きな品物（テレビCM）が入る余地を、小さな品物で先に埋めてしまうことがある。ナップサック問題では、この「端数の予算」が答えを大きく左右するんだ。

```python
pick = {k: prob.add_variable(f"pick_{k}", cat="Binary") for k in candidates}

prob += pulp.lpSum(candidates[k]["value"] * pick[k] for k in candidates), "total_value"
prob += pulp.lpSum(candidates[k]["cost"] * pick[k] for k in candidates) <= BUDGET, "budget"
```

## 13.3　予算・個数・カテゴリの制約

**初花**: でも、予算だけの答えは、Web広告とテレビCMの両方をやることになってる。社長さんが「広告の担当は1チームしかいない」って言ってたよ。

**マリゴールド**: それは **カテゴリの制約** だね。「販促」の種類の施策の `pick` を合計して、1以下にすればいい。第11章で学んだ「バイナリ変数の合計は個数を数える」の使い方だよ。

```python
prob += pulp.lpSum(pick[k] for k in candidates if candidates[k]["group"] == "promo") <= 1, "promo_max1"
```

```text
| 2: ＋販促は1件まで | 1,350 | 990 | 6 | Web広告・大型釜の導入・品質研修・品質管理者の採用・通販サイト・POSデータ分析 |
```

**初花**: テレビCMが外れて、代わりに小さい施策が増えた。でも6件も同時にやるのは、社内の人手が足りないかも。

**マリゴールド**: じゃあ **個数の制約** も足そう。同時に進められるのは4件まで、としてみるよ。全部の `pick` の合計が4以下だね。

```python
prob += pulp.lpSum(pick.values()) <= 4, "count_max4"
```

```text
| 3: ＋4件まで | 1,340 | 970 | 4 | 地方テレビCM・大型釜の導入・品質研修・通販サイト |
```

**初花**: 4件に絞ったら、テレビCMが戻ってきた。件数が限られるなら、一つひとつが大きい施策のほうが得なんだね。

| 制約の種類 | 書き方 | 例 |
|-----------|-------|----|
| 予算 | `Σ 費用 × pick <= 予算` | 1,000万円まで |
| 個数 | `Σ pick <= k` | 4件まで |
| カテゴリの上限 | `Σ（その種類の pick） <= k` | 販促は1件まで |
| カテゴリの下限 | `Σ（その種類の pick） >= k` | 人材を1件以上 |

## 13.4　必須項目と選択項目

**初花**: あと、衛生設備の更新は、法律の基準が変わるから必ずやらないといけないんだって。効果は一番低いけど。

**マリゴールド**: **必須項目** だね。その `pick` を1に固定すればいい。

```python
prob += pick["hygiene"] == 1, "must_hygiene"
```

```text
| 4: ＋衛生設備は必須 | 1,090 | 950 | 3 | 地方テレビCM・衛生設備の更新・大型釜の導入 |
```

**初花**: 効果が250万円も下がった！ 衛生設備に250万円使うのに、効果は150万円しかないから……。

**マリゴールド**: 必須項目は、効果の大小に関係なく予算を先に取ってしまうからね。その結果、残りの予算で選べる組み合わせが変わる。品質研修と通販サイトが外れて、3件になったよ。

**初花**: 最後に、社長さんが「人を育てる施策を最低1つは入れたい」って。

```python
prob += pulp.lpSum(pick[k] for k in candidates if candidates[k]["group"] == "people") >= 1, "people_min1"
```

```text
| 5: ＋人材を1件以上 | 1,070 | 920 | 4 | 地方テレビCM・衛生設備の更新・品質研修・通販サイト |
```

**マリゴールド**: 大型釜が外れて、品質研修と通販サイトが入った。人材の条件のために、効果を20万円あきらめた計算になるね。

| ステップ | 足した条件 | 効果 | 下がった分 |
|---------|-----------|-----:|---------:|
| 1 | 予算だけ | 1,380 | — |
| 2 | ＋販促は1件まで | 1,350 | 30 |
| 3 | ＋4件まで | 1,340 | 10 |
| 4 | ＋衛生設備は必須 | 1,090 | 250 |
| 5 | ＋人材を1件以上 | 1,070 | 20 |

**初花**: 条件ごとに、いくら効果をあきらめたかが分かる。社長さんに見せるなら、この表が一番伝わりそう。

**マリゴールド**: 特に「人材を1件以上」が20万円で済む、という情報は大事だよ。経営の方針として入れたい条件の **値段** が分かれば、納得して決められる。

| 項目の種類 | 書き方 |
|-----------|-------|
| 必須 | `pick[k] == 1` |
| 禁止（今年は見送り） | `pick[k] == 0`、または候補から外す |
| 選択 | 何も書かない |

## 13.5　単純な全探索と最適化の結果を比較する

**初花**: 12個の候補なら、全部の組み合わせを試すこともできるよね。2の12乗で……4,096通り。

**マリゴールド**: できるね。ステップ5の条件を全部入れて、全探索で確かめてみよう。

`ch13_check.py`:

```python
import itertools
from ch13_invest import candidates, BUDGET

names = list(candidates)
best_value, best_pick, checked = -1, None, 0
for picks in itertools.product([0, 1], repeat=len(names)):
    checked += 1
    chosen = [n for n, p in zip(names, picks) if p]
    groups = [candidates[n]["group"] for n in chosen]
    if (sum(candidates[n]["cost"] for n in chosen) <= BUDGET
            and groups.count("promo") <= 1
            and len(chosen) <= 4
            and "hygiene" in chosen
            and groups.count("people") >= 1):
        value = sum(candidates[n]["value"] for n in chosen)
        if value > best_value:
            best_value, best_pick = value, chosen

print("調べた組み合わせ:", checked)
print("最良:", best_value, [candidates[n]["label"] for n in best_pick])
```

実行結果:

```text
調べた組み合わせ: 4096
最良: 1070 ['地方テレビCM', '衛生設備の更新', '品質研修', '通販サイト']
```

**初花**: PuLPと同じ答え！ 第7章で習った「小さな問題で全探索と答え合わせ」だね。

**マリゴールド**: そう。ただ、全探索は候補が増えると一気に重くなる。ランダムに作った候補で、候補の数を増やしながら比べてみたよ（ハンズオン 13-B）。

```text
| 候補の数 | 組み合わせの数 | 全探索 | 秒 | PuLP | 秒 |
|-------:|------------:|------:|---:|-----:|---:|
| 10 | 1,024 | 1,060 | 0.00 | 1,060 | 0.01 |
| 14 | 16,384 | 2,157 | 0.02 | 2,157 | 0.00 |
| 18 | 262,144 | 2,752 | 0.31 | 2,752 | 0.00 |
| 22 | 4,194,304 | 3,325 | 5.46 | 3,325 | 0.00 |
```

**初花**: 候補が4つ増えるたびに、全探索の時間は16倍。22個で5秒だから、30個なら……

**マリゴールド**: 5.46秒 × 2の8乗で、約23分。40個なら約17日かかる計算だね。PuLPは、どれも一瞬で終わっている。

| 方法 | 良いところ | 困るところ |
|------|----------|----------|
| 全探索 | 考え方が単純。必ず最適 | 候補が増えると時間が爆発する |
| 効率順に選ぶ | 速い。説明しやすい | 最適とは限らない。条件を足しにくい |
| PuLP（整数計画） | 速い。必ず最適（Optimal なら）。条件を足しやすい | モデルを正しく書く必要がある |

⚠️ 第12章で見たように、ナップサック問題でも資源の種類が増えると、ソルバーでも時間がかかることがあります。この章の比較は、予算の制約が1本だけの単純な形のものです。

## ハンズオン 13-A — 限られた予算で、価値の合計が最大になる施策を選ぶ

13.2〜13.4 を1つのプログラムにまとめます。条件は `rules` のリストに名前を足していくと、段階的に加わります。

`ch13_invest.py`:

```python
import pulp

# 来年度の施策の候補（本書用の架空のデータ）。費用と効果は万円
candidates = {
    "web_ad":        {"label": "Web広告",          "cost": 120, "value": 180, "group": "promo"},
    "tv_cm":         {"label": "地方テレビCM",     "cost": 400, "value": 520, "group": "promo"},
    "sampling":      {"label": "店頭試食会",       "cost": 80,  "value": 110, "group": "promo"},
    "new_label":     {"label": "ラベル刷新",       "cost": 60,  "value": 70,  "group": "promo"},
    "hygiene":       {"label": "衛生設備の更新",   "cost": 250, "value": 150, "group": "equip"},
    "new_kettle":    {"label": "大型釜の導入",     "cost": 300, "value": 420, "group": "equip"},
    "solar":         {"label": "太陽光パネル",     "cost": 350, "value": 300, "group": "equip"},
    "training":      {"label": "品質研修",         "cost": 90,  "value": 140, "group": "people"},
    "hire_qc":       {"label": "品質管理者の採用", "cost": 200, "value": 230, "group": "people"},
    "inventory_sys": {"label": "在庫管理システム", "cost": 150, "value": 160, "group": "it"},
    "ec_site":       {"label": "通販サイト",       "cost": 180, "value": 260, "group": "it"},
    "pos_data":      {"label": "POSデータ分析",    "cost": 100, "value": 120, "group": "it"},
}
BUDGET = 1000


def solve_invest(rules):
    prob = pulp.LpProblem("invest", pulp.LpMaximize)
    pick = {k: prob.add_variable(f"pick_{k}", cat="Binary") for k in candidates}

    prob += pulp.lpSum(candidates[k]["value"] * pick[k] for k in candidates), "total_value"
    prob += pulp.lpSum(candidates[k]["cost"] * pick[k] for k in candidates) <= BUDGET, "budget"

    if "promo_max1" in rules:   # 広告・販促は1件まで（担当チームが1つ）
        prob += pulp.lpSum(pick[k] for k in candidates if candidates[k]["group"] == "promo") <= 1, "promo_max1"
    if "count_max4" in rules:   # 同時に進められるのは4件まで
        prob += pulp.lpSum(pick.values()) <= 4, "count_max4"
    if "must_hygiene" in rules:  # 衛生設備の更新は必須（法令対応）
        prob += pick["hygiene"] == 1, "must_hygiene"
    if "people_min1" in rules:  # 人材への投資を1件以上
        prob += pulp.lpSum(pick[k] for k in candidates if candidates[k]["group"] == "people") >= 1, "people_min1"

    stats = prob.solve(pulp.HiGHS(msg=False))
    picked = [k for k in candidates if pick[k].value() > 0.5]
    return {
        "status": stats.status_str,
        "value": pulp.value(prob.objective),
        "cost": sum(candidates[k]["cost"] for k in picked),
        "picked": picked,
    }


def greedy(budget):
    """効果 ÷ 費用 が高い順に、予算に収まるものを選ぶ"""
    order = sorted(candidates, key=lambda k: candidates[k]["value"] / candidates[k]["cost"], reverse=True)
    picked, rest = [], budget
    for k in order:
        if candidates[k]["cost"] <= rest:
            picked.append(k)
            rest -= candidates[k]["cost"]
    return {
        "status": "-",
        "value": sum(candidates[k]["value"] for k in picked),
        "cost": budget - rest,
        "picked": picked,
    }


def show(title, r):
    names = "・".join(candidates[k]["label"] for k in r["picked"])
    print(f"| {title} | {r['value']:,.0f} | {r['cost']:,} | {len(r['picked'])} | {names} |")


if __name__ == "__main__":
    print("| 条件 | 効果 | 費用 | 件数 | 選んだ施策 |")
    print("|------|-----:|-----:|----:|-----------|")
    show("効率順に選ぶ（参考）", greedy(BUDGET))
    rules = []
    for title, rule in [
        ("1: 予算だけ", None),
        ("2: ＋販促は1件まで", "promo_max1"),
        ("3: ＋4件まで", "count_max4"),
        ("4: ＋衛生設備は必須", "must_hygiene"),
        ("5: ＋人材を1件以上", "people_min1"),
    ]:
        if rule:
            rules.append(rule)
        show(title, solve_invest(rules))
```

```text
|------|-----:|-----:|----:|-----------|
| 効率順に選ぶ（参考） | 1,300 | 930 | 7 | 品質研修・Web広告・通販サイト・大型釜の導入・店頭試食会・POSデータ分析・ラベル刷新 |
```

## ハンズオン 13-B — 全探索と最適化の計算時間を比べる

ランダムに作った候補で、全探索とPuLPの計算時間を比べます。

`ch13_compare.py`:

```python
import itertools
import random
import time
import pulp


def make_items(n, seed=7):
    rng = random.Random(seed)
    return {f"item{i:02d}": (rng.randint(50, 400), rng.randint(50, 500)) for i in range(n)}  # (費用, 効果)


def brute_force(items, budget):
    names = list(items)
    best_value, best_pick = -1, None
    for picks in itertools.product([0, 1], repeat=len(names)):
        cost = sum(items[n][0] for n, p in zip(names, picks) if p)
        if cost > budget:
            continue
        value = sum(items[n][1] for n, p in zip(names, picks) if p)
        if value > best_value:
            best_value, best_pick = value, picks
    return best_value


def with_pulp(items, budget):
    prob = pulp.LpProblem("knapsack", pulp.LpMaximize)
    y = {n: prob.add_variable(f"pick_{n}", cat="Binary") for n in items}
    prob += pulp.lpSum(items[n][1] * y[n] for n in items)
    prob += pulp.lpSum(items[n][0] * y[n] for n in items) <= budget
    prob.solve(pulp.HiGHS(msg=False))
    return pulp.value(prob.objective)


if __name__ == "__main__":
    print("| 候補の数 | 組み合わせの数 | 全探索 | 秒 | PuLP | 秒 |")
    print("|-------:|------------:|------:|---:|-----:|---:|")
    for n in [10, 14, 18, 22]:
        items = make_items(n)
        budget = sum(c for c, v in items.values()) // 3
        t0 = time.perf_counter(); bf = brute_force(items, budget); t1 = time.perf_counter()
        pl = with_pulp(items, budget); t2 = time.perf_counter()
        print(f"| {n} | {2 ** n:,} | {bf:,} | {t1 - t0:.2f} | {pl:,.0f} | {t2 - t1:.2f} |")
```

候補22個の全探索は、パソコンによっては数十秒かかります。時間がかかりすぎる場合は、リストから `22` を外してください。

## 初花のメモ帳

- ナップサック問題は「バイナリ変数 × 費用の合計 ≦ 予算」で、価値の合計を最大化する
- 個数・カテゴリの条件は `pick` の合計の上下限、必須は `pick == 1` で書く
- 条件を1つずつ足して、目的関数がいくら下がるかを表にすると、条件の「値段」が分かる

## マリゴールドの one more thing

**「AをやるならBも必要」も、バイナリ変数1本の不等式で書ける。**

たとえば「通販サイトを作るなら、在庫管理システムも必要」という条件は、`pick["ec_site"] <= pick["inventory_sys"]` と書けます。通販サイトが1なら在庫管理システムも1でなければならず、通販サイトが0なら在庫管理システムはどちらでもよい、という意味になります。逆に「AとBは同時にはやらない」なら `pick["A"] + pick["B"] <= 1` です。このように、バイナリ変数どうしの不等式で「かつ」「または」「ならば」のような論理を表す方法は、次の章で「複数の選択肢から一つを選ぶ」ときにも使います。
