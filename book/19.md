# 第19章　ソルバーを使い分ける

**初花**: ここまでずっとHiGHSを使ってきたけど、ネットで調べると、CBCとかGLPKとか、いろんなソルバーの名前が出てくるね。どれが一番いいの？

**マリゴールド**: 「いつでも一番」というソルバーはないんだ。問題の種類や大きさによって、得意・不得意がある。それに、ライセンスや入れやすさも選ぶときの大事な条件だよ。

**初花**: 検索したら、AIの要約に「HiGHSのほうがCBCより速い」って書いてあったよ。

**マリゴールド**: そういう評価はよく見かけるね。でも本書では、人の評価をそのまま信じるのではなく、**自分の問題で実際に測る** ことにしよう。この章では、同じ問題を4つのソルバーで解いて比べてみるよ。

---

## 19.1　PuLPとソルバーの役割

**マリゴールド**: 第1章で見た図を、もう一度確認しておこう。

```text
あなたの Python コード
        │  変数・目的関数・制約条件を書く
        ▼
     PuLP（問題を組み立てて、ソルバー用の形に変換）
        │
        ▼
    ソルバー（HiGHS・CBC・GLPK・SCIP など。答えを計算する）
        │
        ▼
     PuLP（結果を Python の値として返す）
```

**初花**: PuLPで書いたモデルは、ソルバーを取り替えても、そのまま使えるんだよね。

**マリゴールド**: そう。`prob.solve(...)` に渡すソルバーを変えるだけだよ。PuLPの一番の強みは、この **ソルバーを選ばない書き方** にあるんだ。

```python
stats = prob.solve(pulp.HiGHS(msg=False))     # HiGHS で解く
stats = prob.solve(pulp.COIN_CMD(msg=False))  # CBC で解く
```

| 役割 | PuLP | ソルバー |
|------|------|---------|
| モデルを書く | ✅ | — |
| 問題をソルバーの形式に変換する | ✅ | — |
| 答えを計算する | — | ✅ |
| 結果を Python に戻す | ✅ | — |

## 19.2　オープンソースのソルバー

**マリゴールド**: 無料で使えるオープンソースのソルバーのうち、PuLP 4 から使いやすいものを並べるよ。

| ソルバー | PuLPでの名前 | 入れ方 | ライセンス | 呼び出し方 |
|---------|------------|-------|----------|----------|
| HiGHS | `pulp.HiGHS` | `pip install "pulp[highs]"` | MIT | Python の中で直接 |
| CBC | `pulp.COIN_CMD` | `pip install "pulp[cbc]"` | EPL-2.0 | 別のプログラムを起動 |
| GLPK | `pulp.PYGLPK` | `pip install "pulp[glpk]"` | GPL-3.0 | Python の中で直接 |
| SCIP | `pulp.SCIP_PY` | `pip install "pulp[scip]"` | Apache-2.0（SCIP本体）、MIT（PySCIPOpt） | Python の中で直接 |

**初花**: ライセンスがみんな違うんだね。何に気をつければいいの？

**マリゴールド**: PuLPから呼び出して使うだけなら、どれも商用・社内利用で困ることはまずない。気をつけるのは、ソルバーを **自分のソフトに組み込んで配布する** ときだね。

| ライセンス | 性格 | 組み込んで配布するとき |
|----------|------|-------------------|
| MIT・Apache-2.0 | 寛容 | 著作権表示を残せばよい |
| EPL-2.0 | 弱いコピーレフト | ソルバー自体を改変したら、その部分の公開が必要 |
| GPL-3.0 | 強いコピーレフト | 組み込んだソフト全体に GPL がかかることがある |

⚠️ 本書は法律の助言をするものではありません。製品に組み込む場合は、各ソルバーのライセンス文書を確認し、必要なら専門家に相談してください。

**初花**: 本書がHiGHSを標準にしたのは、ライセンスがMITで、Pythonから直接呼べるからなんだね。

**マリゴールド**: そう。PuLP 3 までは CBC が同梱されていて標準だったけど、PuLP 4 からはソルバーを自分で選んで入れる形になった。だからこそ、選び方を知っておく価値があるんだ。

## 19.3　ソルバーの導入・利用可能性の確認

**マリゴールド**: 4つのソルバーをまとめて入れてみよう。

```bash
pip install "pulp[highs]" "pulp[cbc]" "pulp[glpk]" "pulp[scip]"
```

```python
print(pulp.listSolvers(onlyAvailable=True))
```

```text
['PYGLPK', 'COIN_CMD', 'SCIP_PY', 'HiGHS']
```

ソルバーごとに使えるかどうかは、`available()` でも確かめられます。プログラムの中で、使えないソルバーを飛ばしたいときに便利です。

```python
solver = pulp.COIN_CMD(msg=False)
if solver.available():
    stats = prob.solve(solver)
```

**初花**: これで4つとも使えるね。

**マリゴールド**: ……と言いたいところだけど、CBCには一つ、つまずきやすいところがある。macOS（Apple Silicon）で CBC を呼ぶと、こんなエラーになることがあるんだ。

```text
pulp.apis.core.PulpSolverError: Pulp: Error while trying to execute, use msg=True for more details
```

**初花**: `listSolvers` には出てくるのに、動かない？

**マリゴールド**: 調べてみると、CBC のプログラムを直接動かしても、macOS に強制終了されていた。

```text
Killed: 9
```

原因は、CBC と一緒に入るライブラリのうち3つのファイルの **署名が壊れている** ことでした（cbcbox 2.935 で確認）。macOS は、署名が正しくないプログラムの部品を読み込むと、安全のためにプログラムを止めます。

```bash
codesign --verify .../cbcbox/cbc_dist/lib/libgfortran.5.dylib
```

```text
invalid signature (code or signature have been modified)
```

次の手順で、手元のファイルに署名し直すと動くようになります。

```bash
# CBC のライブラリがあるフォルダを調べる
python -c "import cbcbox, pathlib; print(pathlib.Path(cbcbox.__file__).parent / 'cbc_dist' / 'lib')"

# 表示されたフォルダに移動して、3つのファイルに署名し直す
cd （表示されたフォルダ）
codesign --force --sign - libgcc_s.1.1.dylib libgfortran.5.dylib libquadmath.0.dylib
```

**初花**: 「入れたら動く」とは限らないんだね。

**マリゴールド**: そう。だから、ソルバーを入れたら **小さな問題で一度解いてみる** のが大事なんだ。第2章の `hello_pulp.py` のような最小のプログラムが、ここで役に立つ。

⚠️ この問題は、cbcbox 2.935 と macOS 26 の組み合わせで起きるものです。cbcbox の開発元にも報告されています（https://github.com/h-g-s/cbcbox/issues/2 ）。新しいバージョンでは直っている可能性があるので、まずこのページで状況を確かめてください。Windows や Linux では起きません。署名し直すのが不安な場合は、HiGHS など他のソルバーを使ってください。

## 19.4　実行時間・ログ・時間制限

**マリゴールド**: いよいよ比べてみよう。第12章で作った、ランダムな「選ぶ・選ばない」の問題を使うよ。候補の数を100・200・300と増やして、4つのソルバーで解く。

`ch19_compare_sizes.py` の実行結果（手元の環境での例）:

```text
| 候補の数 | ソルバー | 状態 | 目的関数 | 秒 |
|-------:|---------|------|-------:|---:|
| 100 | HiGHS | Optimal | 4,027 | 0.21 |
| 100 | CBC | Optimal | 4,027 | 0.52 |
| 100 | GLPK | Optimal | 4,027 | 0.06 |
| 100 | SCIP | Optimal | 4,027 | 0.17 |
| 200 | HiGHS | Optimal | 7,823 | 2.30 |
| 200 | CBC | Optimal | 7,823 | 1.27 |
| 200 | GLPK | Optimal | 7,823 | 2.58 |
| 200 | SCIP | Optimal | 7,823 | 3.34 |
| 300 | HiGHS | Optimal | 12,011 | 3.10 |
| 300 | CBC | Optimal | 12,011 | 1.45 |
| 300 | GLPK | Optimal | 12,011 | 2.82 |
| 300 | SCIP | Optimal | 12,011 | 2.44 |
```

**初花**: 全部同じ答え！ でも速さはバラバラ。100個だとGLPKが一番速くて、200個と300個ではCBCが一番速い。

**マリゴールド**: 「HiGHSのほうが速い」という評価も、この問題では当てはまらなかったね。公開されているベンチマークでは HiGHS が上位に来ることが多いけど、**自分の問題で速いかどうかは、測ってみないと分からない** んだ。

| 速さを比べるときの注意 | 理由 |
|-------------------|------|
| 自分の問題に近いデータで測る | 問題の形でソルバーの得意・不得意が変わる |
| 大きさを変えて何回か測る | 小さい問題の順位は、大きい問題では入れ替わることがある |
| 同じ答えになることを確かめる | 速くても、答えが違えば意味がない |
| パソコンの環境を書き残す | 秒数は環境によって変わる |

### 時間制限

**マリゴールド**: 大きな問題では、最適解が見つかるまで待てないこともある。そのときは `timeLimit`（秒）を指定して、**その時点で一番良い答え** を受け取る。

```python
stats = prob.solve(pulp.HiGHS(msg=False, timeLimit=2))
```

候補400個の問題で、時間制限を2秒と60秒にして比べた結果です（`ch19_limit.py`）。

```text
| ソルバー | 時間制限 | 状態 | 解あり | 目的関数 | 上限 | ギャップ | 秒 |
|---------|-------:|------|:----:|-------:|----:|-------:|---:|
| HiGHS | 2 | TimeLimit | ○ | 15,408 | 15,415.0 | 0.045% | 2.00 |
| HiGHS | 60 | Optimal | ○ | 15,410 | 15,411.0 | 0.006% | 13.18 |
| CBC | 2 | TimeLimit | ○ | 15,403 | None | — | 2.05 |
| CBC | 60 | Optimal | ○ | 15,410 | None | — | 3.51 |
| GLPK | 2 | Optimal | ○ | 15,410 | None | — | 15.95 |
| GLPK | 60 | Optimal | ○ | 15,410 | None | — | 15.95 |
| SCIP | 2 | TimeLimit | ○ | 15,410 | None | — | 2.03 |
| SCIP | 60 | Optimal | ○ | 15,410 | None | — | 4.85 |
```

**初花**: 時間制限2秒だと、状態が `TimeLimit` になって、最適解より少し悪い答えが返ってきてる。でも「解あり」は○だから、使える答えではあるんだね。

**マリゴールド**: そう。第6章で「`Optimal` 以外なら止める」と書いたけど、`TimeLimit` で `has_solution` が真なら、**最適とは限らないけど、制約は守っている答え** だよ。どれくらい最適に近いかは、上限とのギャップで分かる。

**初花**: GLPKは、2秒って言ったのに16秒かかってる！

**マリゴールド**: PuLP 4.0.1 と GLPK の組み合わせでは、`timeLimit` が効かないんだ。こういう違いも、実際に試して初めて分かる。時間制限が大事な場面では、制限が守られるかを確かめてから使おう。

**初花**: それと、HiGHSの60秒のほう、`Optimal` なのにギャップが0.006%ある。最適じゃないの？

**マリゴールド**: 鋭いね。ソルバーの `Optimal` は、「上限とのギャップが **許容範囲以内** になった」という意味なんだ。HiGHSの許容範囲は、標準で0.01%。第2章のログにも `Gap 0% (tolerance: 0.01%)` と出ていたよ。

ギャップの許容範囲は、`gapRel` で変えられます。

```python
stats = prob.solve(pulp.HiGHS(msg=False, gapRel=0.001))   # 0.1% まで許す
```

```text
| gapRel | 状態 | 目的関数 | 上限 | 秒 |
|-------:|------|-------:|----:|---:|
| （標準） | Optimal | 15,410 | 15,411 | 13.18 |
| 0.001 | Optimal | 15,405 | 15,418 | 0.11 |
| 0.01 | Optimal | 15,286 | 15,418 | 0.02 |
```

**初花**: 0.1%まで許すと、13秒が0.11秒に！ 答えは最適より5小さいだけ。

**マリゴールド**: 実務では、データ自体に数%の誤差があることも多い。0.01%の差を詰めるために何時間も待つより、ギャップを少し許して速く答えを出すほうが役に立つこともあるよ。

| 共通のオプション | 意味 | 例 |
|--------------|------|----|
| `msg` | ログを表示するか | `msg=True` |
| `timeLimit` | 時間制限（秒） | `timeLimit=60` |
| `gapRel` | 許容する相対ギャップ | `gapRel=0.001`（0.1%） |
| `gapAbs` | 許容する絶対ギャップ | `gapAbs=10`（目的関数で10まで） |

⚠️ オプションが効くかどうかは、ソルバーによって違います。使う前に、この節のように小さく試して確かめましょう。

## 19.5　LP形式・MPS形式でのモデル出力

**マリゴールド**: 第7章ではLPファイルをデバッグに使ったね。ソルバーを比べるときにも、ファイルへの書き出しが役立つ。PuLP は **MPS形式** でも書き出せるよ。

```python
prob.writeLP("marche.lp")
prob.writeMPS("marche.mps")
```

`marche.mps`（第1章の屋台の問題）:

```text
*SENSE:Maximize
NAME          marche_plan
ROWS
 N  total_profit
 L  budget
COLUMNS
    MARK      'MARKER'                 'INTORG'
    cookie    budget     3.000000000000e2
    cookie    total_profit  -2.000000000000e2
    MARK      'MARKER'                 'INTEND'
    ...
RHS
    RHS       budget     8.500000000000e3
BOUNDS
 UP BND       cookie     1.000000000000e1
 UP BND       muffin     8.000000000000e0
 UP BND       cake       5.000000000000e0
ENDATA
```

**初花**: LPファイルより読みにくい……。利益の係数がマイナスになってる。

**マリゴールド**: MPS形式は古くからある **機械向け** の形式で、目的関数を最小化の形で持つことが多いから、最大化の係数は符号が反転しているんだ。人が読むならLP形式、ソルバーやほかのツールに渡すならMPS形式、と使い分けるといいよ。

| 形式 | 読みやすさ | 主な使い道 |
|------|----------|----------|
| LP形式 | 人が読みやすい | デバッグ、モデルの確認（第7章） |
| MPS形式 | 機械向け | ソルバー間・ツール間の受け渡し、ベンチマーク |

MPSファイルから問題を読み直して、別のソルバーで解くこともできます。

```python
variables, prob2 = pulp.LpProblem.fromMPS("marche.mps", sense=pulp.LpMaximize)
for name, solver in [("HiGHS", pulp.HiGHS(msg=False)), ("CBC", pulp.COIN_CMD(msg=False))]:
    stats = prob2.solve(solver)
    print(name, stats.status_str, pulp.value(prob2.objective), {k: v.value() for k, v in variables.items()})
```

```text
HiGHS Optimal 6100.0 {'cookie': 5.0, 'muffin': 6.0, 'cake': 5.0}
CBC Optimal 6100.0 {'cookie': 5.0, 'muffin': 6.0, 'cake': 5.0}
```

**初花**: ファイルにしておけば、モデルを作ったプログラムがなくても、あとで解き直せるんだ。

**マリゴールド**: 「このモデルで遅い」と相談するときも、MPSファイルを渡せば再現してもらえる。第20章で扱う **再現性** にもつながる考え方だよ。

## 19.6　規模や問題の種類に応じた選択

**マリゴールド**: 最後に、選び方の目安をまとめておこう。

| 状況 | 選び方の目安 |
|------|-----------|
| まず始める | HiGHS（MIT、Pythonから直接、PuLP 4で入れやすい） |
| 遅いと感じたら | 自分の問題で CBC・SCIP なども測って比べる |
| 時間制限が大事 | 制限が守られるソルバーを、実際に試して選ぶ |
| 製品に組み込んで配布する | ライセンス（MIT・Apache・EPL・GPL）を確認する |
| さらに大規模・高速が必要 | 商用ソルバー（Gurobi・CPLEX・Xpress など）も検討する |

**初花**: 商用ソルバーも、PuLPから使えるの？

**マリゴールド**: 使えるよ。PuLP 4 の extra にも `gurobi`・`cplex`・`xpress` などが用意されている。ライセンスの費用はかかるけど、大きな整数計画問題では、オープンソースより大幅に速いことがある。無料の試用版や、学生・研究者向けの無料ライセンスがある製品もあるよ。

**初花**: モデルの書き方は変えなくていいんだよね。

**マリゴールド**: そう。だから、まずはHiGHSでモデルを正しく作ることに集中して、速さが足りなくなったら、ソルバーを取り替えて試す——この順番が一番無駄がないんだ。

## ハンズオン 19-A — 同じ問題を複数のソルバーで実行し、結果と実行状況を比較する

使えるソルバーをすべて試して、状態・目的関数・時間を表にします。第12章の `ch12_scale.py` を同じフォルダに置いて実行します。

`ch19_compare.py`:

```python
import time
import pulp
from ch12_scale import make_data

SOLVERS = {
    "HiGHS": lambda **kw: pulp.HiGHS(**kw),
    "CBC": lambda **kw: pulp.COIN_CMD(**kw),
    "GLPK": lambda **kw: pulp.PYGLPK(**kw),
    "SCIP": lambda **kw: pulp.SCIP_PY(**kw),
}


def build(n):
    value, use, cap = make_data(n)
    prob = pulp.LpProblem("select", pulp.LpMaximize)
    x = [prob.add_variable(f"x{i}", cat="Binary") for i in range(n)]
    prob += pulp.lpSum(v * xi for v, xi in zip(value, x))
    for k, row in enumerate(use):
        prob += pulp.lpSum(u * xi for u, xi in zip(row, x)) <= cap[k], f"res_{k}"
    return prob


if __name__ == "__main__":
    available = pulp.listSolvers(onlyAvailable=True)
    print("使えるソルバー:", available)
    print()
    print("| ソルバー | 状態 | 目的関数 | 秒 |")
    print("|---------|------|-------:|---:|")
    for name, make_solver in SOLVERS.items():
        prob = build(100)
        solver = make_solver(msg=False, timeLimit=60)
        if not solver.available():
            print(f"| {name} | 使えない | — | — |")
            continue
        start = time.perf_counter()
        try:
            stats = prob.solve(solver)
            print(f"| {name} | {stats.status_str} | {pulp.value(prob.objective):,.0f} | {time.perf_counter() - start:.2f} |")
        except Exception as e:
            print(f"| {name} | エラー: {type(e).__name__} | — | — |")
```

実行結果（手元の環境での例）:

```text
使えるソルバー: ['PYGLPK', 'COIN_CMD', 'SCIP_PY', 'HiGHS']

| ソルバー | 状態 | 目的関数 | 秒 |
|---------|------|-------:|---:|
| HiGHS | Optimal | 4,027 | 0.21 |
| CBC | Optimal | 4,027 | 0.56 |
| GLPK | Optimal | 4,027 | 0.06 |
| SCIP | Optimal | 4,027 | 0.17 |
```

入れていないソルバーは「使えない」、入れたのに動かないソルバーは「エラー」と表示されます。19.3 の macOS の CBC の問題がある環境では、CBC の行が `エラー: PulpSolverError` になります。

| `SOLVERS` の書き方 | 理由 |
|-----------------|------|
| `lambda **kw: pulp.HiGHS(**kw)` | オプション（`msg`、`timeLimit` など）を後から渡せるようにする |
| 毎回 `build(100)` で作り直す | 前のソルバーの結果が変数に残らないようにする |

## ハンズオン 19-B — 大きさと時間制限を変えて比べる

19.4 の2つの表を作るプログラムです。

`ch19_compare_sizes.py`:

```python
import time
import pulp
from ch19_compare import SOLVERS, build

print("| 候補の数 | ソルバー | 状態 | 目的関数 | 秒 |")
print("|-------:|---------|------|-------:|---:|")
for n in [100, 200, 300]:
    for name, make_solver in SOLVERS.items():
        prob = build(n)
        start = time.perf_counter()
        stats = prob.solve(make_solver(msg=False, timeLimit=60))
        print(f"| {n} | {name} | {stats.status_str} | {pulp.value(prob.objective):,.0f} | {time.perf_counter() - start:.2f} |")
```

`ch19_limit.py`:

```python
import time
import pulp
from ch19_compare import SOLVERS, build

print("| ソルバー | 時間制限 | 状態 | 解あり | 目的関数 | 上限 | ギャップ | 秒 |")
print("|---------|-------:|------|:----:|-------:|----:|-------:|---:|")
for name, make_solver in SOLVERS.items():
    for limit in [2, 60]:
        prob = build(400)
        start = time.perf_counter()
        stats = prob.solve(make_solver(msg=False, timeLimit=limit))
        obj = pulp.value(prob.objective) if stats.has_solution else None
        bound = stats.best_bound
        gap = (bound - obj) / obj if (obj and bound) else None
        print(f"| {name} | {limit} | {stats.status_str} | {'○' if stats.has_solution else '×'} | "
              f"{'—' if obj is None else f'{obj:,.0f}'} | {bound if bound is None else f'{bound:,.1f}'} | "
              f"{'—' if gap is None else f'{gap:.3%}'} | {time.perf_counter() - start:.2f} |")
```

`stats.best_bound`（上限）は、ソルバーによっては返ってきません（表の `None`）。ギャップを見たいときは HiGHS を使うか、`msg=True` でログを確かめます。

## 振り返り

**初花**: PuLPのモデルはそのままで、ソルバーだけ取り替えて比べられた。しかも、評判と実際の速さが違うこともあった。

**マリゴールド**: CBCの署名の問題や、GLPKで時間制限が効かないことも、実際に動かして初めて分かったことだね。ソルバーを選ぶときは、**入れる・動かす・測る** を自分の手でやるのが一番確かなんだ。

**初花**: それに、`Optimal` が「許容範囲以内」って意味なのは知らなかった。`gapRel` を少し緩めるだけで、あんなに速くなるなんて。

## 初花のメモ帳

- ソルバーは `prob.solve(...)` に渡すものを変えるだけで取り替えられる。入れたら小さな問題で必ず試す
- 速さは問題によって変わる。評判ではなく、自分の問題で大きさを変えて測る
- `Optimal` は「ギャップが許容範囲以内」の意味。`timeLimit` と `gapRel` で、待ち時間と答えの良さを調整できる

## マリゴールドの one more thing

**初期解を渡すと、ソルバーが早く良い答えを見つけることがある。**

前の週の計画や、人が作った案など、「だいたい良い答え」が手元にあることはよくあります。それを **初期解**（warm start）としてソルバーに渡すと、分枝限定法の暫定解として最初から使われ、打ち切れる枝が増えて速く解けることがあります。PuLP 4 では、変数に `setInitialValue(値)` で初期値を入れ、ソルバーに `warmStart=True` を渡します。ただし、初期解を受け付けるかどうかはソルバーによって違うので、19.4 の時間制限と同じように、実際に効くかを確かめてから使いましょう。第20章で扱う「毎週実行するプログラム」では、先週の答えを初期解にする工夫が特に効きます。
