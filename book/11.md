# 第11章　人員配置とタスク割り当て

**初花**: うめ食品の工場長さんから、今度は人の話。毎朝、誰にどの作業をお願いするか決めるのに30分もかかってるんだって。

**マリゴールド**: **割り当て問題** だね。物を運ぶ代わりに、人を仕事に割り当てる。誰がどの作業をするかを「する・しない」で表すのがポイントだよ。

**初花**: 「する・しない」って、0か1ってこと？

**マリゴールド**: そう。第5章でちらっと出てきた **バイナリ変数** を、ここで初めて本格的に使う。バイナリ変数の詳しい性質は第12章で整理するから、この章ではまず使い方に慣れよう。

## 11.1　人と仕事の組み合わせを変数にする

工場の作業員と、その日の作業です（本書用の架空のデータです）。

| 作業員 | 時給 | ひとこと |
|--------|-----:|---------|
| 佐藤 | 2,000円 | ベテラン。何でも速い |
| 鈴木 | 1,500円 | 中堅。仕込みも清掃もできる |
| 高橋 | 1,200円 | 入社2年目 |
| 田中 | 1,200円 | 別部署からの応援 |
| 伊藤 | 1,000円 | 新人 |

その人がその作業をすると何時間かかるかの表です。「—」は、資格や免許がなくて担当できない作業です。

| 作業員 | 原料検品 | ジャム仕込み | 瓶詰め | ラベル貼り | 箱詰め | フォークリフト | 機械清掃 | 在庫記録 |
|--------|------:|---------:|-----:|--------:|-----:|------------:|-------:|-------:|
| 佐藤 | 1.5 | 3.0 | 2.0 | 1.0 | 1.5 | 1.0 | 2.0 | 1.0 |
| 鈴木 | 2.0 | 3.5 | 2.5 | 1.5 | 2.0 | 1.5 | 2.0 | 1.5 |
| 高橋 | 2.5 | — | 3.0 | 1.5 | 2.0 | — | 2.5 | 2.0 |
| 田中 | 2.5 | 4.5 | 3.0 | 2.0 | 2.5 | 2.0 | 3.0 | 2.0 |
| 伊藤 | 3.0 | — | 3.5 | 2.0 | 2.5 | — | 3.0 | 2.5 |

**マリゴールド**: 変数は「作業員 × 作業」の組み合わせごとに1つ。**1なら担当する、0なら担当しない** という意味のバイナリ変数にするよ。

```python
# 1 なら「w さんが t の作業を担当する」
x = {(w, t): prob.add_variable(f"x_{w}_{t}", cat="Binary") for (w, t) in hours}
```

**初花**: 0か1しか取らない変数って、どう計算に使うの？

**マリゴールド**: 掛け算が「スイッチ」になるんだ。たとえば佐藤さんの作業時間は、「各作業の時間 × その作業を担当するか（0か1）」の合計で書ける。担当しない作業は0倍で消えて、担当する作業だけが残る。

```python
load = {w: pulp.lpSum(hours[w, t] * x[w, t] for t in tasks if (w, t) in hours) for w in workers}
```

| 佐藤さんの変数 | 原料検品 | フォークリフト | 在庫記録 | ほかの作業 |
|-------------|-------:|------------:|-------:|---------:|
| `x` の値 | 1 | 1 | 1 | 0 |
| 時間 × `x` | 1.5 | 1.0 | 1.0 | 0 |
| **合計** | | | | **3.5 時間** |

## 11.2　担当可能な仕事を制約にする

**初花**: 「—」の作業は、どうやって禁止するの？

**マリゴールド**: 第9章で、ラインBで作れない梅干しの変数を作らなかったのと同じだよ。**担当できない組み合わせは、変数を作らない**。データの表で `None` にしておいて、辞書を作るときに飛ばすんだ。

```python
# その人がその作業をすると何時間かかるか。None はできない（資格・免許がない）
hours_table = {
    #             検品  仕込み 瓶詰め ラベル 箱詰め リフト 清掃  在庫
    "sato":      [1.5,  3.0,   2.0,   1.0,   1.5,   1.0,   2.0,  1.0],
    "suzuki":    [2.0,  3.5,   2.5,   1.5,   2.0,   1.5,   2.0,  1.5],
    "takahashi": [2.5,  None,  3.0,   1.5,   2.0,   None,  2.5,  2.0],
    "tanaka":    [2.5,  4.5,   3.0,   2.0,   2.5,   2.0,   3.0,  2.0],
    "ito":       [3.0,  None,  3.5,   2.0,   2.5,   None,  3.0,  2.5],
}
hours = {
    (w, t): h
    for w, row in hours_table.items()
    for t, h in zip(tasks, row)
    if h is not None
}
```

**初花**: 表の形のままデータを書けるのは分かりやすい。`zip(tasks, row)` で、作業名と時間を並べてるんだね。

**マリゴールド**: そう。`tasks` は辞書だけど、`zip` に渡すとキーが順番に取り出される。表の列の順番と `tasks` の順番がそろっていることが大事だから、コメントで列名を書いておいたよ。

| 担当できないことの表し方 | 例 |
|----------------------|----|
| 変数を作らない | 資格・免許・権限がない |
| 時間を大きくする | 「できるけど、とても遅い」 |
| 個別の制約 `x[w, t] == 0` | その日だけの事情（今日は腰を痛めている、など） |

## 11.3　各仕事を必ず割り当てる

**マリゴールド**: 割り当て問題で一番大事な制約は、**どの作業にも、ちょうど1人が付く** こと。担当者がいない作業も、2人で同じ作業をすることもないようにする。

```python
for t in tasks:
    prob += pulp.lpSum(x[w, t] for w in workers if (w, t) in hours) == 1, f"one_{t}"
```

**初花**: バイナリ変数の合計が1、ってことは、その作業の列で1になるのは一人だけ、ってことだね。

**マリゴールド**: その通り。バイナリ変数の合計は「何人（何個）が選ばれたか」を数える道具になる。人の側にも、1日8時間までという制約を付けるよ。

```python
for w in workers:
    prob += load[w] <= MAX_HOURS, f"cap_{w}"
```

| バイナリ変数の合計の制約 | 意味 |
|----------------------|------|
| `== 1` | ちょうど1つ選ぶ |
| `<= 1` | 選ばないか、1つだけ選ぶ |
| `>= 1` | 少なくとも1つ選ぶ |
| `<= k` | k 個まで選ぶ |

## 11.4　担当者の能力やコストを反映する

**マリゴールド**: 目的関数を何にするかで、割り当ては大きく変わる。まずは「合計の作業時間を最小にする」で解いてみよう。

```text
■ 合計時間を最小: Optimal
  人件費 24,250 円 / 合計 13.5 時間 / いちばん忙しい人 8.0 時間
  佐藤: 8.0 時間  原料検品・瓶詰め・ラベル貼り・箱詰め・フォークリフト・在庫記録
  鈴木: 5.5 時間  ジャム仕込み・機械清掃
  高橋: 0.0 時間  （なし）
  田中: 0.0 時間  （なし）
  伊藤: 0.0 時間  （なし）
```

**初花**: 佐藤さんに6つも！ 一番速いから当然かもしれないけど、ほかの3人は何もしてない。

**マリゴールド**: 時間だけを見れば、速い人に集めるのが一番だからね。でも佐藤さんは時給も一番高い。今度は「人件費を最小にする」で解いてみよう。人件費は「時給 × 作業時間」の合計だよ。

```python
total_cost = pulp.lpSum(workers[w]["wage"] * hours[w, t] * x[w, t] for (w, t) in hours)
```

```text
■ 人件費を最小: Optimal
  人件費 22,950 円 / 合計 16.5 時間 / いちばん忙しい人 7.5 時間
  佐藤: 2.0 時間  フォークリフト・在庫記録
  鈴木: 7.5 時間  原料検品・ジャム仕込み・機械清掃
  高橋: 3.5 時間  ラベル貼り・箱詰め
  田中: 0.0 時間  （なし）
  伊藤: 3.5 時間  瓶詰め
```

**初花**: 人件費は1,300円安くなったけど、合計時間は3時間も増えてる。今度は鈴木さんが7.5時間で大変そう。それに田中さんがまた何もしてない。

**マリゴールド**: 速さとお金は、たいてい取り合いの関係になる。時給が安くても遅すぎる人は、かえって高くつくこともあるから、ソルバーは人件費と時間のバランスを計算して選んでいるんだ。

| 目的関数 | 人件費 | 合計時間 | いちばん忙しい人 | 何もしない人 |
|---------|------:|-------:|-------------:|-----------:|
| 合計時間を最小 | 24,250 円 | 13.5 時間 | 8.0 時間 | 3人 |
| 人件費を最小 | 22,950 円 | 16.5 時間 | 7.5 時間 | 1人 |

## 11.5　公平性を考慮した割り当て

**初花**: どっちの割り当ても、一人に仕事が集まりすぎてて、現場の雰囲気が悪くなりそう。もっと均等にできないかな。

**マリゴールド**: 公平さの表し方はいろいろあるけど、よく使うのは **いちばん忙しい人の作業時間を、できるだけ短くする** という目的だよ。

**初花**: 「いちばん忙しい人」って、`max()` だよね。第7章で、`max` は使えないって……。

**マリゴールド**: よく覚えていたね。ここで使うのが、**補助変数** の技だ。いちばん忙しい人の時間を表す新しい変数 `z` を作って、「全員の作業時間は `z` 以下」という制約を付ける。そして `z` を最小化するんだ。

```python
z = prob.add_variable("max_load", lowBound=0)   # いちばん忙しい人の作業時間
prob += z, "max_load"
for w in workers:
    prob += load[w] <= z, f"le_max_{w}"
```

```text
全員の作業時間 ≦ z     … z は全員の上限
z を最小化する          … 上限をぎりぎりまで下げる
→ z は「いちばん忙しい人の作業時間」と同じ値になる
```

**初花**: なるほど、`z` が天井で、天井をできるだけ低くするんだ。全員がその下に収まるように。

**マリゴールド**: このやり方で、いちばん忙しい人の作業時間は **3.5時間** まで下げられると分かった。ただ、`z` だけを最小にすると、人件費はどうでもよくなってしまう。そこで第6章の2段階の考え方を使うよ。1段目で `z` の最小値を求めて、2段目では「全員3.5時間以内」を条件にして、人件費を最小にする。

```text
■ 公平（いちばん忙しい人を最小：3.5 時間）のなかで人件費を最小: Optimal
  人件費 23,050 円 / 合計 16.5 時間 / いちばん忙しい人 3.5 時間
  佐藤: 3.5 時間  原料検品・フォークリフト・在庫記録
  鈴木: 3.5 時間  ジャム仕込み
  高橋: 3.5 時間  ラベル貼り・箱詰め
  田中: 3.0 時間  瓶詰め
  伊藤: 3.0 時間  機械清掃
```

**初花**: 全員が3〜3.5時間！ しかも人件費は、最安の22,950円より100円高いだけ。

**マリゴールド**: 公平にするための費用が100円だと分かるのが大事なんだ。それに、作業を並行して進めるなら、一番遅い人が終わった時点でその日の作業が終わる。8時間かかっていた仕事が3.5時間で終わるとも読めるよ。

| 割り当て | 人件費 | いちばん忙しい人 | 何もしない人 |
|---------|------:|-------------:|-----------:|
| 合計時間を最小 | 24,250 円 | 8.0 時間 | 3人 |
| 人件費を最小 | 22,950 円 | 7.5 時間 | 1人 |
| 公平 ＋ 人件費を最小 | 23,050 円 | 3.5 時間 | 0人 |

| 公平さの表し方 | 補助変数の使い方 |
|-------------|---------------|
| いちばん忙しい人を最小にする | `load[w] <= z` で `z` を最小化 |
| いちばん暇な人を最大にする | `load[w] >= z` で `z` を最大化 |
| 全員を一定の範囲に収める | `low <= load[w] <= high` を制約にする |

## ハンズオン 11-A — スキルと作業コストを考慮して、仕事を最適に割り当てる

11.1〜11.5 を1つのプログラムにまとめます。目的関数を `objective` で切り替えられるようにしてあります。

`ch11_assign.py`:

```python
import pulp

# 作業員と時給（円）。本書用の架空のデータ
workers = {
    "sato":      {"label": "佐藤",   "wage": 2000},
    "suzuki":    {"label": "鈴木",   "wage": 1500},
    "takahashi": {"label": "高橋",   "wage": 1200},
    "tanaka":    {"label": "田中",   "wage": 1200},
    "ito":       {"label": "伊藤",   "wage": 1000},
}
tasks = {
    "inspect": "原料検品", "jam_prep": "ジャム仕込み", "bottling": "瓶詰め", "labeling": "ラベル貼り",
    "boxing": "箱詰め", "forklift": "フォークリフト", "cleaning": "機械清掃", "inventory": "在庫記録",
}

# その人がその作業をすると何時間かかるか。None はできない（資格・免許がない）
hours_table = {
    #             検品  仕込み 瓶詰め ラベル 箱詰め リフト 清掃  在庫
    "sato":      [1.5,  3.0,   2.0,   1.0,   1.5,   1.0,   2.0,  1.0],
    "suzuki":    [2.0,  3.5,   2.5,   1.5,   2.0,   1.5,   2.0,  1.5],
    "takahashi": [2.5,  None,  3.0,   1.5,   2.0,   None,  2.5,  2.0],
    "tanaka":    [2.5,  4.5,   3.0,   2.0,   2.5,   2.0,   3.0,  2.0],
    "ito":       [3.0,  None,  3.5,   2.0,   2.5,   None,  3.0,  2.5],
}
hours = {
    (w, t): h
    for w, row in hours_table.items()
    for t, h in zip(tasks, row)
    if h is not None
}
MAX_HOURS = 8   # 1人1日8時間まで


def solve_assign(objective, max_load=None):
    prob = pulp.LpProblem("assign", pulp.LpMinimize)

    # 1 なら「w さんが t の作業を担当する」
    x = {(w, t): prob.add_variable(f"x_{w}_{t}", cat="Binary") for (w, t) in hours}

    load = {w: pulp.lpSum(hours[w, t] * x[w, t] for t in tasks if (w, t) in hours) for w in workers}
    total_hours = pulp.lpSum(load.values())
    total_cost = pulp.lpSum(workers[w]["wage"] * hours[w, t] * x[w, t] for (w, t) in hours)

    if objective == "hours":
        prob += total_hours, "total_hours"
    elif objective == "cost":
        prob += total_cost, "total_cost"
    elif objective == "max_load":
        z = prob.add_variable("max_load", lowBound=0)   # いちばん忙しい人の作業時間
        prob += z, "max_load"
        for w in workers:
            prob += load[w] <= z, f"le_max_{w}"

    for t in tasks:
        prob += pulp.lpSum(x[w, t] for w in workers if (w, t) in hours) == 1, f"one_{t}"
    for w in workers:
        prob += load[w] <= (MAX_HOURS if max_load is None else max_load), f"cap_{w}"

    stats = prob.solve(pulp.HiGHS(msg=False))
    if stats.status_str != "Optimal":
        return {"status": stats.status_str}
    return {
        "status": stats.status_str,
        "cost": pulp.value(total_cost),
        "hours": pulp.value(total_hours),
        "load": {w: pulp.value(load[w]) for w in workers},
        "tasks": {w: [t for t in tasks if (w, t) in hours and x[w, t].value() > 0.5] for w in workers},
    }


def show(title, r):
    print(f"■ {title}: {r['status']}")
    if r["status"] != "Optimal":
        return
    print(f"  人件費 {r['cost']:,.0f} 円 / 合計 {r['hours']:.1f} 時間 / いちばん忙しい人 {max(r['load'].values()):.1f} 時間")
    for w in workers:
        names = "・".join(tasks[t] for t in r["tasks"][w]) or "（なし）"
        print(f"  {workers[w]['label']}: {r['load'][w]:.1f} 時間  {names}")


if __name__ == "__main__":
    show("合計時間を最小", solve_assign("hours"))
    show("人件費を最小", solve_assign("cost"))

    fair = solve_assign("max_load")
    best_max = max(fair["load"].values())
    show(f"公平（いちばん忙しい人を最小：{best_max:.1f} 時間）のなかで人件費を最小",
         solve_assign("cost", max_load=best_max + 1e-6))
```

実行すると、11.4 と 11.5 で見た3つの割り当てが順に表示されます。

⚠️ 結果からバイナリ変数の値を読むときは、`x[w, t].value() > 0.5` のように判定します。小数の誤差で `0.9999999` のような値になることがあるため、`== 1` で比べるのは避けます。

## 振り返り

**初花**: バイナリ変数って、0と1だけなのに、すごく便利。掛け算でスイッチになるし、合計すると人数を数えられる。

**マリゴールド**: しかも補助変数の `z` を使えば、`max` のような「書けないはずの目的」も書けた。この二つは、第4部でたくさん使う技だよ。

**初花**: 公平にしても100円しか変わらないなら、工場長さんにも勧めやすい。最初の「時間最小」の答えだったら、佐藤さんに怒られてたね。

**マリゴールド**: 目的関数を一つに決める前に、いくつか試して比べる。それが、人に受け入れられる答えを出すコツだよ。次の章からは第4部。整数変数とバイナリ変数を、じっくり見ていこう。

## 初花のメモ帳

- 割り当ては「人 × 仕事」のバイナリ変数。担当できない組み合わせは変数を作らない
- 「各仕事にちょうど1人」は、バイナリ変数の合計 `== 1` で書く
- 「いちばん忙しい人を最小」は、補助変数 `z` を作って `load[w] <= z` とし、`z` を最小化する

## マリゴールドの one more thing

**割り当て問題には、専用の速い解き方もある。**

「n人にn個の仕事を1つずつ割り当てて、費用の合計を最小にする」という最も単純な形は、**ハンガリー法** という専用のアルゴリズムで、とても速く解けます。Pythonでは `scipy.optimize.linear_sum_assignment` で使えます。ただし、この章のように「1人が複数の作業を担当できる」「作業時間の上限がある」「公平性を考える」といった条件が加わると、専用のアルゴリズムでは扱えません。PuLPで書いたモデルは、条件を足しても同じ書き方で解けるのが強みです。専用の方法と汎用の方法の使い分けは、第19章のソルバー選びでも同じ考え方をします。
