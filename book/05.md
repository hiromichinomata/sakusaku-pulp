# 第5章　変数・制約条件をPythonで管理する

**初花**: 次のマルシェでは、梅ゼリーも出したいんだ。前の章のコードに、変数を1つと、制約の式に項を1つずつ足せばいいよね。

**マリゴールド**: 今はそれで済む。でも商品が10種類、資源が8種類になったら？ 式を全部手で直すのは大変だし、どこかで足し忘れるよ。

**初花**: うっ……絶対どこか忘れる自信がある。

**マリゴールド**: だからこの章では、**データとモデルを分ける**。モデル表をPythonの辞書にして、`for` 文で変数と制約を作るようにすれば、商品が増えてもデータを書き足すだけで済むんだ。

## 5.1　変数の上下限と型

**マリゴールド**: 辞書に移る前に、変数を作る `add_variable` の引数をもう一度整理しておこう。

```python
prob.add_variable(name, lowBound=None, upBound=None, cat="Continuous")
```

| 引数 | 省略したとき | 指定の例 |
|------|------------|---------|
| `name` | （省略不可） | `"make_jam"` |
| `lowBound` | 下限なし（マイナス無限大まで） | `0`、`10` |
| `upBound` | 上限なし | `20` |
| `cat` | `"Continuous"`（小数OK） | `"Integer"`、`"Binary"` |

**初花**: 上限がないときは、`upBound=None` って書いてもいいの？

**マリゴールド**: いいよ。`None` は「指定しない」という意味になる。これが辞書で便利なんだ。商品ごとに「上限あり」「上限なし」が混ざっていても、`None` を入れておけば同じ書き方で作れるからね。

| 変数の性質 | 書き方 |
|-----------|-------|
| 0以上の量 | `lowBound=0` |
| 0以上の個数 | `lowBound=0, cat="Integer"` |
| 10以上20以下の個数 | `lowBound=10, upBound=20, cat="Integer"` |
| 作る・作らない | `cat="Binary"`（0か1。第12章から使う） |

⚠️ `cat="Binary"` を指定すると、`lowBound` と `upBound` は自動で0と1になります。

---

## 5.2　複数の変数を辞書で管理する

**初花**: 変数を辞書に入れるって、どういうこと？

**マリゴールド**: 今までは `jam`、`syrup`、`umeboshi` と、商品ごとにPythonの変数を作っていたよね。これを **商品名をキーにした辞書** 1つにまとめるんだ。

```python
products = ["jam", "syrup", "umeboshi"]

make = {p: prob.add_variable(f"make_{p}", lowBound=0, cat="Integer") for p in products}
```

```text
{'jam': make_jam, 'syrup': make_syrup, 'umeboshi': make_umeboshi}
```

| 書き方 | 意味 |
|--------|------|
| `make["jam"]` | ジャムを作る数の変数 |
| `make[p]` | `for p in products` の中で、各商品の変数 |
| `make.values()` | すべての変数 |

全部の変数が同じ上下限・型なら、PuLPの `add_variable_dict` でも同じものが作れます。

```python
make = prob.add_variable_dict("make", products, lowBound=0, cat="Integer")
```

**初花**: 短い！ でも商品ごとに下限が違うときは？

**マリゴールド**: `add_variable_dict` は全部に同じ上下限を付けるから、そのときは最初の辞書内包表記を使う。本書では、商品ごとに条件を変えやすい辞書内包表記を基本にするよ。

## 5.3　リストや辞書から制約条件を生成する

**マリゴールド**: 変数が辞書になったら、式は `pulp.lpSum` でまとめて書ける。第1章のコードにも出てきた関数だね。

```python
profit = {"jam": 450, "syrup": 400, "umeboshi": 500}

prob += pulp.lpSum(profit[p] * make[p] for p in products), "total_profit"
```

これは次の式と同じ意味です。

```python
prob += 450 * make["jam"] + 400 * make["syrup"] + 500 * make["umeboshi"], "total_profit"
```

**初花**: `lpSum` の中身は、Pythonの `for` を1行で書いたやつだね。商品が10個になっても、この1行は変わらない。

**マリゴールド**: そう。制約条件も同じ形で書ける。たとえば瓶の制約は、ジャムとシロップしか使わない。**使わない商品は係数0** と考えれば、全商品で同じ式にできるよ。

```python
jar_use = {"jam": 1, "syrup": 1}   # 梅干しは瓶を使わない

prob += pulp.lpSum(jar_use.get(p, 0) * make[p] for p in products) <= 50, "cap_jars"
```

| 書き方 | `p = "umeboshi"` のとき |
|--------|----------------------|
| `jar_use[p]` | ❌ `KeyError`（キーがない） |
| `jar_use.get(p, 0)` | ✅ `0`（キーがなければ0） |

⚠️ 辞書の `get(キー, 0)` を使うと、「使わない商品」をデータに書かずに済みます。逆に、本当は使うのに書き忘れても0として扱われ、エラーにならない点に注意します。第6章の検証で、使用量を確かめる理由の一つです。

## 5.4　`for`文を使ってモデルを一般化する

**マリゴールド**: 材料がそろったから、第4章のモデル表を丸ごと辞書にしよう。

**商品のデータ**（モデル表の「変数」の部分）

```python
products = {
    "jam":      {"label": "ジャム", "profit": 450, "min": 10, "max": None},
    "syrup":    {"label": "シロップ", "profit": 400, "min": 0, "max": None},
    "umeboshi": {"label": "梅干し", "profit": 500, "min": 0, "max": 20},
}
```

**資源のデータ**（モデル表の「係数と上限」の部分）

```python
resources = {
    "ume_g":    {"label": "梅(g)", "capacity": 18 * 1000,
                 "use": {"jam": 300, "syrup": 400, "umeboshi": 500}},
    "sugar_g":  {"label": "砂糖(g)", "capacity": 10 * 1000,
                 "use": {"jam": 200, "syrup": 400}},
    "work_min": {"label": "作業(分)", "capacity": 12 * 60,
                 "use": {"jam": 20, "syrup": 10, "umeboshi": 15}},
    "jars":     {"label": "瓶(個)", "capacity": 50,
                 "use": {"jam": 1, "syrup": 1}},
}
```

**初花**: モデル表の1行が、辞書の1項目になってる。

**マリゴールド**: あとは、資源の数だけ `for` 文で制約を作ればいい。モデルを作る部分は関数にまとめておこう。

```python
def build_model(products, resources):
    prob = pulp.LpProblem("marche_data", pulp.LpMaximize)

    make = {
        p: prob.add_variable(f"make_{p}", lowBound=info["min"], upBound=info["max"], cat="Integer")
        for p, info in products.items()
    }

    prob += pulp.lpSum(products[p]["profit"] * make[p] for p in products), "total_profit"

    used = {}
    for r, info in resources.items():
        used[r] = pulp.lpSum(info["use"].get(p, 0) * make[p] for p in products)
        prob += used[r] <= info["capacity"], f"cap_{r}"

    return prob, make, used
```

| 部分 | 第4章のコードとの違い |
|------|---------------------|
| 変数 | 商品ごとに1行 → 辞書内包表記1つ |
| 目的関数 | 項を並べる → `lpSum` 1行 |
| 制約条件 | 資源ごとに1行 → `for` 文1つ |
| 使用量の式 | 名前を付けた変数 → 辞書 `used` |

**初花**: 関数の中に、ジャムとか梅とかの具体的な名前が一つも出てこない！

**マリゴールド**: それが一般化だよ。この関数は、梅の屋台でも、パン屋でも、工場でも、同じ形のデータなら解ける。

`print(prob)` で、第4章と同じモデルができているか確かめます。

```text
marche_data:
MAXIMIZE
450.0*make_jam + 400.0*make_syrup + 500.0*make_umeboshi + 0.0
SUBJECT TO
cap_ume_g: 300 make_jam + 400 make_syrup + 500 make_umeboshi <= 18000

cap_sugar_g: 200 make_jam + 400 make_syrup <= 10000

cap_work_min: 20 make_jam + 10 make_syrup + 15 make_umeboshi <= 720

cap_jars: make_jam + make_syrup <= 50

VARIABLES
10 <= make_jam Integer
0 <= make_syrup Integer
0 <= make_umeboshi <= 20 Integer
```

## 5.5　変数名・制約名の付け方

**初花**: `make_jam` とか `cap_ume_g` とか、名前に決まりはあるの？

**マリゴールド**: PuLPが強制する決まりは少ないけど、本書では三つのルールで付けるよ。

| ルール | 良い例 | 避けたい例 | 理由 |
|--------|-------|-----------|------|
| 英小文字・数字・`_` だけ | `make_jam` | `ジャム`、`make jam` | ソルバーやLPファイルで扱いやすい |
| 種類を先頭に付ける | `make_jam`、`cap_jars` | `jam`、`jars` | 変数か制約か、何の制約かが分かる |
| 名前を重複させない | `cap_ume_g` が1つだけ | `cap` が2つ | 重複するとLPファイルを書き出せない |

**初花**: 日本語の名前はダメなんだ。

**マリゴールド**: 動くことは動く。でも空白は勝手に `_` に変えられるし、ソルバーによっては日本語を読めないこともある。日本語は `label` のようにデータ側に持っておいて、表示するときに使うのが安全だよ。

名前の重複は、PuLPが黙って受け付けてしまうので特に注意が必要です。

```python
x = prob.add_variable("x", 0, 10)
x2 = prob.add_variable("x", 0, 10)   # 同じ名前（エラーにならない）

prob.checkDuplicateVars()
```

```text
pulp.constants.PulpError: Repeated variable names: {('x', 2)}
```

`for` 文で名前を作るときは、`f"make_{p}"` のように **キーを名前に含める** と、重複を防げます。不安なときは `prob.checkDuplicateVars()` と `prob.checkDuplicateConstraints()` で確かめましょう。

## 5.6　変数や制約条件を追加・変更する

**初花**: モデルを作った後で、制約の上限を変えたくなったら？ 「作業時間を14時間にしたら」とか。

**マリゴールド**: PuLP 4 では、一度モデルに入れた制約の右辺は書き換えられないんだ。試すとこうなる。

```python
prob.get_constraint_by_name("cap_work_min").changeRHS(14 * 60)
```

```text
NotImplementedError: Cannot change RHS of constraint already in model
```

**初花**: えっ、じゃあどうするの？

**マリゴールド**: **データを変えて、モデルを作り直す**。`build_model` を関数にしておいたのは、このためでもあるんだ。モデルを作り直すのは一瞬だから、遠慮しなくていいよ。

| やりたいこと | PuLP 4 でのやり方 |
|-------------|-----------------|
| 制約の上限を変える | データを変えて `build_model` し直す |
| 商品（変数）を追加する | `products` に追加して作り直す |
| 資源（制約）を追加する | `resources` に追加して作り直す |
| 制約を削除する | データから消して作り直す |
| 作った後で制約を足す | `prob += ...` で追加できる |
| 変数の上限を変える | `make["umeboshi"].upBound = 30` で変更できる |

⚠️ 元のデータを直接書き換えると、後で「元の条件」で解き直せなくなります。`copy.deepcopy` でコピーしてから変更します。

`ch05_change.py`:

```python
import copy
import pulp
from ch05_data_model import products, resources, build_model, report

# 元のデータを壊さないようにコピーしてから変更する
more_hours = copy.deepcopy(resources)
more_hours["work_min"]["capacity"] = 14 * 60   # 12時間 → 14時間

prob, make, used = build_model(products, more_hours)
stats = prob.solve(pulp.HiGHS(msg=False))
report(prob, stats, make, used, products, more_hours)
```

実行結果（`report` 関数はハンズオン 5-A で作ります）:

```text
状態: Optimal
利益: 22,250 円
  ジャム: 29
  シロップ: 8
  梅干し: 12
  梅(g): 17,900 / 18,000
  砂糖(g): 9,000 / 10,000
  作業(分): 840 / 840
  瓶(個): 37 / 50
```

**初花**: 2時間増やしたら、利益が20,750円から22,250円に増えた。ジャムが一気に増えてる。

**マリゴールド**: 時間が足りなくて作れなかったジャムに、増えた時間が回ったんだね。条件をまとめて変えて比べる方法は、第18章で扱うよ。

## ハンズオン 5-A — データとモデルを分けたプログラムを作る

5.4 のデータと `build_model` に、結果を表示する `report` 関数を加えて1つのファイルにします。

`ch05_data_model.py`:

```python
import pulp

# ---- データ（モデル表をそのまま辞書にする） ----
products = {
    "jam":      {"label": "ジャム", "profit": 450, "min": 10, "max": None},
    "syrup":    {"label": "シロップ", "profit": 400, "min": 0, "max": None},
    "umeboshi": {"label": "梅干し", "profit": 500, "min": 0, "max": 20},
}

resources = {
    "ume_g":    {"label": "梅(g)", "capacity": 18 * 1000,
                 "use": {"jam": 300, "syrup": 400, "umeboshi": 500}},
    "sugar_g":  {"label": "砂糖(g)", "capacity": 10 * 1000,
                 "use": {"jam": 200, "syrup": 400}},
    "work_min": {"label": "作業(分)", "capacity": 12 * 60,
                 "use": {"jam": 20, "syrup": 10, "umeboshi": 15}},
    "jars":     {"label": "瓶(個)", "capacity": 50,
                 "use": {"jam": 1, "syrup": 1}},
}


# ---- モデル（データが変わっても書き換えない） ----
def build_model(products, resources):
    prob = pulp.LpProblem("marche_data", pulp.LpMaximize)

    make = {
        p: prob.add_variable(f"make_{p}", lowBound=info["min"], upBound=info["max"], cat="Integer")
        for p, info in products.items()
    }

    prob += pulp.lpSum(products[p]["profit"] * make[p] for p in products), "total_profit"

    used = {}
    for r, info in resources.items():
        used[r] = pulp.lpSum(info["use"].get(p, 0) * make[p] for p in products)
        prob += used[r] <= info["capacity"], f"cap_{r}"

    return prob, make, used


def report(prob, stats, make, used, products, resources):
    print("状態:", stats.status_str)
    print(f"利益: {pulp.value(prob.objective):,.0f} 円")
    for p, info in products.items():
        print(f"  {info['label']}: {make[p].value():.0f}")
    for r, info in resources.items():
        print(f"  {info['label']}: {pulp.value(used[r]):,.0f} / {info['capacity']:,}")


if __name__ == "__main__":
    prob, make, used = build_model(products, resources)
    stats = prob.solve(pulp.HiGHS(msg=False))
    report(prob, stats, make, used, products, resources)
```

実行結果:

```text
状態: Optimal
利益: 20,750 円
  ジャム: 19
  シロップ: 13
  梅干し: 14
  梅(g): 17,900 / 18,000
  砂糖(g): 9,000 / 10,000
  作業(分): 720 / 720
  瓶(個): 32 / 50
```

第4章と同じ答えになれば、書き換えは成功です。

⚠️ 最後の `if __name__ == "__main__":` の部分は、このファイルを直接実行したときだけ動きます。ほかのファイルから `import` したときは動かないので、データや関数を再利用できます。

## ハンズオン 5-B — データを変更するだけで商品と資源を増やす

梅ゼリーを追加します。ゼリーはカップに入れて冷蔵ケースに並べるので、瓶は使いませんが、新しい資源「冷蔵棚」（24個分）を使います。

| | ゼリー（1個あたり） |
|---|------------------|
| 梅 | 200 g |
| 砂糖 | 100 g |
| 作業 | 10 分 |
| 冷蔵棚 | 1 個分（全体で24個分） |
| 利益 | 350 円 |

`ch05_add_jelly.py`:

```python
import pulp
from ch05_data_model import products, resources, build_model, report

# 商品を1つ追加：梅ゼリー
products["jelly"] = {"label": "ゼリー", "profit": 350, "min": 0, "max": None}

# 既存の資源に使用量を追加
resources["ume_g"]["use"]["jelly"] = 200
resources["sugar_g"]["use"]["jelly"] = 100
resources["work_min"]["use"]["jelly"] = 10

# 資源を1つ追加：冷蔵ケースの棚（ゼリーだけが使う）
resources["fridge"] = {"label": "冷蔵棚(個)", "capacity": 24, "use": {"jelly": 1}}

prob, make, used = build_model(products, resources)
stats = prob.solve(pulp.HiGHS(msg=False))
report(prob, stats, make, used, products, resources)
```

実行結果:

```text
状態: Optimal
利益: 23,100 円
  ジャム: 10
  シロップ: 13
  梅干し: 10
  ゼリー: 24
  梅(g): 18,000 / 18,000
  砂糖(g): 9,600 / 10,000
  作業(分): 720 / 720
  瓶(個): 23 / 50
  冷蔵棚(個): 24 / 24
```

**初花**: `build_model` には一文字も触ってないのに、ゼリーも冷蔵棚もちゃんと入った！ しかもゼリーが棚いっぱいの24個。

**マリゴールド**: ゼリーは梅も時間も少なくて済むのに、利益は350円ある。だから棚が許す限り作って、その分ジャムを予約分の10瓶まで減らしたんだね。

**初花**: ジャムが19瓶から10瓶に減っちゃった。ちょっと寂しい……。

**マリゴールド**: 「ジャムは看板商品だから15瓶は並べたい」と思うなら、それも制約としてデータに書けばいい。`products["jam"]["min"] = 15` の1行で済むよ。

## 初花のメモ帳

- 変数は商品名をキーにした辞書で持ち、式は `pulp.lpSum(... for p in products)` で書く
- データ（辞書）とモデル（`build_model` 関数）を分けると、データの変更だけで問題を広げられる
- PuLP 4 では制約の右辺を書き換えられないので、データをコピーして変え、モデルを作り直す

## マリゴールドの one more thing

**「疎な」データは辞書と相性がいい。**

資源の `use` には、使う商品だけを書きました。梅干しは砂糖も瓶も使わないので、そのキーはありません。このように、表のほとんどが0で一部だけに値がある状態を **疎（そ）** と呼びます。第10章の輸送問題や第11章の割り当て問題では、「倉庫 × 店舗」「人 × 仕事」のような組み合わせの表を扱いますが、実際に輸送できる経路や担当できる仕事は一部だけ、ということがよくあります。そのとき、存在する組み合わせだけを辞書のキーにして変数を作ると、モデルが小さくなり、速く解けるようになります。
