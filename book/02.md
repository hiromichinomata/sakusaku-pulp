## 2.1　Pythonと仮想環境の準備

**初花**: Pythonはパソコンに入ってると思う。バージョンって気にしたほうがいい？

**マリゴールド**: 気にしてほしい。PuLP 4 は **Python 3.12 以上** が必要なんだ。まずはターミナルで確かめよう。

```bash
python3 --version
```

```text
Python 3.13.3
```

`3.12` 以上なら大丈夫です。`3.11` 以下が表示されたら、[Python公式サイト](https://www.python.org/downloads/)から新しい版を入れてください。Windowsでは `python3` の代わりに `py` を使います。

**初花**: 3.12以上ね、OK。次は「仮想環境」？

**マリゴールド**: そう。仮想環境は、**本書専用のPythonの部屋** だと思って。ほかのプロジェクトのライブラリと混ざらないから、バージョン違いのトラブルを避けられるよ。

本書用のフォルダを作って、その中に仮想環境 `.venv` を作ります。

macOS / Linux:

```bash
mkdir sakusaku-pulp
cd sakusaku-pulp
python3 -m venv .venv
source .venv/bin/activate
```

Windows（PowerShell）:

```powershell
mkdir sakusaku-pulp
cd sakusaku-pulp
py -m venv .venv
.venv\Scripts\Activate.ps1
```

有効になると、プロンプトの先頭に `(.venv)` が付きます。

```text
(.venv) hatsuka@laptop sakusaku-pulp %
```

| 操作 | コマンド |
|------|---------|
| 仮想環境を作る | `python3 -m venv .venv` |
| 有効にする（mac / Linux） | `source .venv/bin/activate` |
| 有効にする（Windows） | `.venv\Scripts\Activate.ps1` |
| 抜ける | `deactivate` |

⚠️ ターミナルを開き直したら、毎回 `activate` し直します。`(.venv)` が付いていない状態で `pip install` すると、本書用の部屋の外に入ってしまいます。

## 2.2　PuLPとソルバーのインストール

**初花**: じゃあ `pip install pulp` だね。

**マリゴールド**: 試しに、それだけでどうなるか見てみよう。失敗の形を一度見ておくと、後で慌てないから。

```bash
pip install pulp
python -c "import pulp"
```

```text
ModuleNotFoundError: No module named 'numpy'
```

**初花**: えっ、import した瞬間に怒られた。numpyって何？

**マリゴールド**: 数値計算のライブラリで、ソルバーのHiGHSが使うものなんだ。PuLP 4 は、**ソルバーを「おまけ」として指定して一緒に入れる** 使い方が前提になっている。正しくはこう書くよ。

```bash
pip install "pulp[highs]"
```

```text
Successfully installed ... highspy-1.13.1 numpy-2.5.4 orloge-1.0.0 pulp-4.0.1 ...
```

`[highs]` の部分を **extra（追加オプション）** と呼びます。PuLP本体に加えて、HiGHSソルバー（`highspy`）と、それが必要とする `numpy` が一緒に入ります。

| 入れ方 | 入るもの | 本書では |
|--------|---------|---------|
| `pip install pulp` | PuLP本体だけ | ❌ import で失敗する |
| `pip install "pulp[highs]"` | PuLP ＋ HiGHS | ✅ **これを使う** |
| `pip install "pulp[cbc]"` | PuLP ＋ CBC | 第19章で比較に使う |

⚠️ `"pulp[highs]"` はダブルクォートで囲みます。macOS標準のシェル（zsh）では、囲まないと `[` `]` が特別な記号として扱われてエラーになります。

**初花**: HiGHSって、前の章の図でPuLPの下にいた「ソルバー」だよね。

**マリゴールド**: そう。オープンソースで速く、PuLPから直接呼び出せるから、本書の標準にしている。ほかのソルバーとの比べ方は第19章で扱うよ。

## 2.3　最適化プログラムを実行する

インストールできたら、最小のプログラムで動作を確かめます。

`hello_pulp.py`:

```python
import pulp

print("PuLP:", pulp.__version__)
print("使えるソルバー:", pulp.listSolvers(onlyAvailable=True))

prob = pulp.LpProblem("hello", pulp.LpMaximize)
x = prob.add_variable("x", lowBound=0, upBound=3)

prob += x, "objective"

stats = prob.solve(pulp.HiGHS(msg=False))
print("状態:", stats.status_str)
print("x =", x.value())
```

```bash
python hello_pulp.py
```

実行結果:

```text
PuLP: 4.0.1
使えるソルバー: ['HiGHS']
状態: Optimal
x = 3.0
```

**初花**: 「xを0から3の間で、できるだけ大きく」で、答えは3。当たり前だけど、動いた！

**マリゴールド**: 当たり前の答えが出ることを確かめるのが、最初の一歩としてちょうどいい。`listSolvers` に `HiGHS` が出ていれば、インストールは成功だよ。

`solve()` には、使うソルバーを毎回渡します。

**初花**: 渡さなかったら、勝手に選んでくれないの？

**マリゴールド**: やってみよう。`prob.solve(pulp.HiGHS(msg=False))` を `prob.solve()` に変えて実行すると、こうなる。

```text
pulp.constants.PulpError: No solver available
```

**初花**: HiGHSは入ってるのに「ソルバーがない」って言われた……。

**マリゴールド**: PuLP 4.0.1 では、引数なしの `solve()` はHiGHSを自動では選ばないんだ。本書では **ソルバーを必ず明示する** ことにしよう。どのソルバーで解いたかがコードに残るから、後で読み返したときにも迷わない。

| 書き方 | 結果 |
|--------|------|
| `prob.solve(pulp.HiGHS(msg=False))` | ✅ HiGHSで解く。ログを出さない |
| `prob.solve(pulp.HiGHS(msg=True))` | ✅ HiGHSで解く。ログを出す |
| `prob.solve()` | ❌ `No solver available`（PuLP 4.0.1 ＋ HiGHSのみの環境） |

## 2.5　サンプルコードと演習環境を整える

**初花**: これから章ごとにファイルが増えていくよね。どう置いておけばいい？

**マリゴールド**: 章ごとにフォルダを分けて、使うライブラリのバージョンを `requirements.txt` に書いておこう。半年後に同じ結果を再現したくなったとき、助けになるよ。

フォルダ構成の例:

```text
sakusaku-pulp/
├── .venv/              … 仮想環境（2.1 で作成）
├── requirements.txt    … 使うライブラリとバージョン
├── ch01/
│   ├── ch01_greedy.py
│   └── ch01_brute_force.py
├── ch02/
│   ├── hello_pulp.py
│   └── ch02_marche.py
├── ch03/
└── data/               … 第17章以降のCSVなど
```

`requirements.txt`:

```text
pulp[highs]==4.0.1
```

別のパソコンや新しい仮想環境では、次の1行で同じ環境を作れます。

```bash
pip install -r requirements.txt
```

第17章からは `pandas` などを追加します。そのときにこのファイルへ書き足していきます。

⚠️ 自分のファイルに **`pulp.py`** や **`inspect.py`** のような、ライブラリと同じ名前を付けないでください。Pythonは今いるフォルダのファイルを先に読み込むため、次のような分かりにくいエラーになります。

```text
AttributeError: module 'pulp' has no attribute 'LpProblem'
```

```text
AttributeError: partially initialized module 'pulp' ... (most likely due to a circular import)
```

**初花**: 2つ目、実は試しに `inspect.py` って名前で保存しちゃって出たやつだ。なんで？

**マリゴールド**: `inspect` はPython標準ライブラリの名前で、PuLPの読み込み途中で使われるんだ。自分のファイルが代わりに読まれて、PuLPが中途半端な状態になった。ファイル名は `ch02_` のように章番号で始めておくと、ぶつかりにくいよ。

## ハンズオン 2-B — 整数の指定を外してみる

変数を作る行の `cat="Integer"` を `cat="Continuous"`（小数OK）に変えて、もう一度実行します。

```python
x = {
    name: prob.add_variable(name, lowBound=0, upBound=info["max"], cat="Continuous")
    for name, info in items.items()
}
```

実行結果:

```text
状態: Optimal
利益: 6133.333333333334
cookie 1.6666666666666667
muffin 8.0
cake 5.0
```

**初花**: 出た、クッキー1.67個！ 第1章の表のとおりだ。

**マリゴールド**: `cat` を一語変えるだけで、整数計画問題が線形計画問題に変わる。どちらで解くべきかは、変数が表すものが「個数」か「量」かで決めよう。

| `cat` の値 | 変数が取る値 | 問題の種類 |
|-----------|-------------|-----------|
| `"Continuous"`（省略時） | 小数もOK | 線形計画問題（LP） |
| `"Integer"` | 整数だけ | 整数計画問題（IP） |
| `"Binary"` | 0か1だけ | 整数計画問題（第12章から） |

**初花**: ねえ、省略したら `Continuous` なんだよね。屋台で `cat=` を書き忘れたら……

**マリゴールド**: 小数の答えが、エラーも出さずに返ってくる。だから結果を見たら、**個数が整数になっているか** を自分の目でも確かめる癖をつけよう。第6章で、その確認をコードにするよ。

## マリゴールドの one more thing

**`stats` を保存しておくと、実行の記録になる。**

`solve()` の戻り値 `stats` には、状態・目的関数値・計算時間・変数の数などがまとまっています。`stats.toJson("result.json")` とすると、これをJSONファイルに書き出せます。条件を変えて何度も解くようになると、「いつ、どの条件で、どれくらい時間がかかったか」を後から比べたくなります。第18章のシナリオ比較と第20章の実行ログで、この記録を活用します。
