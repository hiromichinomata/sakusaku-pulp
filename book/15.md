# 第15章　勤務シフトを作成する

**初花**: うめ食品の梅田店の店長さん、毎週シフト表を作るのに半日かかるんだって。アルバイトさんの都合を聞いて、人数を数えて、連勤になってないか確かめて……。

**マリゴールド**: シフト作成は、最適化が一番喜ばれる仕事の一つだよ。変数は「人 × 日 × 時間帯」のバイナリ変数。第11章の割り当てに、**時間の軸** が加わった形だね。

**初花**: 第8章の one more thing で言ってた、「時間の軸を加えて変数を広げる」ってやつだ。

**マリゴールド**: そう。時間の軸が入ると、「遅番の次の日に早番は入れない」「4日連続では働かない」のような、**日をまたぐ制約** が書けるようになる。それがこの章の山場だよ。

---

## 15.1　日付・時間帯・スタッフを表現する

梅田店の1週間のシフトの条件です（本書用の架空のデータです）。

| 時間帯 | 時間 | 平日の必要人数 | 土日の必要人数 |
|--------|------|-------------:|-------------:|
| 早番 | 9〜14時（5時間） | 1人 | 2人 |
| 遅番 | 14〜19時（5時間） | 2人 | 3人 |

| スタッフ | 時給 | 週の勤務回数 | 勤務できない日・時間帯 |
|---------|-----:|-----------:|------------------|
| 青木 | 1,300円 | 2〜5回 | 日曜 |
| 井上 | 1,250円 | 2〜5回 | 水曜 |
| 上田 | 1,100円 | 2〜5回 | 平日の早番（学校） |
| 遠藤 | 1,100円 | 2〜5回 | 土日の遅番 |
| 小野 | 1,000円 | 2〜5回 | 木曜 |
| 加藤 | 1,000円 | 2〜5回 | 月・火の遅番 |

**マリゴールド**: 変数は「スタッフ × 曜日 × 時間帯」。勤務できない枠は、第11章と同じく変数を作らないよ。

```python
keys = [(p, d, s) for p in staff for d in days for s in shifts if (p, d, s) not in unavailable]
x = {k: prob.add_variable("x_{}_{}_{}".format(*k), cat="Binary") for k in keys}
```

**初花**: キーが3つ組のタプルになった。でも、勤務できない枠の変数がないと、後で `x[p, d, s]` を足すときに `KeyError` にならない？

**マリゴールド**: いいところに気づいたね。そこで、変数がない枠は0として扱う小さな関数を用意しておく。

```python
def X(p, d, s):
    return x.get((p, d, s), 0)   # 勤務できない枠は 0 として扱う
```

| 書き方 | 変数があるとき | 変数がないとき |
|--------|-------------|-------------|
| `x[p, d, s]` | 変数 | `KeyError` |
| `X(p, d, s)` | 変数 | `0` |

`X` を使えば、日をまたぐ制約を書くときに、勤務できない枠を気にせずに済みます。

## 15.2　必要人数を確保する

**マリゴールド**: 必要人数は、曜日 × 時間帯ごとに「入っている人の合計 ≧ 必要人数」と書く。

```python
for (d, s), n in need.items():
    prob += pulp.lpSum(X(p, d, s) for p in staff) >= n, f"need_{d}_{s}"
```

**初花**: 第11章では「各作業にちょうど1人」で `== 1` だったけど、今回は `>=` なんだね。

**マリゴールド**: 人件費を最小にするから、必要以上には入れないはずだけど、「多い分には困らない」という意味で `>=` にしておく。目的関数は人件費の合計だよ。

```python
cost = pulp.lpSum(staff[p]["wage"] * HOURS * x[p, d, s] for (p, d, s) in keys)
```

## 15.3　勤務可能日と勤務回数の制約

**マリゴールド**: スタッフごとの制約は二つ。**週の勤務回数** と、**1日に1回まで** だ。

```python
for p, info in staff.items():
    prob += count[p] >= info["min"], f"min_{p}"
    prob += count[p] <= info["max"], f"max_{p}"
    for d in days:
        prob += pulp.lpSum(X(p, d, s) for s in shifts) <= 1, f"one_per_day_{p}_{d}"
```

`count[p]` は、そのスタッフの1週間の勤務回数を表す式です。

```python
count = {p: pulp.lpSum(X(p, d, s) for d in days for s in shifts) for p in staff}
```

ここまでの条件で解いた結果です（ハンズオン 15-A のステップ1）。表の「早」「遅」は勤務、「・」は休み、「×」は終日勤務できない日です。

```text
  |      | 月 | 火 | 水 | 木 | 金 | 土 | 日 | 回数 |
```

**初花**: 必要人数は満たしてるけど……青木さんは金曜の遅番の次の日が早番、加藤さんも土曜の遅番の次の日が早番。遠藤さんは月曜から木曜まで4連勤。加藤さんなんて、水曜から日曜まで5連勤だよ。

**マリゴールド**: 時給の安い人に勤務を寄せた結果だね。「遅→早 2件」は、遅番の次の日に早番が入っている件数、「最長連勤 5日」は一番長い連続勤務だよ。どちらも、まだ制約として書いていないから、ソルバーは気にしていない。

## 15.4　連続勤務や休息時間を扱う

**マリゴールド**: まずは休息時間。遅番は19時に終わって、早番は9時に始まる。その間が14時間しかないから、「遅番の次の日に早番は入れない」という制約を足そう。

```python
for p in staff:
    for d1, d2 in zip(days, days[1:]):
        prob += X(p, d1, "late") + X(p, d2, "early") <= 1, f"rest_{p}_{d1}"
```

**初花**: `zip(days, days[1:])` で、月と火、火と水……って、隣り合う日の組を作ってるんだね。

**マリゴールド**: そう。そして「遅番」と「次の日の早番」の合計が1以下だから、どちらか一方しか入れない。第13章の one more thing の「AとBは同時にはやらない」と同じ形だよ。

```text
■ 2: ＋遅番の翌日は早番にしない: Optimal
  人件費 136,750 円 / 希望 -1 / 遅→早 0 件 / 最長連勤 4 日 / 回数の差 3
```

**初花**: 遅→早が0件になって、人件費は変わってない。

**マリゴールド**: 次は連続勤務。「4日連続では働かない」は、**どの連続する4日間を見ても、勤務は3日以下** と言い換えられる。月〜木、火〜金、水〜土、木〜日の4つの「窓」について、それぞれ制約を書くんだ。

```python
for p in staff:
    for i in range(len(days) - MAX_STREAK):
        window = days[i:i + MAX_STREAK + 1]
        prob += pulp.lpSum(X(p, d, s) for d in window for s in shifts) <= MAX_STREAK, \
            f"streak_{p}_{window[0]}"
```

```text
月 火 水 木 金 土 日
[月 火 水 木]          … 4日のうち勤務は3日以下
   [火 水 木 金]       … 4日のうち勤務は3日以下
      [水 木 金 土]    … 4日のうち勤務は3日以下
         [木 金 土 日] … 4日のうち勤務は3日以下
```

**初花**: 窓をずらしながら、全部の4日間を見張るんだ。賢い。

**マリゴールド**: この **スライディングウィンドウ**（ずらす窓）の書き方は、「1か月に土日は2回まで」「7日間で40時間まで」など、期間の制約によく使うよ。

```text
■ 3: ＋4連勤しない: Optimal
  人件費 136,750 円 / 希望 +0 / 遅→早 0 件 / 最長連勤 3 日 / 回数の差 3
  |      | 月 | 火 | 水 | 木 | 金 | 土 | 日 | 回数 |
  | 青木 | ・ | ・ | ・ | 遅 | 遅 | ・ | × |  2  |
  | 井上 | ・ | ・ | × | ・ | 早 | 遅 | 遅 |  3  |
  | 上田 | 遅 | 遅 | ・ | ・ | 遅 | 遅 | 遅 |  5  |
  | 遠藤 | 早 | ・ | 遅 | 遅 | ・ | 早 | 早 |  5  |
  | 小野 | 遅 | 遅 | 遅 | × | ・ | 早 | 早 |  5  |
  | 加藤 | ・ | 早 | 早 | 早 | ・ | 遅 | 遅 |  5  |
```

**初花**: 最長連勤が3日になった。しかも人件費はまだ136,750円のまま！

**マリゴールド**: 休息も連勤も、人件費を上げずに守れる組み合わせがあったんだね。最初の答えは、たまたま悪い組み合わせを選んでいただけ。**守ってほしいことは、書かなければ守られない** けど、書いても損をしないことも多いんだ。

## 15.5　希望シフトと公平性を考慮する

**初花**: アルバイトさんの希望も聞いてあげたい。「この日は入りたい」「できればこの日は避けたい」って。

**マリゴールド**: 希望は「必ず守る」制約ではなく、**守れたら嬉しい** ものだね。第10章の欠品の罰金と同じように、目的関数に入れよう。希望1件を1,000円分の価値とみなして、人件費から引くんだ。

| スタッフ | 希望 |
|---------|------|
| 青木 | 土曜の早番に入りたい、金曜の遅番に入りたい |
| 井上 | 月曜の早番に入りたい |
| 小野 | 日曜の早番・土曜の遅番はできれば避けたい |
| 加藤 | 土日の早番・金曜の遅番はできれば避けたい |

```python
# 入りたい（+1）・できれば避けたい（-1）
wish_score = pulp.lpSum(w * X(p, d, s) for (p, d, s), w in wish.items())
objective = objective - WISH_YEN * wish_score
```

```text
■ 4: ＋希望を考える: Optimal
  人件費 136,750 円 / 希望 +2 / 遅→早 0 件 / 最長連勤 3 日 / 回数の差 3
```

**初花**: 希望の点数が+2になった。人件費は同じまま。

**マリゴールド**: 同じ人件費の組み合わせの中から、希望に合うものを選んだんだね。第6章の「最適解が複数あるとき」の話を思い出して。

⚠️ 目的関数を少しずつ組み立てるときは、`objective = objective - ...` のように書きます。`objective -= ...` と書くと、PuLPの式は **その場で書き換わる** ため、`objective = cost` としておいた元の `cost` の式まで変わってしまいます。

```python
cost = 2 * x + 3 * y
obj = cost
obj -= 5 * y
print(cost)   # 2*x - 2*y   ← cost まで変わってしまう
```

**初花**: 気になるのは「回数の差 3」。上田さん・遠藤さん・小野さん・加藤さんは5回なのに、青木さんは2回。時給が高いから減らされてるんだよね。

**マリゴールド**: 人件費だけを見れば合理的だけど、青木さんはもっと働きたいかもしれないし、5回の人は大変だ。第11章で学んだ補助変数を使って、**一番多い人と一番少ない人の差** を小さくしよう。

```python
most = prob.add_variable("most", lowBound=0)     # いちばん多い人の勤務回数
least = prob.add_variable("least", lowBound=0)   # いちばん少ない人の勤務回数
for p in staff:
    prob += count[p] <= most, f"most_{p}"
    prob += count[p] >= least, f"least_{p}"
objective = objective + FAIR_YEN * (most - least)
```

**初花**: `most` は全員の天井、`least` は全員の床。天井と床の差を、1回3,000円の罰金として目的関数に足すんだ。

```text
■ 5: ＋勤務回数を公平に: Optimal
  人件費 140,000 円 / 希望 +2 / 遅→早 0 件 / 最長連勤 3 日 / 回数の差 1
  |      | 月 | 火 | 水 | 木 | 金 | 土 | 日 | 回数 |
  | 青木 | ・ | 遅 | ・ | 遅 | 遅 | 遅 | × |  4  |
  | 井上 | 早 | ・ | × | 遅 | ・ | 早 | 早 |  4  |
  | 上田 | ・ | ・ | 遅 | ・ | 遅 | 遅 | 遅 |  4  |
  | 遠藤 | 遅 | 遅 | ・ | ・ | 早 | ・ | 早 |  4  |
  | 小野 | 遅 | ・ | 遅 | × | ・ | 早 | 遅 |  4  |
  | 加藤 | ・ | 早 | 早 | 早 | ・ | 遅 | 遅 |  5  |
```

**初花**: ほとんどの人が4回で、加藤さんだけ5回。差が1になった！ 人件費は3,250円増えたけど。

**マリゴールド**: 必要な枠は全部で25だから、6人で分けると4回の人と5回の人が出るのは避けられない。差1が一番公平な形だよ。3,250円が、公平さのための費用だね。

| ステップ | 人件費 | 希望 | 遅→早 | 最長連勤 | 回数の差 |
|---------|------:|----:|-----:|-------:|-------:|
| 1: 基本 | 136,750 円 | −1 | 2件 | 5日 | 3 |
| 2: ＋休息 | 136,750 円 | −1 | 0件 | 4日 | 3 |
| 3: ＋連勤 | 136,750 円 | 0 | 0件 | 3日 | 3 |
| 4: ＋希望 | 136,750 円 | ＋2 | 0件 | 3日 | 3 |
| 5: ＋公平 | 140,000 円 | ＋2 | 0件 | 3日 | 1 |

| 条件の種類 | 扱い方 | 例 |
|-----------|-------|----|
| 絶対に守る | 制約 | 必要人数、勤務できない日、休息、連勤 |
| できれば守る | 目的関数に罰金・ご褒美 | 希望、公平さ |

**初花**: 罰金の金額を変えたら、答えも変わるよね。希望を1件5,000円にしたら、もっと希望が通るかも。

**マリゴールド**: そう。罰金の重みは、**何をどれだけ大事にするか** という方針そのものなんだ。店長さんと相談して決める値だよ。

## ハンズオン 15-A — 必要人員を満たしながら、希望や勤務コストを考慮してシフトを作成する

15.1〜15.5 を1つのプログラムにまとめます。`check` 関数は、できあがったシフトの「遅番→翌日早番」の数と最長の連勤日数を、モデルとは別に数え直します（第6章の検証の考え方です）。

`ch15_shift.py`:

```python
import pulp

# うめ食品 梅田店の1週間のシフト（本書用の架空のデータ）
days = ["mon", "tue", "wed", "thu", "fri", "sat", "sun"]
day_label = {"mon": "月", "tue": "火", "wed": "水", "thu": "木", "fri": "金", "sat": "土", "sun": "日"}
shifts = {"early": "早番", "late": "遅番"}   # 早番 9〜14時、遅番 14〜19時（各5時間）

# 必要人数：平日は早番1人・遅番2人、土日は早番2人・遅番3人
need = {}
for d in days:
    weekend = d in ("sat", "sun")
    need[d, "early"] = 2 if weekend else 1
    need[d, "late"] = 3 if weekend else 2

staff = {
    "aoki":  {"label": "青木", "wage": 1300, "min": 2, "max": 5},
    "inoue": {"label": "井上", "wage": 1250, "min": 2, "max": 5},
    "ueda":  {"label": "上田", "wage": 1100, "min": 2, "max": 5},
    "endo":  {"label": "遠藤", "wage": 1100, "min": 2, "max": 5},
    "ono":   {"label": "小野", "wage": 1000, "min": 2, "max": 5},
    "kato":  {"label": "加藤", "wage": 1000, "min": 2, "max": 5},
}

# 勤務できない日・シフト（学校・ほかの仕事など）
unavailable = {
    ("aoki", "sun", "early"), ("aoki", "sun", "late"),
    ("inoue", "wed", "early"), ("inoue", "wed", "late"),
    ("ueda", "mon", "early"), ("ueda", "tue", "early"), ("ueda", "wed", "early"),
    ("ueda", "thu", "early"), ("ueda", "fri", "early"),
    ("endo", "sat", "late"), ("endo", "sun", "late"),
    ("ono", "thu", "early"), ("ono", "thu", "late"),
    ("kato", "mon", "late"), ("kato", "tue", "late"),
}

# 入りたい（+1）・できれば避けたい（-1）という希望
wish = {
    ("aoki", "sat", "early"): 1, ("aoki", "fri", "late"): 1, ("inoue", "mon", "early"): 1,
    ("ono", "sun", "early"): -1, ("ono", "sat", "late"): -1,
    ("kato", "sat", "early"): -1, ("kato", "sun", "early"): -1, ("kato", "fri", "late"): -1,
}

HOURS = 5
MAX_STREAK = 3        # 4日連続では働かない
WISH_YEN = 1000       # 希望1件を、いくら分の価値とみなすか
FAIR_YEN = 3000       # 勤務回数の差1回を、いくら分の不公平とみなすか


def solve_shift(rules):
    prob = pulp.LpProblem("shift", pulp.LpMinimize)

    keys = [(p, d, s) for p in staff for d in days for s in shifts if (p, d, s) not in unavailable]
    x = {k: prob.add_variable("x_{}_{}_{}".format(*k), cat="Binary") for k in keys}

    def X(p, d, s):
        return x.get((p, d, s), 0)   # 勤務できない枠は 0 として扱う

    count = {p: pulp.lpSum(X(p, d, s) for d in days for s in shifts) for p in staff}
    cost = pulp.lpSum(staff[p]["wage"] * HOURS * x[p, d, s] for (p, d, s) in keys)
    wish_score = pulp.lpSum(w * X(p, d, s) for (p, d, s), w in wish.items())

    objective = cost
    if "wish" in rules:
        objective = objective - WISH_YEN * wish_score
    if "fair" in rules:
        most = prob.add_variable("most", lowBound=0)     # いちばん多い人の勤務回数
        least = prob.add_variable("least", lowBound=0)   # いちばん少ない人の勤務回数
        for p in staff:
            prob += count[p] <= most, f"most_{p}"
            prob += count[p] >= least, f"least_{p}"
        objective = objective + FAIR_YEN * (most - least)
    prob += objective, "objective"

    # 必要人数を満たす
    for (d, s), n in need.items():
        prob += pulp.lpSum(X(p, d, s) for p in staff) >= n, f"need_{d}_{s}"

    for p, info in staff.items():
        prob += count[p] >= info["min"], f"min_{p}"
        prob += count[p] <= info["max"], f"max_{p}"
        for d in days:
            prob += pulp.lpSum(X(p, d, s) for s in shifts) <= 1, f"one_per_day_{p}_{d}"

    if "rest" in rules:
        # 遅番の次の日に早番は入れない（休息時間を確保する）
        for p in staff:
            for d1, d2 in zip(days, days[1:]):
                prob += X(p, d1, "late") + X(p, d2, "early") <= 1, f"rest_{p}_{d1}"

    if "streak" in rules:
        # どの連続する MAX_STREAK+1 日を見ても、勤務は MAX_STREAK 日以下
        for p in staff:
            for i in range(len(days) - MAX_STREAK):
                window = days[i:i + MAX_STREAK + 1]
                prob += pulp.lpSum(X(p, d, s) for d in window for s in shifts) <= MAX_STREAK, \
                    f"streak_{p}_{window[0]}"

    stats = prob.solve(pulp.HiGHS(msg=False))
    if stats.status_str != "Optimal":
        return {"status": stats.status_str}
    return {
        "status": stats.status_str,
        "cost": pulp.value(cost),
        "wish": pulp.value(wish_score),
        "sol": {k for k, v in x.items() if v.value() > 0.5},
    }


def check(sol):
    """できあがったシフトの「遅番→翌日早番」の数と、最長の連勤日数を数える"""
    late_early = sum(
        1 for p in staff for d1, d2 in zip(days, days[1:])
        if (p, d1, "late") in sol and (p, d2, "early") in sol
    )
    longest = 0
    for p in staff:
        run = 0
        for d in days:
            run = run + 1 if any((p, d, s) in sol for s in shifts) else 0
            longest = max(longest, run)
    return late_early, longest


def show(title, r):
    print(f"■ {title}: {r['status']}")
    if r["status"] != "Optimal":
        return
    late_early, longest = check(r["sol"])
    counts = [sum(1 for (q, d, s) in r["sol"] if q == p) for p in staff]
    print(f"  人件費 {r['cost']:,.0f} 円 / 希望 {r['wish']:+.0f} / 遅→早 {late_early} 件 / "
          f"最長連勤 {longest} 日 / 回数の差 {max(counts) - min(counts)}")
    print("  |      | " + " | ".join(day_label[d] for d in days) + " | 回数 |")
    for p, n in zip(staff, counts):
        cells = []
        for d in days:
            if (p, d, "early") in r["sol"]:
                cells.append("早")
            elif (p, d, "late") in r["sol"]:
                cells.append("遅")
            elif (p, d, "early") in unavailable and (p, d, "late") in unavailable:
                cells.append("×")
            else:
                cells.append("・")
        print(f"  | {staff[p]['label']} | " + " | ".join(cells) + f" |  {n}  |")


if __name__ == "__main__":
    rules = []
    for title, rule in [
        ("1: 必要人数・勤務できない日・回数", None),
        ("2: ＋遅番の翌日は早番にしない", "rest"),
        ("3: ＋4連勤しない", "streak"),
        ("4: ＋希望を考える", "wish"),
        ("5: ＋勤務回数を公平に", "fair"),

        if rule:
            rules.append(rule)
```

## 初花のメモ帳

- シフトは「人 × 日 × 時間帯」のバイナリ変数。勤務できない枠は変数を作らず、`x.get(キー, 0)` で0として扱う
- 日をまたぐ制約は、隣の日の組（`zip(days, days[1:])`）や、ずらす窓（スライディングウィンドウ）で書く
- 絶対に守るものは制約、できれば守るもの（希望・公平さ）は目的関数の罰金で表す。罰金の重みは方針そのもの

## マリゴールドの one more thing

**必要人数が満たせない週は、第10章の「欠品」の考え方で。**

アルバイトさんの都合が重なって、どうやっても必要人数を満たせない週もあります。そのままでは `Infeasible` になってしまうので、第10章の欠品と同じように「不足人数」の変数を作り、`入っている人数 ＋ 不足 ≧ 必要人数` とし、不足に大きな罰金を付けます。解くと、どの曜日のどの時間帯が何人足りないかが分かり、店長さんが「この枠だけ社員が入る」「この枠だけ募集する」と判断する材料になります。解けないときに「解けません」で終わらせず、**どこがどれだけ足りないか** を示すのも、最適化の大切な役割です。
