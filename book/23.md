## 23.1　最適化したい目的を明確にする

**初花**: まず、状況をメモに書いてみた（数値は本書用の架空の設定です）。

> - 収穫シーズンは10日間。前半は青梅、後半は完熟梅が採れる
> - 青梅は梅シロップに、完熟梅は梅干しと梅ジャムにする
> - 採った梅は、その日か次の日に加工しないと傷んでしまう。次の日に加工すると、少し品質が落ちる
> - 加工に使える時間は、平日は4時間、週末は家族総出で10時間
> - 梅シロップは150kg、梅干しは120kg、梅ジャムは100kg分までしか売り先がない

**マリゴールド**: 次は目的だね。何をよくしたい？

**初花**: 「捨てる梅を減らしたい」……かな。

**マリゴールド**: それも一つの答えだね。でも、捨てる梅を減らすだけなら、一番手間のかからない梅シロップばかり作ればいい。それで初花は満足？

**初花**: うーん、それは違う。梅干しはおばあちゃんの得意料理だし、売ったときの値段も高い。……そうか、本当によくしたいのは **加工した梅の価値の合計** なんだ。捨てる梅が減るのは、その結果。

**マリゴールド**: いいところに気づいたね。目的を決めるときは、「本当は何を大事にしているか」を自分に問うことが大切なんだ。目的を変えると、答えも変わるからね。

| 目的の候補 | 起きそうなこと |
|----------|-----------|
| 捨てる梅の量を最小にする | 手間の少ない商品ばかり作る |
| 加工した梅の価値を最大にする | 価値と手間の釣り合いで選ぶ（✅ 採用） |
| 作業時間を最小にする | 何も作らないのが一番になる |

**初花**: 価値は、1kgあたり梅シロップ800円、梅干し1,200円、梅ジャム1,000円にする。次の日に加工したら1割引き。

**マリゴールド**: 「次の日なら1割引き」は、傷みかけた梅で作ると品質が落ちることを、価値の差で表したんだね。第10章の欠品の罰金や、第15章の希望と同じ考え方だよ。

## 23.2　意思決定変数と制約条件を設計する

**初花**: 決めたいのは「どの日に採った梅を、どの日に、何に加工するか」。だから変数は「収穫日 × 加工日 × 商品」の3つ組。単位はkgだから、連続変数でいいよね。

**マリゴールド**: いい設計だね。全部の組み合わせを作る？

**初花**: ううん、加工日は「収穫日か、その次の日」だけ。それに、青梅は梅シロップ、完熟梅は梅干しと梅ジャムにしかならない。ありえない組み合わせは、変数を作らない。第16章の one more thing だね。

```python
def plans(d):
    """(収穫日 h, 加工日 t, 商品 p) の組み合わせと、その価値の倍率"""
    keys = {}
    for p, info in d["products"].items():
        for h in DAYS:
            if d["harvest"][info["kind"]][h] == 0:
                continue
            for t in WORK_DAYS:
                if t == h:
                    keys[h, t, p] = 1.0                 # その日のうちに加工
                elif t == h + 1:
                    keys[h, t, p] = NEXT_DAY            # 次の日に加工
                elif d["freezer_kg"] > 0 and info["freezable"] and h + 2 <= t <= h + FREEZE_DAYS:
                    keys[h, t, p] = FROZEN              # 冷凍して、あとで加工
    return keys
```

**マリゴールド**: 最後の `elif` は？

**初花**: えへへ、先に書いちゃった。あとで「冷凍庫があったら」を試したくなると思って、冷凍した梅を数日後に加工する組み合わせも作れるようにしておいたの。冷凍庫がないとき（`freezer_kg` が0のとき）は、この組み合わせは作られない。

**マリゴールド**: 変数を作る関数に、組み合わせのルールを全部まとめたんだね。モデルの本体がすっきりするし、ルールを変えたいときはここだけ直せばいい。

| 部品 | この問題では | 学んだ章 |
|------|-----------|--------|
| 変数 `x[h, t, p]` | 収穫日 h の梅を、加工日 t に、商品 p にする量（kg） | 第10・18章 |
| 目的関数 | Σ 価値 × 倍率 × x（倍率は当日1.0、翌日0.9、冷凍0.95） | 第10・15章 |
| 制約 | 収穫日ごと・梅の種類ごとに、加工する量 ≦ 収穫量 | 第10章 |
| 制約 | 加工日ごとに、作業時間 ≦ 使える時間 | 第9章 |
| 制約 | 商品ごとに、加工する量 ≦ 売り先の量 | 第9章 |
| 制約 | 冷凍庫に入っている量 ≦ 冷凍庫の容量 | 第18章 |
| 組み合わせのルール | ありえない組み合わせは変数を作らない | 第16章 |

**初花**: 捨てる梅は、変数にしなくていいの？

**マリゴールド**: 「収穫量 − 加工した量」で計算できるから、変数にしなくていいよ。第4章で「利益は変数から計算される値だから、変数にしない」と話したのと同じだね。

**マリゴールド**: 3つ目のテストが特にいいね。「選択肢を増やしたら、最大化の答えは悪くならない」という性質を確かめている。第8章で「制約を足すと、最小化の目的関数は同じか悪くなる」と話したことの裏返しだよ。

| 極端な条件のテスト | 確かめる性質 |
|----------------|-----------|
| 資源を無限にする | 制約が効かなければ、無駄は出ない |
| 資源を0にする | 何もできなければ、目的関数は0 |
| 選択肢を増やす | 最大化の答えは同じか良くなる |
| 制約を足す | 最大化の答えは同じか悪くなる |

**初花**: 全探索ができなくても、こういう「当たり前のこと」が成り立つかで、モデルの書き間違いに気づけるんだね。

⚠️ テストが通っても、モデルが正しいとは限りません。テストは「明らかな間違い」を見つける網です。網の目を細かくするほど、見逃しは減ります。

## 23.5　改善点とモデルの限界を説明する

**初花**: 完熟梅が追いつかないなら、冷凍しておいて、シーズンが終わってからゆっくりジャムにすればいいんじゃないかな。11日目から15日目は、平日の4時間を加工に使えるし。

**マリゴールド**: 23.2 で用意しておいた冷凍の組み合わせが、ここで役に立つね。30kg入る冷凍庫を買った場合で解いてみよう。

```text

  価値 353,700 円 / 捨てる梅 51.0 / 415 kg / 冷凍 30.0 kg
  梅シロップ 150.0kg / 梅干し 120.0kg / 梅ジャム 94.0kg
  捨てる梅の内訳: 3日目青梅 5.0, 4日目青梅 25.0, 5日目青梅 5.0, 5日目完熟梅 13.0, 8日目完熟梅 3.0
  作業時間: 3.0/4 4.0/4 4.0/4 4.0/4 4.0/4 10.0/10 10.0/10 4.0/4 4.0/4 4.0/4 4.0/4 4.0/4 2.8/4 0.8/4 0.0/4
```

**初花**: 捨てる梅が81kgから51kgに減って、価値は28,500円増えた！ 8日目と9日目の完熟梅を冷凍して、シーズンのあとの12〜14日目にジャムにしてる。

**マリゴールド**: 冷凍庫が数万円なら、1シーズンで元が取れるかもしれないね。青梅の売り先も増やした場合も見てみよう。

```text

  価値 367,500 円 / 捨てる梅 30.0 / 415 kg / 冷凍 35.0 kg
  梅シロップ 185.0kg / 梅干し 120.0kg / 梅ジャム 80.0kg
  捨てる梅の内訳: 4日目完熟梅 10.0, 5日目完熟梅 17.0, 8日目完熟梅 3.0
```

**初花**: 梅シロップを200kgまで売れるようにしたら、青梅は全部使い切れた。捨てる梅は30kg。最初の81kgから、半分以下になった！

**マリゴールド**: 「冷凍 35.0kg」は、シーズン全体で冷凍した量の合計だよ。冷凍庫に同時に入っているのは、いつも30kg以下になっている。

| 案 | 価値 | 捨てる梅 | 必要なこと |
|----|-----:|-------:|----------|
| 1: 基本 | 325,200 円 | 81 kg | — |
| 2: 試合の日 | 301,200 円 | 105 kg | （何もしないとこうなる） |
| 3: 冷凍庫 | 353,700 円 | 51 kg | 冷凍庫を買う |
| 4: 冷凍庫＋売り先 | 367,500 円 | 30 kg | 冷凍庫を買い、シロップの売り先を探す |

**初花**: おばあちゃんに見せたら喜ぶと思う。……でも、このモデル、どこまで信じていいんだろう。

**マリゴールド**: 大事な問いだね。最後に、**このモデルの限界** を言葉にしておこう。自分のモデルの限界を説明できることは、モデルを作れることと同じくらい大切なんだ。

**初花**: 考えてみる。

- 収穫量は「見込み」で、天気によって変わる。雨が続けば収穫は遅れるし、台風が来れば一気に落ちる
- 作業時間は、疲れや段取りを考えていない。10時間ぶっ通しで同じペースで作業できるとは限らない
- 「次の日なら1割引き」「冷凍なら5%引き」は、わたしが決めた値。本当の品質の差とは違うかもしれない
- 売り先の上限も見込み。実際に売れるかは分からない
- 冷凍庫は、梅を入れたり出したりする手間を考えていない

**マリゴールド**: 素晴らしい。どれも、モデルを改良するときの出発点になるよ。

| 限界 | 改良の方向 |
|------|---------|
| 収穫量が不確か | 晴れ・雨など複数のシナリオで解いて比べる（第18章） |
| 作業のペースが一定ではない | 1日の作業時間に余裕を残す（第6章） |
| 品質の差の値が仮のもの | 値を変えて、答えがどれだけ変わるか確かめる（第21章） |
| 売れる量が不確か | 売れ残ったときの損も目的関数に入れる |
| 冷凍の手間 | 冷凍・解凍の作業時間を制約に足す |

**初花**: 限界が分かってると、答えを「絶対」じゃなくて「判断の材料」として使えるね。

**マリゴールド**: その通り。最適化は未来を予言する道具じゃない。**限られた条件の中で、筋の通った選択肢を示す道具** なんだ。

## ハンズオン 23-A — 梅の収穫と加工の計画を作る（解答例）

23.1〜23.5 の解答例です。

`ch23_harvest.py`:

```python
import copy
import pulp

# 梅の収穫シーズン10日間と、そのあと5日間の加工計画（本書用の架空のデータ）
DAYS = list(range(1, 11))        # 収穫する日
WORK_DAYS = list(range(1, 16))   # 加工できる日（11〜15日目はシーズンのあと）

base = {
    # 収穫の見込み（kg）。前半は青梅、後半は完熟梅
    "harvest": {
        "green": {1: 30, 2: 40, 3: 45, 4: 40, 5: 20, 6: 10, 7: 0, 8: 0, 9: 0, 10: 0},
        "ripe":  {1: 0, 2: 0, 3: 0, 4: 10, 5: 25, 6: 40, 7: 50, 8: 50, 9: 35, 10: 20},
    },
    # 家族が加工に使える時間（時間）。6・7日目は週末、11〜15日目はシーズンのあと
    "hours": {1: 4, 2: 4, 3: 4, 4: 4, 5: 4, 6: 10, 7: 10, 8: 4, 9: 4, 10: 4,
              11: 4, 12: 4, 13: 4, 14: 4, 15: 4},
    "products": {
        "syrup":    {"label": "梅シロップ", "kind": "green", "value": 800,  "h_per_kg": 0.10, "max_kg": 150, "freezable": True},
        "umeboshi": {"label": "梅干し",     "kind": "ripe",  "value": 1200, "h_per_kg": 0.20, "max_kg": 120, "freezable": False},
        "jam":      {"label": "梅ジャム",   "kind": "ripe",  "value": 1000, "h_per_kg": 0.25, "max_kg": 100, "freezable": True},
    },
    "freezer_kg": 0,   # 冷凍庫に入る梅の量（kg）。0 なら冷凍庫なし
}
NEXT_DAY = 0.9     # 次の日に加工すると、価値が1割下がる
FROZEN = 0.95      # 冷凍してから加工すると、価値が5%下がる
FREEZE_DAYS = 5    # 冷凍した梅は、5日後までに加工する


def plans(d):
    """(収穫日 h, 加工日 t, 商品 p) の組み合わせと、その価値の倍率"""
    keys = {}
    for p, info in d["products"].items():
        for h in DAYS:
            if d["harvest"][info["kind"]][h] == 0:
                continue
            for t in WORK_DAYS:
                if t == h:
                    keys[h, t, p] = 1.0                 # その日のうちに加工
                elif t == h + 1:
                    keys[h, t, p] = NEXT_DAY            # 次の日に加工
                elif d["freezer_kg"] > 0 and info["freezable"] and h + 2 <= t <= h + FREEZE_DAYS:
                    keys[h, t, p] = FROZEN              # 冷凍して、あとで加工
    return keys


def solve_harvest(d):
    keys = plans(d)
    prob = pulp.LpProblem("harvest", pulp.LpMaximize)
    x = {k: prob.add_variable("x_{}_{}_{}".format(*k), lowBound=0) for k in keys}   # kg
    P = d["products"]

    prob += pulp.lpSum(P[p]["value"] * keys[h, t, p] * v for (h, t, p), v in x.items()), "value"

    for kind, by_day in d["harvest"].items():
        for h in DAYS:
            prob += pulp.lpSum(v for (hh, t, p), v in x.items()
                               if hh == h and P[p]["kind"] == kind) <= by_day[h], f"harvest_{kind}_{h}"
    for t in WORK_DAYS:
        prob += pulp.lpSum(P[p]["h_per_kg"] * v for (h, tt, p), v in x.items() if tt == t) \
            <= d["hours"][t], f"hours_{t}"
    for p in P:
        prob += pulp.lpSum(v for (h, t, pp), v in x.items() if pp == p) <= P[p]["max_kg"], f"max_{p}"
    if d["freezer_kg"] > 0:
        # その日の夜に冷凍庫に入っている梅（収穫日の翌日より後に加工するもの）
        for day in WORK_DAYS:
            prob += pulp.lpSum(v for (h, t, p), v in x.items() if t >= h + 2 and h <= day < t) \
                <= d["freezer_kg"], f"freezer_{day}"

    stats = prob.solve(pulp.HiGHS(msg=False))
    if stats.status_str != "Optimal":
        return {"status": stats.status_str}
    total = sum(sum(by_day.values()) for by_day in d["harvest"].values())
    done = {p: sum(v.value() for (h, t, pp), v in x.items() if pp == p) for p in P}
    waste_by_day = {}
    for kind, by_day in d["harvest"].items():
        for h in DAYS:
            used = sum(v.value() for (hh, t, p), v in x.items() if hh == h and P[p]["kind"] == kind)
            if by_day[h] - used > 1e-6:
                waste_by_day[kind, h] = by_day[h] - used
    return {
        "status": stats.status_str,
        "value": pulp.value(prob.objective),
        "done": done,
        "waste": total - sum(done.values()),
        "total": total,
        "waste_by_day": waste_by_day,
        "hours_used": {t: sum(P[p]["h_per_kg"] * v.value() for (h, tt, p), v in x.items() if tt == t) for t in WORK_DAYS},
        "frozen": sum(v.value() for (h, t, p), v in x.items() if t >= h + 2),
    }


def show(title, r, d):
    print(f"■ {title}: {r['status']}")
    done = " / ".join(f"{d['products'][p]['label']} {kg:.1f}kg" for p, kg in r["done"].items())
    print(f"  価値 {r['value']:,.0f} 円 / 捨てる梅 {r['waste']:.1f} / {r['total']} kg / 冷凍 {r['frozen']:.1f} kg")

    print(f"  捨てる梅の内訳: {waste or 'なし'}")
    print("  作業時間: " + " ".join(f"{r['hours_used'][t]:.1f}/{d['hours'][t]}" for t in WORK_DAYS))


if __name__ == "__main__":
    show("1: 基本", solve_harvest(base), base)
```

## マリゴールドの one more thing

**不確かさを正面から扱う最適化もある。**

この章のモデルでは、収穫量を「見込み」の1つの値として扱いました。天気で収穫量が変わることを正面から扱うには、晴れ・雨などのシナリオごとに収穫量を用意し、「どのシナリオでもそこそこ良い計画」や「平均で一番良い計画」を求める方法があります。前者を **ロバスト最適化**、後者を **確率計画法**（ストキャスティック・プログラミング）と呼びます。どちらも、この本で学んだ線形計画・整数計画の書き方を土台にして、変数や制約をシナリオの数だけ増やして作ります。さらに学びたいときは、付録Hの資料を手がかりにしてください。
