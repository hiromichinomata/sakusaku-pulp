# 第18章　条件を変更して結果を比較する

**初花**: 工場長さんから質問が山ほど来たんだ。「原材料費が上がったら？」「需要が減ったら？」「ラインBの点検で時間が減ったら？」って。

**マリゴールド**: 経営の現場では、答えを一つ出して終わり、ということはまずない。**もしこうなったら** を何通りも比べて、備えたり決めたりするんだ。

**初花**: 1つずつデータを書き換えて実行するのは、大変そう。

**マリゴールド**: だから、条件の変え方を **シナリオ** として並べて、一括で実行する仕組みを作ろう。この章では、これまで「第18章で」と予告してきた、感度分析や週をまたぐ計画もまとめて扱うよ。

## 18.1　需要やコストの変化を試す

**マリゴールド**: 第17章では、CSVを読み込んで辞書に変換し、`build_model` に渡した。シナリオは、**辞書を受け取って、条件を変えた辞書を返す関数** として書くよ。

```python
def material_up_20(d):
    """原材料費が2割上がる"""
    for p in d["products"].values():
        p["material"] = p["material"] * 1.2
    return d


def demand_down_20(d):
    """需要が2割減る（端数は切り捨て）"""
    for p in d["products"].values():
        p["demand"] = int(p["demand"] * 0.8)
    return d
```

**初花**: 関数の中で辞書を書き換えてるけど、元のデータが壊れない？

**マリゴールド**: いいところに気づいたね。呼び出す側で `copy.deepcopy` してから渡すんだ。第5章でも同じことをしたよね。

```python
d = change(copy.deepcopy(base_dicts))   # 元のデータを壊さない
prob, make, total = build_model(d)
```

| シナリオを関数にする良さ | 説明 |
|---------------------|------|
| 名前が付く | `material_up_20` で何を変えたか分かる |
| 組み合わせられる | `demand_down_20(material_up_20(d))` で両方 |
| 一覧にできる | 辞書に並べて、ループで一括実行 |

## 18.5　感度分析の考え方とPuLPでの注意点

**初花**: 第3章で「梅を増やしたら利益はどれだけ増える？」って聞いたら、「第18章の感度分析で」って言われたんだ。

**マリゴールド**: 約束を果たそう。連続変数だけのモデル（線形計画問題）では、ソルバーが **双対価格** という値を一緒に計算してくれる。制約の右辺を1単位増やしたら、目的関数がいくら良くなるか、という値だよ。PuLP では制約の `pi` で取り出せる。

`ch18_sensitivity.py` の前半:

```python
prob, stats, jam, syrup = solve_ume()
base = pulp.value(prob.objective)
print(f"基本: 利益 {base:,.1f} 円（ジャム {jam.value():.1f} kg / シロップ {syrup.value():.1f} L）")
print()
print("| 制約 | 余り | 双対価格（pi） |")
print("|------|-----:|-------------:|")
for c in prob.constraints():
    print(f"| {c.name} | {abs(c.slack):.1f} | {c.pi:,.1f} |")
```

```text
基本: 利益 39,000.0 円（ジャム 30.0 kg / シロップ 30.0 L）

| 制約 | 余り | 双対価格（pi） |
|------|-----:|-------------:|
| ume_kg | 0.0 | 692.3 |
| work_hours | 0.0 | 769.2 |
```

**初花**: 梅を1kg増やすと692.3円、作業を1時間増やすと769.2円、利益が増えるってこと？

**マリゴールド**: そう読める。本当にそうなるか、解き直して確かめてみよう。

```text
梅を 34 kg に: 利益 39,692.3 円（+692.3） ジャム 28.5 / シロップ 33.8
作業を 22 時間に: 利益 39,769.2 円（+769.2） ジャム 33.8 / シロップ 25.4
梅を 43 kg に: 利益 45,923.1 円（+6,923.1） ジャム 14.6 / シロップ 68.5
梅を 60 kg に: 利益 52,500.0 円（+13,500.0） ジャム 0.0 / シロップ 105.0
```

**初花**: 34kgで+692.3円、43kgで+6,923.1円。ちょうど10倍だ！ でも60kgだと+13,500円で、27倍の18,692円にはならない。

**マリゴールド**: 双対価格が使えるのは、**効いている制約の組み合わせが変わらない範囲だけ** なんだ。梅を増やしていくと、ジャムが減ってシロップが増える。ジャムが0になったところ（梅52.5kg）から先は、梅は余るようになって、もう利益は増えない。

| 感度分析の言葉 | 意味 | PuLP |
|-------------|------|------|
| 双対価格（シャドープライス） | 制約の右辺を1増やしたときの目的関数の改善 | `制約.pi` |
| 余り（スラック） | 制約の右辺と左辺の差 | `制約.slack` |
| 被約費用（リデュースドコスト） | 0の変数を1増やしたときの目的関数の悪化 | `変数.dj` |

**初花**: じゃあ、工場のモデルでも `pi` を見れば、ラインBを1時間増やす価値が分かるね。

**マリゴールド**: それが、そうはいかないんだ。工場のモデルは整数変数を含むから、双対価格は意味を持たない。実際に見てみると……

```text
line_A 0.10000000000000142 0.0
line_B -0.0 0.0
res_ume_kg 483.0 0.0
res_sugar_kg 169.0 0.0
```

**初花**: ラインBは効いてる（余り0）のに、`pi` は0.0？

**マリゴールド**: 整数計画問題には、線形計画問題のような双対価格の理論がそのままは当てはまらないんだ。PuLP 4 と HiGHS の組み合わせでは、このように0が返ってくる。だから、整数を含むモデルでは **18.3 のシナリオで実際に解き直して比べる** のが正しい方法だよ。包装を10時間増やして14,700円、というのはまさにその結果だね。

| モデル | 感度分析の方法 |
|--------|-------------|
| 連続変数だけ（線形計画問題） | `pi` で見当をつけ、範囲を解き直して確かめる |
| 整数変数を含む | シナリオで解き直して比べる（`pi` は使わない） |

⚠️ `pi` の符号は、最大化か最小化か、制約が `<=` か `>=` かによって変わります。使うときは、この節のように右辺を少し変えて解き直し、符号と大きさを確かめましょう。

## ハンズオン 18-A — 原材料費や需要が変わった場合の最適な生産計画を比較する

18.1〜18.4 のプログラムです。第17章の `ch17_plan.py` と `data/` を同じフォルダに置いて実行します。

`ch18_scenarios.py`:

```python
import copy
import time
from pathlib import Path

import pandas as pd
import pulp
from ch17_plan import load_data, validate, to_dicts, build_model

OUT = Path(__file__).parent / "output"


# ---- シナリオ：基本のデータ（辞書）を受け取り、変更したコピーを返す関数 ----
def base(d):
    return d


def material_up_20(d):
    """原材料費が2割上がる"""
    for p in d["products"].values():
        p["material"] = p["material"] * 1.2
    return d


def demand_down_20(d):
    """需要が2割減る（端数は切り捨て）"""
    for p in d["products"].values():
        p["demand"] = int(p["demand"] * 0.8)
    return d


def pack_50h(d):
    """包装の時間を週50時間に増やす"""
    d["capacity"]["pack_h"] = 50
    return d


def line_b_30h(d):
    """ラインBが点検で週30時間しか使えない"""
    d["lines"]["B"]["hours"] = 30
    return d


SCENARIOS = {
    "基本": base,
    "原材料費+20%": material_up_20,
    "需要-20%": demand_down_20,
    "包装50時間": pack_50h,
    "ラインB 30時間": line_b_30h,
}


def run_scenario(i, name, change, base_dicts):
    d = change(copy.deepcopy(base_dicts))   # 元のデータを壊さない
    prob, make, total = build_model(d)
    start = time.perf_counter()
    stats = prob.solve(pulp.HiGHS(msg=False))
    stats.toJson(OUT / f"stats_{i:02d}.json")   # 実行の記録（第2章）
    row = {"scenario": name, "status": stats.status_str, "seconds": round(time.perf_counter() - start, 3)}
    if stats.status_str != "Optimal":
        return row
    row["profit"] = round(pulp.value(prob.objective))
    for p in d["products"]:
        row[p] = round(pulp.value(total[p]))
    # 効いている制約（余りがほぼ0の制約）の名前
    row["binding"] = " ".join(c.name for c in prob.constraints() if c.slack is not None and abs(c.slack) < 1e-6)
    return row


if __name__ == "__main__":
    data = load_data(Path(__file__).parent / "data")
    assert not validate(data)
    base_dicts = to_dicts(data)

    OUT.mkdir(exist_ok=True)
    rows = [run_scenario(i, name, change, base_dicts) for i, (name, change) in enumerate(SCENARIOS.items())]
    table = pd.DataFrame(rows)
    table["vs_base"] = table["profit"] - table.loc[0, "profit"]

    print(table[["scenario", "status", "profit", "vs_base", "jam", "syrup", "umeboshi", "dressing"]].to_string(index=False))
    print()
    print(table[["scenario", "binding"]].to_string(index=False))

    table.to_csv(OUT / "scenarios.csv", index=False, encoding="utf-8-sig")
    print()
    print("保存しました:", sorted(p.name for p in OUT.iterdir()))
```

## ハンズオン 18-B — 双対価格を確かめる

18.5 の感度分析のプログラムです。

`ch18_sensitivity.py`:

import pulp


def solve_ume(ume_kg=33, work_hours=21):
    prob = pulp.LpProblem("ume_kobo", pulp.LpMaximize)
    jam = prob.add_variable("jam", lowBound=0)
    syrup = prob.add_variable("syrup", lowBound=0)
    prob += 800 * jam + 500 * syrup, "total_profit"
    prob += 0.6 * jam + 0.5 * syrup <= ume_kg, "ume_kg"
    prob += 0.5 * jam + 0.2 * syrup <= work_hours, "work_hours"
    stats = prob.solve(pulp.HiGHS(msg=False))
    return prob, stats, jam, syrup


prob, stats, jam, syrup = solve_ume()
base = pulp.value(prob.objective)
print(f"基本: 利益 {base:,.1f} 円（ジャム {jam.value():.1f} kg / シロップ {syrup.value():.1f} L）")
print()
print("| 制約 | 余り | 双対価格（pi） |")
print("|------|-----:|-------------:|")
for c in prob.constraints():
    print(f"| {c.name} | {abs(c.slack):.1f} | {c.pi:,.1f} |")

print()
for name, kwargs in [("梅を 34 kg に", {"ume_kg": 34}), ("作業を 22 時間に", {"work_hours": 22}),
                     ("梅を 43 kg に", {"ume_kg": 43}), ("梅を 60 kg に", {"ume_kg": 60})]:
    p, s, j, y = solve_ume(**kwargs)
    v = pulp.value(p.objective)
    print(f"{name}: 利益 {v:,.1f} 円（+{v - base:,.1f}） ジャム {j.value():.1f} / シロップ {y.value():.1f}")

## ハンズオン 18-C — 需要が週ごとに変わる計画を立てる

第9章の one more thing で予告した、週をまたぐ計画です。3週目にお中元の注文が集中するとき、在庫を持てるかどうかで計画がどう変わるかを比べます（本書用の架空のデータです）。

在庫の計算は、第4章で「本当にぴったりでなければいけないとき」に使うと話した等式の制約です。

```text
先週の在庫 ＋ 今週作った量 − 今週売った量 ＝ 今週末の在庫
```

`ch18_weeks.py`:

```python
import pulp

# 4週間の生産と在庫の計画（本書用の架空のデータ）。3週目にお中元の注文が集中する
weeks = [1, 2, 3, 4]
products = {
    "jam":   {"label": "ジャム",   "profit": 2000, "hours": 0.5},
    "syrup": {"label": "シロップ", "profit": 2100, "hours": 0.3},
}
demand = {
    ("jam", 1): 40, ("jam", 2): 50, ("jam", 3): 120, ("jam", 4): 60,
    ("syrup", 1): 60, ("syrup", 2): 60, ("syrup", 3): 100, ("syrup", 4): 50,
}
LINE_HOURS = 50   # 1週間に使えるラインの時間
HOLD = 150        # 1ケースを1週間在庫として持つ費用（円）


def solve_weeks(allow_stock):
    prob = pulp.LpProblem("weeks", pulp.LpMaximize)
    make = {(p, w): prob.add_variable(f"make_{p}_{w}", lowBound=0, cat="Integer") for p in products for w in weeks}
    sell = {(p, w): prob.add_variable(f"sell_{p}_{w}", lowBound=0, upBound=demand[p, w]) for p in products for w in weeks}
    stock = {(p, w): prob.add_variable(f"stock_{p}_{w}", lowBound=0) for p in products for w in weeks}

    prob += (pulp.lpSum(products[p]["profit"] * sell[p, w] for p in products for w in weeks)
             - pulp.lpSum(HOLD * stock[p, w] for p in products for w in weeks)), "profit"

    for p in products:
        for w in weeks:
            before = stock[p, w - 1] if w > 1 else 0   # 1週目の前の在庫は 0
            # 先週の在庫 ＋ 今週作った量 − 今週売った量 ＝ 今週末の在庫
            prob += before + make[p, w] - sell[p, w] == stock[p, w], f"balance_{p}_{w}"
            if not allow_stock:
                prob += stock[p, w] == 0, f"no_stock_{p}_{w}"
    for w in weeks:
        prob += pulp.lpSum(products[p]["hours"] * make[p, w] for p in products) <= LINE_HOURS, f"line_{w}"

    stats = prob.solve(pulp.HiGHS(msg=False))
    return stats, prob, make, sell, stock


def show(title, allow_stock):
    stats, prob, make, sell, stock = solve_weeks(allow_stock)
    print(f"■ {title}: {stats.status_str}  利益 {pulp.value(prob.objective):,.0f} 円")
    print("| 商品 | 項目 | 1週 | 2週 | 3週 | 4週 |")
    print("|------|------|----:|----:|----:|----:|")
    for p in products:
        for label, var in [("需要", None), ("生産", make), ("販売", sell), ("在庫", stock)]:
            vals = [demand[p, w] if var is None else round(var[p, w].value()) for w in weeks]
            print(f"| {products[p]['label']} | {label} | " + " | ".join(str(v) for v in vals) + " |")
    used = [sum(products[p]["hours"] * make[p, w].value() for p in products) for w in weeks]
    print("ライン: " + " / ".join(f"{u:.1f}" for u in used) + f"（各週 {LINE_HOURS} 時間まで）")


if __name__ == "__main__":
    show("在庫を持たない", allow_stock=False)
    show("在庫を持ってよい", allow_stock=True)
```

## 初花のメモ帳

- シナリオは「辞書を受け取って、条件を変えた辞書を返す関数」。`copy.deepcopy` してから渡す
- 結果は利益だけでなく、生産数と効いている制約（`slack` がほぼ0）も並べて比べる
- 双対価格（`pi`）は連続変数のモデルで、効いている制約が変わらない範囲だけ使える。整数を含むモデルは解き直して比べる

## マリゴールドの one more thing

**目的が二つあるときは、重みを変えたシナリオを並べる。**

第4章で「利益も大きく、作業時間も短く」のように目的が二つあるときの話をしました。一つの方法は、`利益 − 重み × 作業時間` のように重みを付けて一つの目的関数にまとめ、**重みを変えたシナリオ** を並べて解くことです。重みが0なら利益だけ、重みが大きくなるほど作業時間を減らす計画になります。結果を「利益」と「作業時間」の2つの軸で並べると、どちらかを良くするともう一方が悪くなる境目の線（パレートフロント）が見えてきます。どの点を選ぶかは、最後は人の判断です。第22章の総合演習で、人件費と公平さの釣り合いを比べるときに、この考え方を使います。
