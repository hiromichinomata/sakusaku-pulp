# 第1章　Pythonで「最適な答え」を探す

**初花**: 今度の週末、マルシェでお菓子の屋台を出すことになったんだ。仕入れの予算が決まってて、何をいくつ並べるか迷ってる。

**マリゴールド**: いい題材を持ってきたね。「限られた予算で、利益がいちばん大きくなる組み合わせ」は、まさに **最適化** の問題だよ。

**初花**: 最適化って、なんだか難しそう。数学の式がずらっと並ぶやつ？

**マリゴールド**: 本書では式から入らない。まずは屋台の仕入れを、手で考えて、Pythonで全部試して、最後に **PuLP** という道具に解かせる——その流れをこの章で一度通してみよう。

## 1.1　最適化とは何か

**初花**: 「最適」って、「いちばんいい」って意味だよね。何がいちばんいいかは、人によって違わない？

**マリゴールド**: そこが最初のポイント。最適化では、**何をいちばんよくしたいか** を先に一つ決める。屋台なら「利益を最大にしたい」、通勤なら「時間を最小にしたい」という具合だね。

最適化の問題は、どれも次の三つの部品でできています。

| 部品 | 意味 | 屋台の例 |
|------|------|----------|
| 意思決定変数 | 自分が決められる数 | クッキー・マフィン・ケーキを **いくつ仕入れるか** |
| 目的関数 | 大きく（または小さく）したい量 | 売れたときの **利益の合計** |
| 制約条件 | 守らなければいけないルール | 仕入れ額は **予算以内**、各商品は **売れる数まで** |

**初花**: 決められるもの、よくしたいもの、守るルール。三つに分けるだけなら、わたしにもできそう。

**マリゴールド**: それができれば半分終わり。残り半分は、その三つをコードに書いて、答え探しをコンピュータに任せる作業だよ。

身近な最適化の例をもう少し並べてみます。

| 場面 | 決めるもの | よくしたいもの | ルール |
|------|------------|----------------|--------|
| 献立 | 食材の量 | 費用を最小 | 栄養の基準を満たす |
| 工場 | 商品ごとの生産数 | 利益を最大 | 機械と材料の上限 |
| 配送 | どの倉庫からどの店へ何個 | 輸送費を最小 | 在庫と注文数 |
| シフト | 誰がいつ働くか | 人件費を最小 | 必要人数・勤務回数 |

本書の後半では、これらを一つずつPuLPで解いていきます。

## 1.2　全パターンを試す方法と最適化ソルバーの違い

**初花**: でもさ、パソコンって速いんでしょ？ 組み合わせを全部試して、いちばん利益が大きいのを選べばよくない？

**マリゴールド**: 小さな問題なら、それで正解。この章のハンズオンでも実際にやるよ。困るのは、商品が増えたときの **組み合わせの数** なんだ。

各商品を「0〜10個のどれか」仕入れるとしたときの組み合わせの数です。

| 商品の種類 | 組み合わせの数 |
|-----------|----------------|
| 3 | 1,331 |
| 5 | 161,051 |
| 10 | 25,937,424,601 |
| 20 | 672,749,994,932,560,009,201 |

1秒に1000万通り調べられるとしても、10種類で約43分、20種類だと **約200万年** かかります。

**初花**: 20種類って、ちょっと大きいお店なら普通にあるよね……。じゃあ最適化ソルバーは、もっと速く全部調べてるの？

**マリゴールド**: 全部は調べない。**明らかにダメな組み合わせをまとめて捨てながら**、良い答えの方へ絞り込んでいく仕組みを持っているんだ。しかも「これより良い答えはない」ことまで確かめてくれる。

| | 全パターンを試す | 最適化ソルバー |
|---|-----------------|----------------|
| やり方 | 一つずつ全部計算する | 数学的な性質を使って探す範囲を絞る |
| 小さい問題 | 確実・わかりやすい | 確実・速い |
| 大きい問題 | 現実的な時間で終わらない | 多くの場合、現実的な時間で解ける |
| 「最適」の保証 | 全部見たので保証される | ソルバーが保証してくれる |
| 書くもの | 探し方そのもの | 変数・目的・制約（問題の形） |

**初花**: 書くものが違うんだ。全探索は「探し方」、ソルバーは「問題の形」。

**マリゴールド**: そう、そこがいちばん大事な違い。PuLPを使うと、私たちは **問題の形を書くだけ** で、探し方はソルバーに任せられる。

## 1.3　PuLPで解ける問題・解くのが難しい問題

**初花**: PuLPって、さっきから出てくるけど何者？ ソルバーとは別なの？

**マリゴールド**: 別物だよ。**PuLP** は、Pythonで最適化の問題を書くための **ライブラリ**。書いた問題を、裏で **ソルバー**（実際に答えを計算するプログラム）に渡して、結果を受け取ってくる。

```text
あなたの Python コード
        │  変数・目的関数・制約条件を書く
        ▼
     PuLP（問題を組み立てて、ソルバー用の形に変換）
        │
        ▼
    ソルバー（HiGHS・CBC など。答えを計算する）
        │
        ▼
     PuLP（結果を Python の値として返す）
```

**初花**: 通訳みたいなものかな。わたしはPuLPに話しかけるだけでいい？

**マリゴールド**: その理解で十分。ただし、PuLPが通訳できるのは **「足し算」と「数との掛け算」だけでできた式** なんだ。これを **線形**（せんけい）な式と呼ぶよ。

| 書き方 | PuLPで | 例 |
|--------|--------|----|
| 変数 × 数 の足し算 | ✅ そのまま書ける | `200 * クッキー + 350 * マフィン` |
| 〜以下・〜以上・〜と等しい | ✅ そのまま書ける | `300 * クッキー + ... <= 8500` |
| 変数 × 変数 | ❌ 直接は書けない | `価格 * 販売数`（どちらも決めたい場合） |
| 変数の二乗・平方根 | ❌ 直接は書けない | `クッキー ** 2` |
| 変数どうしの割り算（比率） | ❌ 直接は書けない | `利益 / 仕入れ額` を最大化 |
| 「もし〜なら」 | ⚠️ 工夫すれば書ける | 「ケーキを仕入れるなら冷蔵ケース代がかかる」 |
| 運・天気などの不確かさ | ⚠️ 工夫が必要 | 「雨ならマフィンが売れ残る」 |

**初花**: 「もし〜なら」が書けないのは意外。屋台だと、そういう条件ばっかりな気がする。

**マリゴールド**: 実は、0か1しか取らない変数を使うと、多くの「もし〜なら」は線形な式に直せる。本書の第4部でその技を練習するよ。

⚠️ もう一つの難しさは **規模** です。線形な式で書けても、整数の変数が何千・何万と増えると、ソルバーでも長い時間がかかることがあります。どこまでが現実的かは、第12章と第19章で扱います。

## 1.4　線形計画問題と整数計画問題

**初花**: 屋台の問題って、線形な式で書ける？

**マリゴールド**: 書けるよ。利益も仕入れ額も「単価 × 個数」の足し算だからね。ただ、もう一つ気にすることがある。**個数は整数** でないといけない、という点だ。

| 名前 | 変数が取る値 | 例 |
|------|-------------|----|
| 線形計画問題（LP） | 小数もOK（連続変数） | 原材料を何kg使うか、何時間働くか |
| 整数計画問題（IP） | 整数だけ（整数変数） | 何個仕入れるか、何人配置するか |
| 混合整数計画問題（MIP） | 小数の変数と整数の変数が混ざる | 何kg使うか ＋ 何台の機械を動かすか |

**初花**: 小数がダメなら、小数で解いてから四捨五入すればいいんじゃない？

**マリゴールド**: そう考える人は多い。でも、それで最適になるとは限らないんだ。屋台の問題を「小数OK」で解いた結果を見てみよう。

| 解き方 | クッキー | マフィン | ケーキ | 利益 |
|--------|---------|---------|-------|------|
| 小数OKで解く | 1.67 | 8 | 5 | 約6,133円 |
| ↑を切り捨て | 1 | 8 | 5 | 6,000円 |
| 整数として解く | 5 | 6 | 5 | **6,100円** |

**初花**: えっ、切り捨てたらマフィン8個のままなのに、正解はマフィン6個でクッキー5個？ 全然違う形になってる。

**マリゴールド**: 予算がぴったり8,500円使えるのは、整数で解いた方なんだ。**小数の答えを丸めても、整数の最適解にはならないことがある**——だから最初から「整数で」とソルバーに伝える。PuLPでは、変数を作るときに一言添えるだけだよ。

## ハンズオン 1-A — 屋台の仕入れ問題を整理する

初花の屋台で扱う商品です（金額は本書用の架空の設定です）。

| 商品 | 仕入れ値（1個） | 利益（1個売れたら） | 売れそうな上限 |
|------|---------------|-------------------|--------------|
| クッキー | 300円 | 200円 | 10個 |
| マフィン | 500円 | 350円 | 8個 |
| ケーキ | 800円 | 600円 | 5個 |

仕入れの予算は **8,500円** です。上限まで仕入れた分は全部売れるものとします。

まず、1.1 の三つの部品に分けてみます。

| 部品 | この問題では |
|------|-------------|
| 意思決定変数 | クッキー・マフィン・ケーキを **それぞれ何個仕入れるか**（0以上の整数） |
| 目的関数 | 利益の合計 ＝ 200 × クッキー ＋ 350 × マフィン ＋ 600 × ケーキ → **最大化** |
| 制約条件 | 仕入れ額 ＝ 300 × クッキー ＋ 500 × マフィン ＋ 800 × ケーキ が **8,500円以下** |
| 制約条件 | クッキーは10個まで、マフィンは8個まで、ケーキは5個まで |

**初花**: 表にすると、もう問題が「答えを待ってる形」になったね。

**マリゴールド**: 第4章では、この「表に整理する」作業を正式な手順にするよ。まずは自分の直感で答えを出してみて。

## ハンズオン 1-B — 直感で解いてみる（効率のよい順に詰める）

**初花**: わたしなら、1円あたりの利益がいちばん高い商品から順に、仕入れられるだけ仕入れるかな。ケーキが 600 ÷ 800 = 0.75 でいちばん効率いいよね。

**マリゴールド**: 自然な作戦だね。その作戦をそのままPythonにしてみよう。

次のコードを `ch01_greedy.py` として保存し、ターミナルで `python3 ch01_greedy.py` を実行します（第2章で環境を整える前でも、Python 3 が入っていれば動きます）。

```python
items = {
    "クッキー": {"cost": 300, "profit": 200, "max": 10},
    "マフィン": {"cost": 500, "profit": 350, "max": 8},
    "ケーキ": {"cost": 800, "profit": 600, "max": 5},
}
budget = 8500

# 1円あたりの利益が高い順に並べる
order = sorted(items, key=lambda n: items[n]["profit"] / items[n]["cost"], reverse=True)

remaining = budget
plan = {}
for name in order:
    info = items[name]
    count = min(info["max"], remaining // info["cost"])
    plan[name] = count
    remaining -= count * info["cost"]

profit = sum(items[n]["profit"] * k for n, k in plan.items())
print("効率順:", order)
print("仕入れ案:", plan)
print("利益:", profit, "円 / 残り予算:", remaining, "円")
```

実行結果:

```text
効率順: ['ケーキ', 'マフィン', 'クッキー']
仕入れ案: {'ケーキ': 5, 'マフィン': 8, 'クッキー': 1}
利益: 6000 円 / 残り予算: 200 円
```

**初花**: 利益6,000円。200円余ったけど、クッキーは300円だからもう買えないね。これが答えでしょ？

**マリゴールド**: それを確かめるのが次のハンズオンだよ。

## ハンズオン 1-C — 全パターンを試す

組み合わせを全部試して、予算内でいちばん利益が大きいものを探します。`itertools.product` は、複数の範囲の **すべての組み合わせ** を順番に作ってくれる標準ライブラリの関数です。

`ch01_brute_force.py`:

```python
import itertools

items = {
    "クッキー": {"cost": 300, "profit": 200, "max": 10},
    "マフィン": {"cost": 500, "profit": 350, "max": 8},
    "ケーキ": {"cost": 800, "profit": 600, "max": 5},
}
budget = 8500

names = list(items)
ranges = [range(items[n]["max"] + 1) for n in names]  # 0〜上限個

best_profit = -1
best_plan = None
checked = 0
feasible = 0

for counts in itertools.product(*ranges):
    checked += 1
    cost = sum(items[n]["cost"] * k for n, k in zip(names, counts))
    if cost > budget:  # 予算オーバーは候補にしない
        continue
    feasible += 1
    profit = sum(items[n]["profit"] * k for n, k in zip(names, counts))
    if profit > best_profit:
        best_profit = profit
        best_plan = dict(zip(names, counts))
        best_cost = cost

print("調べた組み合わせ:", checked, "通り")
print("予算内の組み合わせ:", feasible, "通り")
print("最良の仕入れ案:", best_plan)
print("利益:", best_profit, "円 / 仕入れ額:", best_cost, "円")
```

実行結果:

```text
調べた組み合わせ: 594 通り
予算内の組み合わせ: 547 通り
最良の仕入れ案: {'クッキー': 5, 'マフィン': 6, 'ケーキ': 5}
利益: 6100 円 / 仕入れ額: 8500 円
```

**初花**: 6,100円！ わたしの作戦より100円多い。マフィンを2個減らしてクッキーを4個増やすと、予算がぴったり使い切れるんだ。

**マリゴールド**: 効率のよい順に詰める作戦は速くて便利だけど、**端数の予算が無駄になる** と最適を逃すことがある。今回の差は100円でも、規模が大きくなればこの差も大きくなるよ。

| 方法 | 仕入れ案（クッキー・マフィン・ケーキ） | 利益 | 予算の余り |
|------|------------------------------------|------|-----------|
| 効率順に詰める | 1・8・5 | 6,000円 | 200円 |
| 全パターンを試す | 5・6・5 | **6,100円** | 0円 |

⚠️ 「効率のよい順」が最適になる問題もあります。ただ、**いつ最適になるかを自分で見分けるのは難しい** ので、本書では答えの正しさをソルバーに保証させる方法を身につけます。

## ハンズオン 1-D — PuLPで書くとどうなるか（のぞき見）

同じ問題をPuLPで書くと、次のようになります。PuLPのインストールは第2章で行うので、ここでは **読むだけ** で大丈夫です。

```python
import pulp

items = {
    "cookie": {"cost": 300, "profit": 200, "max": 10},
    "muffin": {"cost": 500, "profit": 350, "max": 8},
    "cake": {"cost": 800, "profit": 600, "max": 5},
}
budget = 8500

# 問題を作る（利益を最大化）
prob = pulp.LpProblem("marche_plan", pulp.LpMaximize)

# 意思決定変数：各商品の仕入れ数（0〜上限の整数）
x = {
    name: prob.add_variable(name, lowBound=0, upBound=info["max"], cat="Integer")
    for name, info in items.items()
}

# 目的関数：利益の合計
prob += pulp.lpSum(items[n]["profit"] * x[n] for n in items), "total_profit"

# 制約条件：仕入れ額は予算以内
prob += pulp.lpSum(items[n]["cost"] * x[n] for n in items) <= budget, "budget"

# ソルバーで解く
stats = prob.solve(pulp.HiGHS(msg=False))

print("状態:", stats.status_str)
print("利益:", pulp.value(prob.objective))
for name in items:
    print(name, x[name].value())
```

実行結果（第2章で環境を整えると、この出力が得られます）:

```text
状態: Optimal
利益: 6100.0
cookie 5.0
muffin 6.0
cake 5.0
```

**初花**: 全探索と同じ答え！ しかも「探し方」のループがどこにもない。

**マリゴールド**: 1.2 で話した通り、書いたのは **変数・目的関数・制約条件** の三つだけ。`Optimal` は「これ以上良い答えはない」とソルバーが確かめた、という意味だよ。

コードの各行が、ハンズオン 1-A の表のどこに対応するかを確認しておきましょう。

| コード | 1-A の表 |
|--------|---------|
| `prob.add_variable(..., cat="Integer")` | 意思決定変数（0以上の整数） |
| `upBound=info["max"]` | 各商品の上限 |
| `prob += pulp.lpSum(... profit ...)` | 目的関数（利益の合計） |
| `pulp.LpMaximize` | 「最大化」したい |
| `prob += ... <= budget` | 制約条件（予算以内） |

**初花**: ねえ、`cat="Integer"` を消したらどうなる？

**マリゴールド**: 1.4 の表の「小数OKで解く」になる。クッキーが1.67個になるはずだから、第2章で環境ができたら試してみて。

⚠️ 本書は **PuLP 4.x** を前提にしています。インターネット上の古い記事では、変数を `pulp.LpVariable(...)` で作ったり、結果を `pulp.LpStatus[prob.status]` で表示したりする書き方が多く見られます。これはPuLP 3.x以前の書き方で、4.x ではそのまま動きません。バージョンの違いは付録Eにまとめます。

## 振り返り

**初花**: 今日わかったのは、「決めるもの・よくしたいもの・守るルール」に分けられたら、あとはソルバーが探してくれるってこと。それと、わたしの直感の作戦は100円負けた……。

**マリゴールド**: 直感で6,000円まで行けたのは十分すごいよ。ただ「本当にこれがいちばんか」を言い切るには、全探索かソルバーの保証が要る。

**初花**: 商品が20種類になったら全探索は200万年だから、ソルバー一択だね。

**マリゴールド**: そういうこと。次の章で、PuLPとソルバーを手元に入れて、1-D のコードを実際に動かそう。

## 初花のメモ帳

- 最適化の問題は **意思決定変数・目的関数・制約条件** の三つに分けて考える
- 全探索は「探し方」を書く。PuLPは「問題の形」を書いて、探し方はソルバーに任せる
- 個数のような値は **最初から整数として** 解く。小数の答えを丸めても最適とは限らない

## マリゴールドの one more thing

**「全部試す」は、答え合わせの道具として残しておこう。**

全探索は大きな問題には使えませんが、商品を2〜3種類に減らした **小さなテストケース** なら一瞬で終わります。PuLPで書いたモデルが正しいか不安なときは、小さなデータで全探索の答えと比べてみてください。両方が同じ答えになれば、モデルの書き間違いがないという手がかりになります。この方法は、第7章のデバッグと第20章の自動テストでもう一度使います。
