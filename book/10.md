# 第10章　物流と輸送を最適化する

**初花**: うめ食品の人から、また相談が来たんだ。商品を倉庫から各地のお店に届けるトラック代が高くて困ってるって。

**マリゴールド**: 今度は **輸送問題** だね。どの倉庫から、どの店に、何ケース運ぶかを決めて、輸送費の合計を最小にする。最適化の中でも、特に歴史が長くて、実務でよく使われる形なんだ。

**初花**: 前の章は「商品 × ライン」だったけど、今度は「倉庫 × 店」が変数になるのかな。

**マリゴールド**: その通り。形は似ているけど、輸送問題ならではの制約の書き方がある。供給が足りないときの扱いまで、一緒に見ていこう。

## 10.1　倉庫・配送先・輸送費を整理する

うめ食品の倉庫と店舗の情報です（本書用の架空のデータです）。

| 倉庫 | 在庫（ケース） |
|------|------------:|
| 大阪倉庫 | 300 |
| 和歌山倉庫 | 200 |
| 名古屋倉庫 | 250 |
| **合計** | **750** |

| 店舗 | 注文（ケース） |
|------|------------:|
| 京都店 | 150 |
| 神戸店 | 120 |
| 奈良店 | 100 |
| 津店 | 130 |
| 梅田店 | 180 |
| **合計** | **680** |

1ケースあたりの輸送費（円）です。和歌山倉庫から津店へは直通便がありません。

| 倉庫 \ 店舗 | 京都店 | 神戸店 | 奈良店 | 津店 | 梅田店 |
|------------|------:|------:|------:|----:|------:|

| 和歌山倉庫 | 500 | 450 | 350 | — | 350 |
| 名古屋倉庫 | 400 | 650 | 450 | 250 | 450 |

**初花**: 在庫の合計が750で、注文の合計が680。在庫のほうが多いから、全部の注文に応えられるね。

**マリゴールド**: そう、まずはその確認が大事。輸送問題では、**在庫の合計と注文の合計の大小** で、モデルの書き方が変わるんだ。10.5 で、在庫が足りない場合も扱うよ。

輸送費の表は、第9章と同じくタプルをキーにした辞書にします。直通便のない組み合わせはキーを作りません。

```python
cost = {

    ("wakayama", "kyoto"): 500, ("wakayama", "kobe"): 450, ("wakayama", "nara"): 350, ("wakayama", "umeda"): 350,
    ("nagoya", "kyoto"): 400, ("nagoya", "kobe"): 650, ("nagoya", "nara"): 450, ("nagoya", "tsu"): 250, ("nagoya", "umeda"): 450,

```

## 10.2　供給量と需要量の制約

**マリゴールド**: 輸送問題の制約は、二種類だけ。**倉庫から出せる量** と、**店に届ける量** だ。

| 制約 | 意味 | 式の形 |
|------|------|-------|
| 供給 | 倉庫から出荷する合計は、在庫以下 | 倉庫ごとに `<=` |
| 需要 | 店に届く合計は、注文とちょうど同じ | 店ごとに `==` |

```python
for w in supply:
    prob += pulp.lpSum(ship[w, s] for s in demand if (w, s) in cost) <= supply[w], f"supply_{w}"
for s in demand:
    prob += pulp.lpSum(ship[w, s] for w in supply if (w, s) in cost) == demand[s], f"demand_{s}"
```

**初花**: 需要のほうは `==` なんだ。第4章で「等式は本当にぴったりじゃないといけないときだけ」って習ったけど。

**マリゴールド**: 注文より少なく届けたら欠品だし、多く届けても店は困る。だから「ちょうど」でいい。供給のほうは、在庫を全部出す必要はないから `<=` だね。

**初花**: 需要を `>=` にしたらどうなる？

**マリゴールド**: 輸送費を最小にしたいから、ソルバーは余計に運ぼうとはしない。結果は `==` と同じになることが多いよ。ただ、意味がはっきりするから、本書では `==` を使う。

| 倉庫・店の制約の向き | 使う場面 |
|-------------------|---------|
| 供給 `<=`、需要 `==` | 在庫 ≧ 注文（この節） |
| 供給 `==`、需要 `<=` | 在庫を必ず全部出したい（期限切れ前など） |
| 欠品の変数を足す | 在庫 ＜ 注文（10.5） |

## 10.3　輸送量を決める変数

**マリゴールド**: 変数は「倉庫 × 店」の組み合わせごとに1つ。運べる経路の数だけ作るよ。

```python
ship = {(w, s): prob.add_variable(f"ship_{w}_{s}", lowBound=0) for (w, s) in cost}

prob += pulp.lpSum(cost[k] * ship[k] for k in cost), "total_cost"
```

**初花**: ケースの数なのに、`cat="Integer"` を付けてないよ？

**マリゴールド**: 鋭いね。輸送問題には面白い性質があって、**在庫と注文が整数なら、連続変数のままでも、ソルバーは整数の答えを返す** んだ。だから整数の指定がなくても困らないし、連続変数のほうが速く解ける。

ハンズオン 10-A で解いた結果です。

```text
状態: Optimal
輸送費: 178,500 円
| 倉庫 \ 店舗 | 京都店 | 神戸店 | 奈良店 | 津店 | 梅田店 | 出荷計 | 在庫 |
|---|---|---|---|---|---|---|---|
| 大阪倉庫 | 30 | 90 | 0 | 0 | 180 | 300 | 300 |
| 和歌山倉庫 | 0 | 30 | 100 | — | 0 | 130 | 200 |
| 名古屋倉庫 | 120 | 0 | 0 | 130 | 0 | 250 | 250 |
```

**初花**: 本当に全部整数だ！ 大阪倉庫は梅田店に全部の180を送ってる。100円で一番安い経路だもんね。

**マリゴールド**: でも、京都店は一番安い大阪倉庫（300円）からは30しかもらっていない。大阪倉庫の在庫は、梅田店や神戸店に回したほうが全体で得だからだよ。一つの経路の安さだけでは、全体の答えは決まらない。

**初花**: 和歌山倉庫は200のうち130しか出してない。余った70は？

**マリゴールド**: そのまま倉庫に残る。供給の制約を `<=` にしたからだね。在庫が一番余るのが和歌山倉庫になったのは、ほとんどの店から遠いからだ。

⚠️ 「連続変数でも整数の答え」になるのは、輸送問題のような特別な形のときだけです。第9章の生産計画のように、ほかの制約が混ざると成り立たないことがあります。迷ったら `cat="Integer"` を付けましょう。

## 10.4　複数拠点を持つ輸送計画

**初花**: 倉庫の在庫って、どこから来るんだろう。

**マリゴールド**: 工場から運ばれてくるんだ。工場 → 倉庫 → 店、という **2段階** の輸送をまとめて計画してみよう。

うめ食品の工場の情報です。

| 工場 | 生産能力（ケース） | → 大阪倉庫 | → 和歌山倉庫 | → 名古屋倉庫 |
|------|---------------:|---------:|-----------:|-----------:|
| 和歌山工場 | 450 | 150円 | 50円 | 500円 |
| 名古屋工場 | 350 | 400円 | 600円 | 50円 |

倉庫は在庫を持つ場所ではなく、**通過する場所** として扱います。1週間に扱える量の上限は、10.1 の在庫の数（大阪300、和歌山200、名古屋250）と同じとします。

**初花**: 倉庫が「通過する場所」なら、制約はどうなるの？

**マリゴールド**: **入ってきた量と、出ていく量が同じ** になる。これを **流量保存**（フロー保存）の制約というよ。

```python
for w, cap in handling.items():
    flow_in = pulp.lpSum(inbound[f, w] for f in factories if (f, w) in in_cost)
    flow_out = pulp.lpSum(outbound[w, s] for s in demand if (w, s) in out_cost)
    prob += flow_in == flow_out, f"balance_{w}"      # 入った分だけ出ていく
    prob += flow_in <= cap, f"handling_{w}"          # 倉庫の取扱量の上限
```

| 拠点 | 制約 |
|------|------|
| 工場 | 出荷 ≦ 生産能力 |
| 倉庫 | 入荷 ＝ 出荷（流量保存）、入荷 ≦ 取扱量 |
| 店舗 | 入荷 ＝ 注文 |

ハンズオン 10-B で解いた結果です。

```text
状態: Optimal
輸送費: 242,500 円（工場→倉庫 64,000 円 / 倉庫→店舗 178,500 円）
工場→倉庫:
  和歌山工場 → 大阪倉庫: 300
  和歌山工場 → 和歌山倉庫: 130
  名古屋工場 → 名古屋倉庫: 250
倉庫→店舗:
  大阪倉庫 → 京都店: 30
  大阪倉庫 → 神戸店: 90
  大阪倉庫 → 梅田店: 180
  和歌山倉庫 → 神戸店: 30
  和歌山倉庫 → 奈良店: 100
  名古屋倉庫 → 京都店: 120
  名古屋倉庫 → 津店: 130
```

**初花**: 名古屋工場は350作れるのに、250しか出してない。名古屋倉庫が250までしか扱えないからだね。ほかの倉庫に送るのは400円以上かかるし。

**マリゴールド**: そう。もし名古屋倉庫の取扱量を増やせたら、輸送費がどれだけ下がるか——第18章のシナリオ比較で試せる問いだよ。

**初花**: 倉庫から店への運び方は、10.3 と全く同じになってる。

**マリゴールド**: この例では、工場から倉庫への運び方が、倉庫の在庫を10.3 と同じにするのが一番安かったんだ。条件によっては、2段階をまとめて解くことで、倉庫から店への運び方も変わる。別々に解くより、まとめて解くほうが良い答えになりうる、というのが2段階のモデルの強みだよ。

## 10.5　供給不足・余剰がある場合の扱い

**初花**: 京都店から「来週は230ケースほしい」って追加の注文が来たら？

**マリゴールド**: 注文の合計が760になって、在庫の750を超える。どう頑張っても10ケース足りないから、今のモデルは `Infeasible` になるよ。

```text
在庫の合計: 750 / 注文の合計: 760
欠品を考えないモデル: Infeasible
```

**初花**: 解けません、で終わったら困る。足りないなりに、一番いい配り方を知りたいのに。

**マリゴールド**: 第7章の one more thing で話した方法を使おう。**届けられない量（欠品）を変数にして、罰金を付ける** んだ。需要の制約は「届けた量 ＋ 欠品 ＝ 注文」になる。

```python
short = {s: prob.add_variable(f"short_{s}", lowBound=0) for s in demand2}

prob += (pulp.lpSum(cost[k] * ship[k] for k in cost)
         + pulp.lpSum(PENALTY * short[s] for s in demand2)), "total_cost"

for s in demand2:
    prob += pulp.lpSum(ship[w, s] for w in supply if (w, s) in cost) + short[s] == demand2[s], f"demand_{s}"
```

罰金を1ケースあたり2,000円にして解いた結果です。

```text
欠品を許すモデル: Optimal
輸送費: 213,500 円 / 欠品の罰金: 20,000 円
  京都店: 10 ケース欠品
```

**初花**: 足りない10ケースだけが欠品になって、ほかは全部届いてる。

**マリゴールド**: 罰金は、欠品で失う利益やお客さんの信用を、お金に換算したものだと考えるといい。ただし、罰金の金額には注意が必要だよ。試しに300円にすると、こうなる。

```text
欠品を許すモデル: Optimal
輸送費: 80,500 円 / 欠品の罰金: 99,000 円
  京都店: 230 ケース欠品
  奈良店: 100 ケース欠品
```

**初花**: 330ケースも欠品！ 在庫はあるのに、運ばないことにしちゃった。

**マリゴールド**: 輸送費が300円より高い経路では、運ぶより罰金を払うほうが安いからね。罰金は **どの輸送費よりも十分に大きく** しておく必要があるんだ。

| 罰金の決め方 | 結果 |
|------------|------|
| どの輸送費よりも大きい | 本当に足りない分だけが欠品になる |
| 一部の輸送費より小さい | 在庫があっても運ばない「わざと欠品」が起きる |
| 店ごとに変える | 大事な店ほど欠品しにくくなる |

**初花**: 店ごとに罰金を変えれば、「京都店は大口のお客さんだから、欠品させるなら奈良店で」みたいなこともできるんだ。

**マリゴールド**: そう。罰金は、**守りたい度合い** をソルバーに伝える道具なんだ。逆に在庫が余る場合は、供給の制約が `<=` になっていれば自動的に倉庫に残るから、特別な変数は要らないよ。

## ハンズオン 10-A — 複数の倉庫から店舗へ運ぶ輸送コストを最小化する

10.1〜10.3 のモデルです。結果を倉庫 × 店舗の表で表示します。

`ch10_transport.py`:

```python
import pulp

# 倉庫の在庫（ケース）と店舗の注文（ケース）。本書用の架空のデータ
supply = {"osaka": 300, "wakayama": 200, "nagoya": 250}
demand = {"kyoto": 150, "kobe": 120, "nara": 100, "tsu": 130, "umeda": 180}

# 1ケースあたりの輸送費（円）。和歌山→津は直通便がない
cost = {
    ("osaka", "kyoto"): 300, ("osaka", "kobe"): 250, ("osaka", "nara"): 280, ("osaka", "tsu"): 600, ("osaka", "umeda"): 100,
    ("wakayama", "kyoto"): 500, ("wakayama", "kobe"): 450, ("wakayama", "nara"): 350, ("wakayama", "umeda"): 350,
    ("nagoya", "kyoto"): 400, ("nagoya", "kobe"): 650, ("nagoya", "nara"): 450, ("nagoya", "tsu"): 250, ("nagoya", "umeda"): 450,
}

labels = {
    "osaka": "大阪倉庫", "wakayama": "和歌山倉庫", "nagoya": "名古屋倉庫",
    "kyoto": "京都店", "kobe": "神戸店", "nara": "奈良店", "tsu": "津店", "umeda": "梅田店",
}


def solve_transport(supply, demand, cost):
    prob = pulp.LpProblem("transport", pulp.LpMinimize)

    ship = {(w, s): prob.add_variable(f"ship_{w}_{s}", lowBound=0) for (w, s) in cost}

    prob += pulp.lpSum(cost[k] * ship[k] for k in cost), "total_cost"

    for w in supply:
        prob += pulp.lpSum(ship[w, s] for s in demand if (w, s) in cost) <= supply[w], f"supply_{w}"
    for s in demand:
        prob += pulp.lpSum(ship[w, s] for w in supply if (w, s) in cost) == demand[s], f"demand_{s}"

    stats = prob.solve(pulp.HiGHS(msg=False))
    return stats, prob, ship


def print_plan(supply, demand, cost, ship):
    stores = list(demand)
    print("| 倉庫 \\ 店舗 | " + " | ".join(labels[s] for s in stores) + " | 出荷計 | 在庫 |")
    print("|---" * (len(stores) + 3) + "|")
    for w in supply:
        row = [f"{ship[w, s].value():.0f}" if (w, s) in cost else "—" for s in stores]
        out = sum(ship[w, s].value() for s in stores if (w, s) in cost)
        print(f"| {labels[w]} | " + " | ".join(row) + f" | {out:.0f} | {supply[w]} |")


if __name__ == "__main__":
    stats, prob, ship = solve_transport(supply, demand, cost)
    print("状態:", stats.status_str)
    print(f"輸送費: {pulp.value(prob.objective):,.0f} 円")
    print_plan(supply, demand, cost, ship)
```

実行結果は 10.3 の表のとおりです。

## ハンズオン 10-B — 工場から店舗までの2段階で計画する

10.4 の2段階モデルです。倉庫から店舗の輸送費は、ハンズオン 10-A のデータを再利用します。

`ch10_two_stage.py`:

```python
import pulp
from ch10_transport import demand, cost as out_cost, labels

# 工場の生産能力（ケース）と、工場→倉庫の輸送費（円/ケース）
factories = {"f_wakayama": 450, "f_nagoya": 350}
in_cost = {
    ("f_wakayama", "osaka"): 150, ("f_wakayama", "wakayama"): 50, ("f_wakayama", "nagoya"): 500,
    ("f_nagoya", "osaka"): 400, ("f_nagoya", "wakayama"): 600, ("f_nagoya", "nagoya"): 50,
}
# 倉庫が1週間に扱える量（ケース）
handling = {"osaka": 300, "wakayama": 200, "nagoya": 250}
labels = {**labels, "f_wakayama": "和歌山工場", "f_nagoya": "名古屋工場"}

prob = pulp.LpProblem("two_stage", pulp.LpMinimize)

inbound = {k: prob.add_variable(f"in_{k[0]}_{k[1]}", lowBound=0) for k in in_cost}
outbound = {k: prob.add_variable(f"out_{k[0]}_{k[1]}", lowBound=0) for k in out_cost}

prob += (pulp.lpSum(in_cost[k] * inbound[k] for k in in_cost)
         + pulp.lpSum(out_cost[k] * outbound[k] for k in out_cost)), "total_cost"

for f, cap in factories.items():
    prob += pulp.lpSum(inbound[f, w] for w in handling if (f, w) in in_cost) <= cap, f"factory_{f}"

for w, cap in handling.items():
    flow_in = pulp.lpSum(inbound[f, w] for f in factories if (f, w) in in_cost)
    flow_out = pulp.lpSum(outbound[w, s] for s in demand if (w, s) in out_cost)
    prob += flow_in == flow_out, f"balance_{w}"      # 入った分だけ出ていく
    prob += flow_in <= cap, f"handling_{w}"          # 倉庫の取扱量の上限

for s, d in demand.items():
    prob += pulp.lpSum(outbound[w, s] for w in handling if (w, s) in out_cost) == d, f"demand_{s}"

stats = prob.solve(pulp.HiGHS(msg=False))
print("状態:", stats.status_str)
in_total = sum(in_cost[k] * inbound[k].value() for k in in_cost)
out_total = sum(out_cost[k] * outbound[k].value() for k in out_cost)
print(f"輸送費: {in_total + out_total:,.0f} 円（工場→倉庫 {in_total:,.0f} 円 / 倉庫→店舗 {out_total:,.0f} 円）")
print("工場→倉庫:")
for (f, w), v in inbound.items():
    if v.value() > 1e-6:
        print(f"  {labels[f]} → {labels[w]}: {v.value():.0f}")
print("倉庫→店舗:")
for (w, s), v in outbound.items():
    if v.value() > 1e-6:
        print(f"  {labels[w]} → {labels[s]}: {v.value():.0f}")
```

## ハンズオン 10-C — 供給不足を欠品の罰金で扱う

10.5 のモデルです。

`ch10_shortage.py`:

```python
import pulp
from ch10_transport import supply, demand, cost, labels, solve_transport

# 京都店の注文が 150 → 230 ケースに増えた
demand2 = {**demand, "kyoto": 230}
print("在庫の合計:", sum(supply.values()), "/ 注文の合計:", sum(demand2.values()))

stats, prob, ship = solve_transport(supply, demand2, cost)
print("欠品を考えないモデル:", stats.status_str)

# 欠品（届けられない量）を変数にして、1ケースあたり 2,000 円の罰金を付ける
PENALTY = 2000

prob = pulp.LpProblem("transport_shortage", pulp.LpMinimize)
ship = {(w, s): prob.add_variable(f"ship_{w}_{s}", lowBound=0) for (w, s) in cost}
short = {s: prob.add_variable(f"short_{s}", lowBound=0) for s in demand2}

prob += (pulp.lpSum(cost[k] * ship[k] for k in cost)
         + pulp.lpSum(PENALTY * short[s] for s in demand2)), "total_cost"

for w in supply:
    prob += pulp.lpSum(ship[w, s] for s in demand2 if (w, s) in cost) <= supply[w], f"supply_{w}"
for s in demand2:
    prob += pulp.lpSum(ship[w, s] for w in supply if (w, s) in cost) + short[s] == demand2[s], f"demand_{s}"

stats = prob.solve(pulp.HiGHS(msg=False))
print("欠品を許すモデル:", stats.status_str)
transport = sum(cost[k] * ship[k].value() for k in cost)
print(f"輸送費: {transport:,.0f} 円 / 欠品の罰金: {PENALTY * sum(v.value() for v in short.values()):,.0f} 円")
for s in demand2:
    if short[s].value() > 1e-6:
        print(f"  {labels[s]}: {short[s].value():.0f} ケース欠品")
```

`PENALTY` を `300` に変えて実行し、10.5 で見た「わざと欠品」が起きることも確かめてみましょう。

## 振り返り

**初花**: 輸送問題は、供給の `<=` と需要の `==` の二種類の制約だけで書けた。2段階になっても、倉庫で「入る量 ＝ 出る量」を足せばいいんだね。

**マリゴールド**: 流量保存は、物流だけでなく、お金の流れや在庫の計算など、いろんな場面で出てくる形だよ。

**初花**: 欠品の罰金の話は面白かった。罰金が安すぎると、在庫があるのに運ばなくなるなんて。

**マリゴールド**: 罰金は、ソルバーへの「お願いの強さ」なんだ。強すぎても弱すぎても困るから、意味のある金額にすることが大切だよ。次の章では、物ではなく人を割り当てる問題を扱おう。

## 初花のメモ帳

- 輸送問題は「倉庫 × 店」の変数で、供給は `<=`、需要は `==`。直通便のない経路は変数を作らない
- 通過する拠点には「入る量 ＝ 出る量」（流量保存）の制約を置く
- 供給不足は欠品の変数と罰金で扱う。罰金はどの輸送費よりも十分に大きくする

## マリゴールドの one more thing

**トラックの台数で費用が決まるなら、整数変数が必要になる。**

この章では、輸送費が「1ケースあたり○円」で、運ぶ量に比例すると考えました。実際には、トラック1台を出すと何ケース積んでも同じ料金、ということがよくあります。その場合は「経路ごとに何台トラックを出すか」を整数変数にし、「運ぶ量 ≦ 1台の積載量 × 台数」という制約を足します。こうなると10.3 で話した「連続変数でも整数の答え」の性質は成り立たなくなり、整数計画問題になります。第4部では、こうした「台数」「使う・使わない」を表す整数変数とバイナリ変数を本格的に扱います。
