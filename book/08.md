# 第8章　食事・原材料の配合を最適化する

**初花**: 稽古のあとって、すごくお腹が空くんだ。でも毎日コンビニでお弁当を買うと高くつくから、安くて栄養のとれるお昼を自分で組み合わせたい。

**マリゴールド**: それは最適化の古典中の古典、**配合問題** だね。いくつかの材料を混ぜて、条件を満たしながら費用を最小にする。食事だけでなく、家畜の飼料、肥料、合金、ブレンドコーヒーなど、いろんな分野で使われているよ。

**初花**: 第3部の最初の題材が、わたしのお昼ごはんなんだ。

**マリゴールド**: 身近な分、答えの **おかしさ** にもすぐ気づける。条件を一つずつ足しながら、答えがどう変わるかを見ていこう。

⚠️ この章の栄養の値は、食品成分表をもとにした **概算** です。価格は本書用の架空の値です。実際の食事の目安は、専門家や公的な資料で確かめてください。

## 8.1　栄養・品質・コストの条件を整理する

**マリゴールド**: まずは、いつものようにモデル表から。材料の候補と、その性質を表にするよ。

| 食品（1人前） | 価格 | エネルギー | たんぱく質 | 食物繊維 | カルシウム |
|--------------|-----:|---------:|---------:|--------:|---------:|
| ごはん（150g） | 40円 | 234 kcal | 3.8 g | 2.3 g | 5 mg |
| 納豆（1パック） | 50円 | 86 kcal | 7.4 g | 3.0 g | 41 mg |
| 卵（1個） | 30円 | 71 kcal | 6.1 g | 0.0 g | 23 mg |
| 牛乳（200mL） | 50円 | 126 kcal | 6.8 g | 0.0 g | 227 mg |
| バナナ（1本） | 35円 | 93 kcal | 1.1 g | 1.1 g | 6 mg |
| 鶏むね肉（100g） | 90円 | 105 kcal | 23.3 g | 0.0 g | 4 mg |
| ブロッコリー（80g） | 60円 | 30 kcal | 4.3 g | 4.1 g | 30 mg |

**初花**: 変数は「それぞれ何人前食べるか」。目的は「価格を最小にする」だね。

**マリゴールド**: そう。配合問題の制約は、たいてい **「栄養（品質）を一定以上・以下にする」** という形になる。第4章までの「資源を使いすぎない」とは向きが逆で、`>=` が主役になるんだ。

| 部品 | 配合問題では | お昼の例 |
|------|------------|---------|
| 変数 | 各材料の量 | 各食品を何人前食べるか |
| 目的関数 | 費用の合計 → 最小化 | 価格の合計 |
| 制約条件 | 品質の下限・上限 | エネルギー・たんぱく質など |
| 制約条件 | 材料ごとの使用量の上下限 | 1食で食べられる量 |
| 制約条件 | 割合の条件 | 主食の割合 |

## 8.2　最小費用の配合計画

**マリゴールド**: 最初は、条件を二つだけにしてみよう。エネルギーは700〜900kcal、たんぱく質は30g以上。

第5章と同じように、食品と条件をデータとして持ち、モデルは関数にします。

```python
needs = {
    "kcal":    (700, 900),     # (下限, 上限)
    "protein": (30, None),     # None は条件なし
}
```

```python
def total(key):
    return pulp.lpSum(foods[f][key] * eat[f] for f in foods)

prob += total("price"), "total_price"

for key, (low, high) in needs.items():
    if low is not None:
        prob += total(key) >= low, f"min_{key}"
    if high is not None:
        prob += total(key) <= high, f"max_{key}"
```

ステップ1の結果（コード全体はハンズオン 8-A）:

```text
■ ステップ1: Optimal
  181.8 円  ごはん(150g) 2.60 / 鶏むね肉(100g) 0.86
  700 kcal / たんぱく質 30.0 g / 食物繊維 6.0 g / カルシウム 16 mg / ごはんのエネルギー比 87%
```

**初花**: ごはん2.6杯と、鶏むね肉86g。……安いけど、これはお昼ごはんっていうより、ボディビルダーの減量食だよ。

**マリゴールド**: ソルバーは、**書いた条件だけ** を守って、あとは一番安い組み合わせを探す。エネルギー1kcalあたりが一番安いごはんと、たんぱく質1gあたりが一番安い鶏むね肉だけになったんだね。

**初花**: 「おいしく食べられる量」とか「いろんな栄養」とか、わたしの頭の中にあった条件を、何も書いてなかったからか。

**マリゴールド**: その通り。配合問題は、**おかしな答えを見て、足りない条件に気づく** の繰り返しなんだ。気づいた条件を一つずつ足していこう。

| 気づいたこと | 足す条件 | 節 |
|------------|---------|----|
| ごはん2.6杯は食べきれない | 食品ごとの上限 | 8.3 |
| 食物繊維やカルシウムが少ない | 栄養の条件を増やす | 8.4 |
| ごはんばかりに偏っている | 主食の割合の上限 | 8.4 |
| 野菜がない・量が細かすぎる | 下限・量の刻み | 8.5 |

## 8.3　原材料ごとの使用上限

**マリゴールド**: 材料ごとの上限は、変数の `upBound` で書ける。データに `max` を持たせよう。

```python
foods2["rice"]["max"] = 2    # ごはんは2杯まで
foods2["egg"]["max"] = 1     # 卵は1個まで
foods2["milk"]["max"] = 1    # 牛乳は1本まで
# ほかの食品は2人前まで
```

```text
■ ステップ2: Optimal
  194.8 円  ごはん(150g) 2.00 / 卵(1個) 1.00 / 牛乳(200mL) 0.92 / 鶏むね肉(100g) 0.43
  700 kcal / たんぱく質 30.0 g / 食物繊維 4.6 g / カルシウム 243 mg / ごはんのエネルギー比 67%
```

**初花**: ごはんは上限の2杯ちょうど。卵も上限の1個。上限に張り付いてる材料が多いね。

**マリゴールド**: 上限に張り付いた材料は、もっと使いたいのに止められている材料だよ。第6章の「効いている制約」と同じ見方ができる。その分、次に安い牛乳と鶏むね肉で補っているんだ。

| 材料の上限の理由 | 例 |
|----------------|----|
| 食べられる量・おいしさ | ごはんは2杯まで |
| 在庫・仕入れの量 | 原材料が倉庫に何kgあるか |
| 品質・安全の基準 | 添加物は全体の○%まで |
| 好み・習慣 | 卵は1日1個まで |

## 8.4　複数の品質条件を同時に満たす

**マリゴールド**: 次は、栄養の条件を増やそう。食物繊維7g以上、カルシウム250mg以上。データの `needs` に2行足すだけだよ。

```python
needs3 = {**needs, "fiber": (7, None), "calcium": (250, None)}
```

```text
■ ステップ3: Optimal
  205.5 円  ごはん(150g) 2.00 / 納豆(1パック) 0.80 / 卵(1個) 0.08 / 牛乳(200mL) 0.90 / 鶏むね肉(100g) 0.43
  700 kcal / たんぱく質 30.0 g / 食物繊維 7.0 g / カルシウム 250 mg / ごはんのエネルギー比 67%
```

**初花**: 食物繊維のために納豆が入ってきた。卵はほぼいなくなっちゃったけど。

**マリゴールド**: 条件が増えると、それを満たすのに得意な材料が選ばれるようになる。でも、ごはんのエネルギー比はまだ67%。主食に偏りすぎているね。次は **割合** の条件を入れてみよう。

**初花**: 「ごはんのエネルギーが全体の50%以下」ってこと？ でも、割合って割り算だよね。第1章で、変数どうしの割り算は書けないって言ってなかった？

**マリゴールド**: よく覚えていたね。割り算のまま書くと線形にならない。でも、**両辺に分母を掛ければ** 割り算が消えるんだ。

```text
ごはんのエネルギー ÷ 全体のエネルギー ≦ 0.5
            ↓ 両辺に「全体のエネルギー」を掛ける（全体は正なので向きは変わらない）
ごはんのエネルギー ≦ 0.5 × 全体のエネルギー
```

```python
prob += foods["rice"]["kcal"] * eat["rice"] <= staple_ratio * total("kcal"), "staple_ratio"
```

```text
■ ステップ4: Optimal
  222.4 円  ごはん(150g) 1.50 / 納豆(1パック) 0.98 / 卵(1個) 1.00 / 牛乳(200mL) 1.00 / バナナ(1本) 0.57 / 鶏むね肉(100g) 0.15
  700 kcal / たんぱく質 30.0 g / 食物繊維 7.0 g / カルシウム 302 mg / ごはんのエネルギー比 50%
```

**初花**: ごはんが1.5杯に減って、バナナが入ってきた。ちょうど50%だ。

**マリゴールド**: 割合の条件は、配合問題でとてもよく使う。「脂質のエネルギーは全体の30%以下」「果汁は50%以上」なども、同じ変形で線形にできるよ。

| 割合の条件 | 線形にした形 |
|-----------|------------|
| A ÷ 全体 ≦ r | A ≦ r × 全体 |
| A ÷ 全体 ≧ r | A ≧ r × 全体 |
| A ÷ B ≦ r（Bは正） | A ≦ r × B |

⚠️ この変形は、分母が必ず **正** のときだけ使えます。分母が0になりうる場合（何も食べない場合など）は、別の下限条件で0にならないようにしておきます。

## 8.5　配合量の上下限を設定する

**初花**: だいぶお昼らしくなってきた。でも、野菜がまだないのが気になる。それに「納豆0.98パック」とか「鶏むね肉15g」とか、細かすぎて用意できないよ。

**マリゴールド**: 二つとも、量の条件で解決できる。野菜は **下限**、細かさは **量の刻み** だね。

ブロッコリーの下限は、データの `min` に入れます。

```python
foods5["broccoli"]["min"] = 0.5   # ブロッコリーは半人前（40g）以上
```

量の刻みは、整数変数を使って表します。「半人前を何単位食べるか」を整数の変数にして、量はその0.5倍とします。

```python
units = {f: prob.add_variable(f"units_{f}", lowBound=..., upBound=..., cat="Integer") for f in foods}
eat = {f: 0.5 * units[f] for f in foods}
```

**初花**: `eat` は変数じゃなくて、変数を0.5倍した **式** なんだ。

**マリゴールド**: そう。式でも、目的関数や制約の中では変数と同じように使える。量を半人前単位、4分の1単位、10g単位……と刻みたいときに使える書き方だよ。

```text
■ ステップ5(小数): Optimal
  239.6 円  ごはん(150g) 1.50 / 納豆(1パック) 0.13 / 卵(1個) 1.00 / 牛乳(200mL) 1.00 / バナナ(1本) 1.01 / 鶏むね肉(100g) 0.31 / ブロッコリー(80g) 0.50
  700 kcal / たんぱく質 30.0 g / 食物繊維 7.0 g / カルシウム 285 mg / ごはんのエネルギー比 50%
■ ステップ5(半人前単位): Optimal
  252.5 円  ごはん(150g) 1.50 / 卵(1個) 0.50 / 牛乳(200mL) 1.00 / バナナ(1本) 1.50 / 鶏むね肉(100g) 0.50 / ブロッコリー(80g) 0.50
  720 kcal / たんぱく質 31.0 g / 食物繊維 7.1 g / カルシウム 272 mg / ごはんのエネルギー比 49%
```

**初花**: ごはん1.5杯、卵半分、牛乳1本、バナナ1本半、鶏むね肉50g、ブロッコリー40g。これなら作れる！ 252.5円。

**マリゴールド**: 刻みを入れたら13円高くなった。小数のままの答えが、どんな刻みの答えよりも安いのは当然だね。第1章で見た「整数にすると最適値が変わる」と同じことだよ。

| ステップ | 足した条件 | 価格 |
|---------|-----------|-----:|
| 1 | エネルギー・たんぱく質 | 181.8 円 |
| 2 | ＋ 食品ごとの上限 | 194.8 円 |
| 3 | ＋ 食物繊維・カルシウム | 205.5 円 |
| 4 | ＋ ごはんのエネルギー比 50%以下 | 222.4 円 |
| 5 | ＋ ブロッコリー下限・半人前単位 | 252.5 円 |

**初花**: 条件を足すたびに、少しずつ高くなっていく。

**マリゴールド**: 制約を足すと、選べる答えが減るから、最小化の目的関数は **同じか悪くなる** しかない。どの条件にいくら払っているかが分かるのも、段階的に足していく良さだよ。

## ハンズオン 8-A — 必要な栄養条件を満たす最安の食材組み合わせを求める

ここまでのステップ1〜5を、1つのプログラムで順に実行します。

`ch08_lunch.py`:

```python
import copy
import pulp

# 1人前あたりの値（食品成分表をもとにした概算）。価格は本書用の架空の値
foods = {
    "rice":     {"label": "ごはん(150g)",      "price": 40, "kcal": 234, "protein": 3.8,  "fiber": 2.3, "calcium": 5,   "min": 0, "max": None},
    "natto":    {"label": "納豆(1パック)",     "price": 50, "kcal": 86,  "protein": 7.4,  "fiber": 3.0, "calcium": 41,  "min": 0, "max": None},
    "egg":      {"label": "卵(1個)",           "price": 30, "kcal": 71,  "protein": 6.1,  "fiber": 0.0, "calcium": 23,  "min": 0, "max": None},
    "milk":     {"label": "牛乳(200mL)",       "price": 50, "kcal": 126, "protein": 6.8,  "fiber": 0.0, "calcium": 227, "min": 0, "max": None},
    "banana":   {"label": "バナナ(1本)",       "price": 35, "kcal": 93,  "protein": 1.1,  "fiber": 1.1, "calcium": 6,   "min": 0, "max": None},
    "chicken":  {"label": "鶏むね肉(100g)",    "price": 90, "kcal": 105, "protein": 23.3, "fiber": 0.0, "calcium": 4,   "min": 0, "max": None},
    "broccoli": {"label": "ブロッコリー(80g)", "price": 60, "kcal": 30,  "protein": 4.3,  "fiber": 4.1, "calcium": 30,  "min": 0, "max": None},
}

# 栄養の条件：(下限, 上限)。None は条件なし
needs = {
    "kcal":    (700, 900),
    "protein": (30, None),
}


def solve_lunch(foods, needs, staple_ratio=None, step=None):
    prob = pulp.LpProblem("lunch", pulp.LpMinimize)

    if step is None:
        # 何人前食べるか（小数OK）
        eat = {
            f: prob.add_variable(f"eat_{f}", lowBound=d["min"], upBound=d["max"])
            for f, d in foods.items()
        }
    else:
        # step 人前を何単位食べるか（整数）。0.5 なら半人前ずつ
        units = {
            f: prob.add_variable(
                f"units_{f}",
                lowBound=round(d["min"] / step),
                upBound=None if d["max"] is None else round(d["max"] / step),
                cat="Integer",
            )
            for f, d in foods.items()
        }
        eat = {f: step * units[f] for f in foods}

    def total(key):
        return pulp.lpSum(foods[f][key] * eat[f] for f in foods)

    prob += total("price"), "total_price"

    for key, (low, high) in needs.items():
        if low is not None:
            prob += total(key) >= low, f"min_{key}"
        if high is not None:
            prob += total(key) <= high, f"max_{key}"

    if staple_ratio is not None:
        # ごはんのエネルギー ≦ 全体のエネルギー × staple_ratio
        prob += foods["rice"]["kcal"] * eat["rice"] <= staple_ratio * total("kcal"), "staple_ratio"

    stats = prob.solve(pulp.HiGHS(msg=False))
    if stats.status_str != "Optimal":
        return {"status": stats.status_str}

    return {
        "status": stats.status_str,
        "price": pulp.value(prob.objective),
        "eat": {f: pulp.value(e) for f, e in eat.items()},
        "totals": {k: pulp.value(total(k)) for k in ["kcal", "protein", "fiber", "calcium"]},
        "rice_ratio": foods["rice"]["kcal"] * pulp.value(eat["rice"]) / pulp.value(total("kcal")),
    }


def show(title, result, foods):
    print(f"■ {title}: {result['status']}")
    if result["status"] != "Optimal":
        return
    menu = " / ".join(f"{foods[f]['label']} {x:.2f}" for f, x in result["eat"].items() if x > 1e-6)
    t = result["totals"]
    print(f"  {result['price']:.1f} 円  {menu}")
    print(f"  {t['kcal']:.0f} kcal / たんぱく質 {t['protein']:.1f} g / 食物繊維 {t['fiber']:.1f} g / "
          f"カルシウム {t['calcium']:.0f} mg / ごはんのエネルギー比 {result['rice_ratio']:.0%}")


if __name__ == "__main__":
    # ステップ1：エネルギーとたんぱく質だけ
    show("ステップ1", solve_lunch(foods, needs), foods)

    # ステップ2：食品ごとの上限を加える
    foods2 = copy.deepcopy(foods)
    foods2["rice"]["max"] = 2
    foods2["egg"]["max"] = 1
    foods2["milk"]["max"] = 1
    for f in foods2:
        if foods2[f]["max"] is None:
            foods2[f]["max"] = 2
    show("ステップ2", solve_lunch(foods2, needs), foods2)

    # ステップ3：食物繊維とカルシウムの条件を加える
    needs3 = {**needs, "fiber": (7, None), "calcium": (250, None)}
    show("ステップ3", solve_lunch(foods2, needs3), foods2)

    # ステップ4：ごはんのエネルギーを全体の50%以下にする
    show("ステップ4", solve_lunch(foods2, needs3, staple_ratio=0.5), foods2)

    # ステップ5：ブロッコリーを半人前以上、量は半人前単位にする
    foods5 = copy.deepcopy(foods2)
    foods5["broccoli"]["min"] = 0.5
    show("ステップ5(小数)", solve_lunch(foods5, needs3, staple_ratio=0.5), foods5)
    show("ステップ5(半人前単位)", solve_lunch(foods5, needs3, staple_ratio=0.5, step=0.5), foods5)
```

実行すると、8.2〜8.5 で見た6つの結果が順に表示されます。

| 関数・データ | 役割 |
|------------|------|
| `foods` | 材料の性質（モデル表の行） |
| `needs` | 栄養の下限・上限 |
| `solve_lunch` | モデルを作って解き、結果を辞書で返す |
| `staple_ratio` | 割合の条件（`None` なら付けない） |
| `step` | 量の刻み（`None` なら小数OK） |

## ハンズオン 8-B — 条件を自分で変えてみる

`ch08_lunch.py` の最後に次のコードを足して、自分の好みの条件で解いてみます。

```python
    # 自分の条件：たんぱく質を40g以上にしたい
    my_needs = {**needs3, "protein": (40, None)}
```

実行結果:

```text
  709 kcal / たんぱく質 40.5 g / 食物繊維 10.0 g / カルシウム 324 mg / ごはんのエネルギー比 50%
```

**初花**: たんぱく質を増やすなら、鶏むね肉が増えると思ってた。増えたのは納豆で、バナナがいなくなってる。

**マリゴールド**: 納豆はたんぱく質だけでなく、食物繊維もカルシウムも持っているからね。鶏むね肉を足すより、バナナを納豆に置き換えるほうが、全部の条件をまとめて安く満たせたんだ。一つの栄養だけを見た予想は、外れることが多いよ。

ほかにも、次のような変更を試してみましょう。結果は、予想と比べながら確かめてください。

| 試した変更 | 結果 |
|-----------|------|
| たんぱく質を 40 g 以上にする | 納豆が増えてバナナが消え、275.0 円 |
| エネルギーの上限を 750 kcal にする | 献立は変わらない（もともと 720 kcal） |
| 納豆の上限を 0 にする（苦手） | 献立は変わらない（もともと納豆を使っていない） |
| ブロッコリーの値段を 30 円にする | 献立は変わらず、237.5 円に下がる |

**初花**: 下の3つは、献立が変わらなかった。ブロッコリーなんて、安くなっても下限の量のままなんだね。

**マリゴールド**: 今の答えで **効いていない** 条件を変えても、答えは変わらないんだ。ブロッコリーは下限の半人前だけ入っていて、安くなっても、ほかの食品より得になるほどではなかった。条件を厳しくしすぎると `Infeasible` になることもあるから、そのときは第7章の方法で、どの条件がぶつかっているかを探そう。

## 振り返り

**初花**: 最初の答えがボディビルダーの減量食で笑っちゃったけど、条件を足していったら、ちゃんとしたお昼になった。

**マリゴールド**: 配合問題では、最初の答えがおかしいのは普通のことなんだ。おかしさを言葉にして、条件として書き足す。その繰り返しで、自分の頭の中の「なんとなくの基準」がはっきりしていく。

**初花**: 割合の条件を、掛け算に直して線形にできるのは目からうろこだった。

**マリゴールド**: 書けないと思った条件も、変形すれば書けることが多いんだ。次の章では、工場の生産計画で、機械・人・材料の制約が絡み合う問題を扱おう。

## 初花のメモ帳

- 配合問題は「品質の下限・上限を満たしながら費用を最小にする」。`>=` の制約が主役
- 割合の条件は、両辺に分母を掛けて線形にする（分母が正のとき）
- 量の刻みは「単位数を整数変数にして、刻み幅を掛けた式」で表す

## マリゴールドの one more thing

**最安の献立は、毎日同じ献立になる。**

この章のモデルは、同じデータなら毎回同じ答えを返します。毎日食べるなら、さすがに飽きてしまいますね。1週間分の献立を作るなら、「日」と「食品」の組み合わせを変数にし、「同じ食品は週に4回まで」のような制約を足すことになります。このように **時間の軸** を加えて変数を「食品 × 日」に広げる考え方は、第15章の勤務シフトで本格的に使います。
